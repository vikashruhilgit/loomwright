# Project Memory (advisory — subordinate to CLAUDE.md; written only via write-project-memory.sh)
- [2d32221d] The otel-collector contrib image is distroless (no shell/wget), so compose healthchecks for it must use a binary CMD like ["/otelcol-contrib", "--version"]; HTTP probes only work externally via the health_check extension on :13133.
- [cea220a5] Compose-consumed env vars can be mechanically diffed against a documented .env recipe: grep -oE '\$\{[A-Z0-9_]+' on docker-compose.yml vs ^[A-Z0-9_]+= on the recipe — the regex must include digits or LANGFUSE_S3_BUCKET truncates to a false mismatch.
- [83b693d0] test-telemetry.sh golden fixtures must be regenerated with WRITE_GOLDENS=1 whenever the redacted Raw Data JSON gains a key, and any release-varying value needs a normalise rule in normalise_for_golden (plugin_version is normalised to "<NORMALISED>") so goldens survive version bumps.
- [ac3f1a80] jq `.field // empty` silently collapses a boolean-`false` config value to empty — use `if has("field") then .field else empty end` for false-meaningful opt-out flags (canonical falsy-coercion self-heal miss-class).
- [ead04b14] macOS bash 3.2 errors on "${empty_array[@]}" under set -u (unbound variable); use "$@" which is set -u-safe even when empty, or guard array expansions before expanding.
- [edc10b50] Self-tests that gate on CLAUDE_CODE_ENABLE_TELEMETRY must `env -u CLAUDE_CODE_ENABLE_TELEMETRY` to scrub the dev/CI inherited flag (it is set =1 in this repo's ~/.claude/settings.json), else telemetry-OFF fixtures false-pass.
- [6ae712d5] sdk-spike dry-run fixtures are WORKER_RESULT/CODE_REVIEW_RESULT payloads only — token usage lives on the SDK result MESSAGE, so synthetic accounting must be injected at the query seam (makeDryRunQuery), never into the fixtures.
- [4916add2] README.md keeps a growing stack of dated 'NEW in vX.Y.Z' blockquote banners at the top — a release ADDS one, never rewrites old ones (dated lines, exempt from doc-currency).
- [c61a7518] CHANGELOG.md entries are single '**vX.Y.Z — title:** ...' paragraphs (no ## headings); a new entry goes directly after the historical-entries blockquote near the top.
- [a178a7b5] When spawning this plugin's agents via the Agent tool, subagent_type is double-prefixed: loomwright:loomwright:<role> (e.g. ...:plan-reviewer, ...:worker, ...:supervisor-runner). The single-prefix form loomwright:<role> ERRORS — verified empirically 2026-08-08; do not "correct" this to a single prefix based on strings inside agent prompt .md files.
- [16474355] CI's anti-drift self-test loop globs loomwright/scripts/test-*.sh ONLY — a test added under root scripts/ never runs unless .github/workflows/ci.yml names it explicitly in its own run: step.
- [b2d8c93c] For a repo-scanning CI gate, enumerate with 'git ls-files', not 'find': find picks up gitignored node_modules/dist that exist on a dev checkout but not in CI, so the two measure different file sets.
- [ae55bd55] add-rule.sh refuses to write from a linked worktree or submodule (top-level .git is a FILE, red-team F1, exit 3), so any sample exercising its PLANNED WRITE branch must be generated from a clone, not a worktree.
- [015f34a3] A concurrent agent in this checkout runs 'git checkout -- <file>' on files another agent is editing; uncommitted edits in a shared lane can be destroyed mid-task, so snapshot work outside the repo before running long verifications.
- [eacb5191] write-agent-memory.sh --proposal does NOT delete the promoted proposal file; the deletion is the caller's step (commands/dreaming.md owns it), same as add-orientation.sh.
- [0ac9b111] Any line inserted into .github/workflows/ci.yml shifts pinned ci.yml:NN citations elsewhere in the repo (e.g. the CI hard-glob citation in test-committed-twin-scrub.sh's WRITE CONTAINMENT header); test-citation-drift.sh fails until the pin is re-derived. Write the anchor descriptively, not as a bare file:N — this fact's own first wording failed that gate.
