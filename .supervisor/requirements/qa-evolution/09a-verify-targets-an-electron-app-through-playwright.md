### Scope

**Part 1: the contract gains a `target` discriminator; the web path is byte-identical.**
- `docs/result-schemas/verify-env.md` documents an OPTIONAL `target: enum [web, electron, mobile]`. Absent ⇒ `web`. `mobile` is reserved here (accepted by the reader, semantics in `09b`); `read-verify.sh` rejects any other value with `[type_invalid:target]` (MALFORMED, nothing on stdout).
- For `target: electron` an `electron` object is REQUIRED (`[required_key_missing:electron]` when absent) — PO default shape: `app_dir: string` (required; the directory passed as `electron.launch`'s `args[0]` and `cwd`), `build: string|null` (REQUIRED KEY, NULLABLE VALUE — a shell string `verify-env.sh` runs BEFORE launch, e.g. `npm run build`; `null` = already built), `launch_timeout_s: number` (optional; `electron.launch`'s `timeout`, default 30 s per Playwright), `env: object` (optional; a string→string map merged over the process environment at launch — the project's own hidden-window variable goes here; the plugin invents no hiding mechanism). The `electron` object is a trust surface like `start`/`seed` (its `build` is shell): the schema's TRUST SURFACE paragraph names it.
- `base_url` and `health` become target-conditional: required for `web` (unchanged), NOT required for `electron` (present ⇒ typed as today, ignored by the executor with an advisory `[member_ignored_for_target:<key>]` on stderr). `start`, `stop`, `seed`, `reset`, `auth` stay required keys with today's types: `start`/`stop` describe a backend the app needs (nullable); `seed`/`reset` are the mutation carve-out's seams exactly as for web.
- **Non-prod for electron.** `non_prod_assert` stays REQUIRED and fail-closed. `base_url_matches` is unusable on a non-web target: the reader names it `[member_unusable_for_target:base_url_matches]` and it does not count toward "at least one usable member", so `{"target":"electron","non_prod_assert":{"base_url_matches":"…"}}` is `[non_prod_assert_empty]`; an electron project asserts with `env_var_equals` or `cmd`. Target-intrinsic rule: the app is launched from a source/build checkout, never a packaged installer — the executor refuses an `app_dir` that is not a directory containing a `package.json` whose `main` is a non-empty string (`[electron_app_dir_invalid]`); a `.app`, `.dmg`, `.exe` or `.AppImage` path can never satisfy that.
- `propose-verify.sh` gains `--target electron`, `--electron-app-dir <dir>`, `--electron-build <cmd>|null`, `--electron-env NAME=VAL` (repeatable), `--electron-launch-timeout-s <n>`; without `--target` it writes exactly what it writes today (no `target` key). `--target electron` with `--base-url` or `--health` is a parse-time refusal naming the rule. The dry run prints `BLOCKED` without `--electron-app-dir`, as it does today without `--base-url` for web.
- `test-verify-seam.sh` gains the reader cases (enum, `electron` object presence and types, the two target-conditional requireds, `member_unusable_for_target`, `electron_app_dir_invalid` is the executor's and is tested in `test-verify-walkthrough.sh`), the writer cases for the new flags, and the byte-identical case: every existing web fixture reads and writes exactly as before.

**Part 2: the executor builds and gates; `walk` launches through a generated fixture.**
- `verify-env.sh` (`gate_non_prod` first, as every subcommand): for `target: electron`, `start` runs `electron.build` (when non-null; `bash -c`, after the gate, logged to the state dir like `start.log`) and then `start` (when non-null, the backend, health polled only when `health` is present — PO default: an electron contract with `start` non-null and no `health` treats a 0 exit as `start_detached`); `[electron_app_dir_invalid]` is checked BEFORE `build` runs. New subcommand `verify-env.sh launch-env` prints the merged launch environment and resolved `app_dir` as `key=value` lines for `walk` (never executes anything) — so `walk` keeps loading the contract through the reader and never re-parses the file.

Every electron spec imports `test`/`expect` from `../electron-fixture.mjs` instead of `@playwright/test`. The reporter→verdict mapping, `walk_ingest`, artifact copy, `spec-replay`, `verdict`, `finish`, `summary.md`, `evidence.jsonl` and `VERIFY_RESULT` are UNCHANGED; `propose-from-verify.sh` reads the same `ac` lines. - `preflight`'s `env` line gains `target: web|electron` (default `web`, so an existing line without the field reads as web); `verify-evidence.md` documents the optional field. `preflight` itself stays target-aware only through the reader.

## Risks
- **Playwright's Electron API is experimental.** A Playwright minor could change `_electron.launch` or `firstWindow()`; the fixture is generated per run from one template, so the fix is one template. Mitigation: the project pins its own `@playwright/test`; the plugin requires nothing.
- **A visible window steals focus on macOS** (Studio's harness comment). Mitigation: the project passes its own hiding variable through `electron.env`; the plugin does not pretend to solve it.
- **`build` is arbitrary shell run by the executor** — the same trust surface as `start`/`seed`, gated the same way (after `gate_non_prod`, in-process). Mitigation: the seam test plants markers; AC "Build runs after the gate".
- **The hermetic suite cannot prove a launch.** Mitigation: the Running-system entries below are the proof; the CI assertions pin the generated files and the stub's argv, and the story says so rather than shipping a fixture Electron app that would need the binary in CI.
- **Re-baseline of `verify-walkthrough`'s budget.** Mitigation: measured + ~10% with the mirror row in the same change; `check-token-budget.sh` is the gate.
- **Three siblings share the verify seam files; `05` shares twelve of fourteen.** They serialise in a wave; none blocks another.
- **`target: mobile` is accepted by the reader before `09b` lands**, so a `mobile` contract passes the reader and then fails at the executor (`[target_unsupported:mobile]` — PO default). Mitigation: the executor refuses it by name; `09b` replaces the refusal.
