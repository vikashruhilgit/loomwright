## Procedure

### Part A — after `01-qa-session-accounting-is-derived-never-agent-written.md` has merged
Target: `~/Documents/work/personal/sports-management`. State on disk on 2026-11-09: `.qa-session/coverage.json` (`updated_at: 2026-04-06`, `scopes_total: 24`, `scopes_completed: 16`, `coverage_weighted: 61.4`), `.qa-session/plan.json`, six files under `.qa-session/results/` (`coaching`, `documents`, `notifications-chat`, `platform-admin`, `store`, `teams`); the ten older result files are recoverable with `git show 8f45d5b6^:.qa-session/results/<scope>.json`.
1. **Snapshot the old accounting.** Copy `.qa-session/coverage.json` and `.qa-summary.md` aside (they are gitignored since `8f45d5b6`). Record the old roll-up's `scopes_completed`, `coverage_weighted`, the per-scope `status` for `store`, and the `apis_tested` sum (183 against `apis_total` 175 on 2026-09-08).
2. **Validate the result files against the new schema.** Run whatever validator `01-qa-session-accounting-is-derived-never-agent-written.md` ships against each of the six `results/*.json` files and against the ten recovered ones. Record per file: pass / the first reason named. Expect several to fail (five of sixteen had no `status` key on 2026-09-08); a validator that passes all sixteen unchanged files is the first finding to investigate, not a success.
3. **Re-run one scope.** `/qa-executor --continue` on the repo (the app must be running — `npm run dev`; the executor requires it and never starts it). Record: which pending scope it picked, the derived `coverage.json` versus the snapshot (does `store` now read `failed` in the roll-up? do the `apis_tested` and risk-bucket sums reconcile with the headers?), whether `.qa-summary.md` is cumulative or still the last scope only, tool calls used and wall time.
4. **Falsify.** Hand-edit the derived `coverage.json` (flip one `failed` to `completed`) and re-run the derivation: it must be overwritten. Delete one `results/*.json` and re-derive: the scope must drop out of the counts, not persist from a cache.

### Part B — after `04-verify-runs-inside-the-delivery-loop-in-shadow.md` has merged
No repo under `~/Documents/work` has `.agent/verify.json` today, so the contract has to be bootstrapped first — on `sports-management`, which is the natural first target (Next.js, `package.json` scripts `dev: next dev`, `db:reset: bash scripts/reset-db.sh`, no `db:seed`; no `playwright.config.*` and no `APP_URL`/`BASE_URL` in `.env*` were found on 2026-11-09, so `propose-verify.sh` will print `BLOCKED` without `--base-url`, and `--non-prod` is always required).
