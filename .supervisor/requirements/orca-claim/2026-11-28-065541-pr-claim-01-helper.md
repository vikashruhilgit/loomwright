# PR claim 01 — `pr-claim.sh` helper (CLAIM.md v1 take / renew / release / assert)

## Status: pending

Owner approval: 2026-11-28, request from `orca-plugin-dev` (relayed by the Orca coordinator). Contract: `vikashruhilgit/loomwright-orca` `docs/CLAIM.md` (v1), reference implementation `src/claim.ts` (PR #1, merged); park handoff: `docs/HANDOFF.md` §1 and §5; guard: `docs/GUARD.md`. Counterpart already on loomwright-orca main: PR #7 (`a1de67b`, `claim-step.js handover` and the dev-bot side of the handoff) and PR #9 (`5ad9434`, the merge/push guard: `loomwright@*` may merge on a `loomwright: true` project, nobody pushes to a set-up project's base). Design note: `loomwright/docs/SPIKES/ORCA_PR_CLAIM_DESIGN.md`. Set: 01 helper → 02 drains → 03 /automate.

**As a** repo owner running both Orca bots and Loomwright on my `vikashruhilgit` repos,
**I want** a deterministic claim helper that implements the contract exactly,
**so that** every Loomwright surface takes, renews and releases the claim the same way and the Orca bots read our markers as valid.

## Acceptance Criteria

**Part A — one claim helper (`scripts/pr-claim.sh`)**

- [ ] Given a PR on a repo whose owner is in `LOOMWRIGHT_CLAIM_OWNERS` (default `vikashruhilgit`), when `pr-claim.sh take <pr_url>` runs and no counting live marker exists, then it posts exactly one comment whose first line is `<!-- loomwright-claim v1 holder=<id> kind=loomwright lease_until=<now+lease, ISO second precision, Z> -->`, re-reads the comments, and only once that re-read shows our marker as the holder adds the `loomwright:claimed` label and removes `loomwright:parked` if present (a lost race leaves both labels untouched), prints `taken holder=<id> lease_until=<ts> comment=<id>` and exits 0.
- [ ] Given a counting live marker from another holder, when `take` runs, then it writes nothing and prints `held holder=<their id> kind=<their kind> lease_until=<ts>` with exit 10.
- [ ] Given a live marker of this holder, when `take` runs, then it edits that comment in place (a renew), deletes any duplicate markers of this holder, removes `loomwright:parked` if present, prints `renewed …` and exits 0. It never posts a second marker.
- [ ] Given a rival marker created before ours appears between our create and our re-read, when `take` runs, then it deletes its own comment and prints `held holder=<winner> … reason=lost-race` with exit 10.
- [ ] Given markers whose author's `author_association` is not `OWNER`, `MEMBER` or `COLLABORATOR`, a version other than `v1`, a kind other than `orca-bot|loomwright`, an invalid holder or an unparseable `lease_until`, then those markers never count (each case a test fixture).
- [ ] Given two counting live markers, then the holder is the one with the earlier `created_at`, ties broken by the lower comment id; an expired marker (`now >= lease_until`) never counts.
- [ ] Given an expired marker of this holder and no live one, when `renew` runs, then it refuses with `expired` (exit 11) and writes nothing; the caller must `take` again.
- [ ] When `release <pr_url>` runs, then it deletes every marker comment of this holder, removes `loomwright:claimed` only when no other counting live marker remains (404 = already gone), and exits 0 on every path (fail-safe).
- [ ] `release <pr_url> --parked` is the park path and is specified in Part B: hand the claim over to `pr-merge`, then the label, then the handoff, with release plus label only as the fallback. It never leaves two holders and never leaves a gap while the handover succeeds.
- [ ] Given a repo whose owner is not in scope, or no `gh` binary on PATH, when any subcommand runs, then it makes no GitHub call (asserted by an empty stub-gh call log), prints `skipped reason=out_of_scope|gh_unavailable` and exits 0.
- [ ] Given an in-scope repo and a failing comment read or write (non-zero `gh`, unparseable JSON, a comment that does not read back as a counting marker), when `take`, `renew` or `assert` runs, then it prints `unreadable reason=<first error line>` and exits 12 (fail CLOSED); `release` stays exit 0.
- [ ] `pr-claim.sh assert <pr_url>` exits 0 only when this holder holds a live claim with at least 5 minutes left (or the scope check printed `skipped`), else 10/11/12 as above. It writes nothing.
- [ ] Given any successful `take` (taken or renewed) on a PR carrying `loomwright:parked`, then the label is gone afterwards, so a stale label never wakes the merge bot. A failed removal is reported (`parked_label=remove_failed`) and does not undo the take. Test legs: fresh take, take-as-renew, lost race (label kept).
- [ ] `pr-claim.sh holder [--run-id <id>]` prints the holder id, resolved in this order: `--holder <id>` flag, then `$LOOMWRIGHT_CLAIM_HOLDER`, then a generated `loomwright@<host>/<run-id>`. A flag or env value that does not start with `loomwright@` exits 2 (the guard's `loomwright@*` merger pattern only matches that form). `<host>` is `hostname -s` with a trailing `.local` stripped, every character outside `A-Z a-z 0-9 . _ : @ / + -` replaced by `-`, cut to 40 chars; `<run-id>` gets the same character rule. The whole id is cut to 100 chars. A result that is empty or still fails `^[A-Za-z0-9._:@/+-]{1,100}$` exits 2, and so does an explicit flag or env value that fails it (refused, never silently rewritten). Test legs: host `My Mac.local` ⇒ `loomwright@My-Mac/<id>`; a 150-char run id ⇒ a 100-char holder; a space in the env value ⇒ exit 2; env `pr-merge` ⇒ exit 2.
- [ ] **The holder lives in the session env, never in a command prefix.** The guard takes identity from the environment Claude Code was started with; when that is set, a `LOOMWRIGHT_CLAIM_HOLDER=…` command prefix is ignored for merges (loomwright-orca `docs/GUARD.md` §"Who the session is"). So there is no `write-prefix` subcommand, and no model-facing instruction carries a `LOOMWRIGHT_CLAIM_HOLDER=` prefix (a prompt-lint test greps `agents`, `skills` and `commands`, and the instruction text the scripts print, and fails on one). A script may still set the variable in its own child's env (`claim-step.js`, a launched session). `pr-claim.sh session-check <holder>` exits 0 when `$LOOMWRIGHT_CLAIM_HOLDER` is exactly `<holder>`, and otherwise prints `session_mismatch session=<value|unset> holder=<holder>` and exits 13. It writes nothing and makes no GitHub call. A caller running in a session it did not start (stories 02 and 03) runs it before `take`. Test legs: equal ⇒ 0; unset ⇒ 13 `session=unset`; different ⇒ 13.
- [ ] Lease defaults to 60 minutes (`LOOMWRIGHT_CLAIM_LEASE_MIN`, 10–120 accepted, else exit 2). 120 is the contract's soft cap, so no marker is ever written with `lease_until` past now+120 min; a longer job renews instead. `renew-if-due` renews only when under half the lease remains (half-life).

**Part B — the park: hand the claim to `pr-merge`, label, send the handoff (`release --parked`)**

Orca's `github.labeled` trigger does not fire for a label added by the owner's own GitHub account, which is the account Loomwright's `gh` runs as, so `loomwright:parked` alone cannot wake the `pr-merge` bot (loomwright-orca `docs/bots/pr-merge.md` §"Wake-ups"). HANDOFF.md §5 is the agreed park: hand the claim over, add the label, send the handoff. The claim moves with no gap and never two holders, and pr-merge removes the label once it holds the claim (`claim-step.js unpark` after a handover, `take` on the fallback).

- [ ] `pr-claim.sh release <pr_url> --parked [--reason <text>] [--holder <id>]` runs these steps in order:
  1. **Pre-checks, before any write** (out of scope, no `gh`, `LOOMWRIGHT_ORCA_PARK_HANDOFF=0`, no Orca CLI, no `claim-step.js`, an unreadable head; each below). Any of them sends the run down the fallback (step 5) without a handover, so `pr-merge` is never handed a claim nobody will tell it about.
  2. **Hand over:** `node "$LOOMWRIGHT_ORCA_CHECKOUT/cli/lib/cli/src/claim-step.js" handover --repo <owner/repo> --pr <n> --holder <holder> --to ${LOOMWRIGHT_ORCA_MERGE_BOT:-pr-merge} --lease-minutes 60`, run with `LOOMWRIGHT_CLAIM_HOLDER=<holder>` in the child's env. Success is exit 0 with `"ok": true` in its JSON. Loomwright does not reimplement `handover`; the reference `claim-step.js` (loomwright-orca PR #7, `a1de67b`) is the one implementation.
  3. **Label:** add `loomwright:parked`.
  4. **Send** the handoff (body below). The output is `released parked=added|failed handover=done handoff=sent`, exit 0.
  5. **Fallback.** A refused handover (`not-held`, `held`, `lost-race`, exit 1 or 2, unparseable JSON) or any step 1 pre-check: run the plain `release` (every marker of this holder deleted), THEN add `loomwright:parked` (release first, so a reader that sees the label finds the PR free; CLAIM.md §"The parked label"), and send no handoff. The output is `released parked=added|failed handover=refused|skipped handoff=skipped reason=<why>`, exit 0.
  6. **Send fails after a successful handover** (non-zero exit, timeout, nothing parseable): hand the claim back the same no-gap way (`claim-step.js handover --holder ${LOOMWRIGHT_ORCA_MERGE_BOT:-pr-merge} --to <holder>`, as loomwright-orca's `handoff-step` does), then the step 5 fallback (release, label already on). The output is `released parked=added|failed handover=done handoff=failed reason=<why> restored=true|false`, exit 0. `restored=false` (the hand-back failed too) means `pr-merge`'s marker stays live until its 60-minute lease ends; the stderr line says so. The PR is never unclaimed while a marker is live.
  A plain `release` (no `--parked`) never hands over, never labels and never sends.
- [ ] The send is exactly this argv, with the body on stdin so no shell quoting touches it:
  `"${ORCA_CLI_COMMAND:-orca}" orchestration send --to bot:${LOOMWRIGHT_ORCA_MERGE_BOT:-pr-merge} --type handoff --subject "handoff <owner/repo>#<n>" --body-file -`
  The body is the loomwright-orca `docs/HANDOFF.md` v1 form (`src/handoff.ts` `parseHandoff` reads it): the header line first, then `key: value` lines, each once:
  ```
  loomwright-handoff v1
  repo: <owner/repo>
  pr: <n>
  project: <repo name, the part after the slash>
  dev-bot: <$LOOMWRIGHT_ORCA_DEV_BOT, else none>
  head: <40-char lower-case head SHA, read live>
  round: 1
  reason: <park reason>
  holder: loomwright@<host>/<run_id>
  ```
  `parseHandoff` skips `reason:` and `holder:`; they are for people (HANDOFF.md §1 step 2). A value runs to the end of its line, so spaces stay parseable. The helper collapses every whitespace run in the reason (newlines included) to one space, trims it, cuts it to 200 chars, and uses `unspecified` when it is empty.
- [ ] **`dev-bot` is an Orca bot, never the Loomwright run.** pr-merge sends its replies (`merged`, `fix-needed`, `waiting-owner`) to the handoff's `dev-bot` (`replyRecipient`), so it must name a bot that can act on them. The helper reads it from `$LOOMWRIGHT_ORCA_DEV_BOT`, which whoever starts the run sets (`lw-dev` for loomwright, `studio-dev` for loomwright-studio). Unset or empty ⇒ `dev-bot: none`, which HANDOFF.md requires to be said, not left out; pr-merge then answers the project's settings `devBot`, else the owner. A value that is `none`, fails `HOLDER_RE`, or starts with `loomwright@` is not a bot: the helper writes `dev-bot: none` and one `pr-claim: dev_bot_invalid value=<v>` stderr line. The run's claim holder goes on the `holder:` line only.
- [ ] The head comes from one live read, `gh pr view <n> -R <owner/repo> --json headRefOid`, never from the caller. A failed read or a value that is not 40 hex chars sends the run down the fallback: `handover=skipped handoff=skipped reason=head_unreadable`.
- [ ] **Detected at runtime, no hard dependency, fail-SAFE.** Every path exits 0. The pre-checks that send the run to the fallback before any handover:
  - out of scope (owner not in `LOOMWRIGHT_CLAIM_OWNERS`) or no `gh`: `skipped reason=out_of_scope|gh_unavailable`, no GitHub, `node` or orca call at all (as for every subcommand);
  - `LOOMWRIGHT_ORCA_PARK_HANDOFF=0`: `reason=disabled`;
  - `${ORCA_CLI_COMMAND:-orca}` does not resolve with `command -v` to an executable: `reason=orca_unavailable`;
  - `LOOMWRIGHT_ORCA_CHECKOUT` unset, its `cli/lib/cli/src/claim-step.js` missing, or no `node` on PATH: `reason=claim_step_unavailable`.
  The send and each `claim-step.js` call run under a 20 s watchdog (background child + kill; macOS has no `timeout`) that leaves no child behind. Every `failed`, `refused` and `skipped` (except `out_of_scope`) also writes one `pr-claim: park handover=<status> handoff=<status> reason=<why> pr=<owner/repo>#<n>` line to stderr, so the caller can log it.
- [ ] **One place.** `release --parked` is the only code in `loomwright/` that runs `orchestration send`, `claim-step.js`, or reads `ORCA_CLI_COMMAND`, `LOOMWRIGHT_ORCA_CHECKOUT` or `LOOMWRIGHT_ORCA_DEV_BOT`. A test greps `loomwright/scripts`, `agents`, `skills` and `commands` (tests and docs excluded) and fails on any other hit.
- [ ] **Tests** (`test-pr-claim.sh`; a stub orca named by `ORCA_CLI_COMMAND` and a stub `claim-step.js` under a temp `LOOMWRIGHT_ORCA_CHECKOUT` each write their argv, one per line, their stdin and their `LOOMWRIGHT_CLAIM_HOLDER` to one shared log; exit code, stdout and stderr are set per leg):
  - (a) main path, `--reason "gate: required check ci failed (ubuntu)"`, `LOOMWRIGHT_ORCA_DEV_BOT=lw-dev`: the shared log shows, in order, the `handover … --to pr-merge` call (child env holder = the run's holder), the label add, the orca send; the send argv equals the line above exactly; no marker delete by Loomwright (the handover deleted it). The body has the header first and each field once, `dev-bot: lw-dev`, `holder:` the run's holder, `head` the stub-gh SHA, `round: 1`. A test-local copy of `parseHandoff`'s rules (header line, required fields, 40-hex head, `HOLDER_RE`, `none` allowed) accepts it. A reason with a newline and tab reads back collapsed to one line;
  - (b) `LOOMWRIGHT_ORCA_DEV_BOT` unset ⇒ `dev-bot: none`; set to `loomwright@x/y` ⇒ `dev-bot: none` plus the `dev_bot_invalid` stderr line;
  - (c) handover refused (stub `claim-step.js` prints `{"ok":false,"reason":"lost-race"}`, exit 1): the log shows the handover attempt, then the marker deletes, then the label add, and no orca call; output `handover=refused handoff=skipped reason=lost-race`;
  - (d) orca absent, `LOOMWRIGHT_ORCA_CHECKOUT` unset, `LOOMWRIGHT_ORCA_PARK_HANDOFF=0`, a head read failure: each makes no `claim-step.js` and no orca call, and the log shows release then label;
  - (e) send exits 1 with stderr `There is no bot named pr-merge on this computer`: the log shows handover, label, send, the hand-back `handover --holder pr-merge --to <holder>`, then the release; output `handoff=failed reason=There is no bot named pr-merge on this computer restored=true`, exit 0. The same with the hand-back stub failing: `restored=false`;
  - (f) a send stub that sleeps past the watchdog: `handoff=failed reason=timeout`, then the hand-back, exit 0, and no child still running (found by a marker file the stub writes, not by a `pgrep -f` on the test's own command text);
  - (g) out of scope and a plain `release`: an empty `claim-step.js` and orca log; out of scope also an empty gh log.

## Non-goals
- Changing `gate-eval`'s seven conditions, its PARK reasons or its merge command.
- Claiming during Supervisor Phase 4.5 / FINALIZE pushes inside `/autonomous` RUN (the PR is brand new; no drain is working it yet).
- A background renew heartbeat process.
- Implementing the merge bot, or enforcing claims for other tools (the Orca worker and `claim-guard` hook do that).
- Repos outside `LOOMWRIGHT_CLAIM_OWNERS`.

## Owner decisions
- 2026-11-28 (owner, via orca-plugin-dev): adopt CLAIM.md v1; `kind=loomwright`; scope is `vikashruhilgit` repos only; park signal is either a marker field or a `loomwright:parked` label, implementer's choice with justification — chosen: the label (release deletes the marker, so a marker field would vanish with it).
- Fail mode: fail-OPEN (no GitHub call) out of scope and when `gh` is absent; fail-CLOSED in scope when the claim cannot be read or written. Agreed by orca-plugin-dev 2026-11-28.
- 2026-11-28 (orca-plugin-dev answers): `loomwright:parked` agreed. Loomwright adds it after releasing, on a trusted-auto-merge gate PARK only. The merge bot removes it when it takes the claim, and Loomwright removes it on any take of its own. CLAIM.md gains the label on their side. A 60-min lease with half-life renewal is fine; the contract's soft cap is 120 min (renew, never lease longer). Holder ids must match `[A-Za-z0-9._:@/+-]{1,100}`: sanitise the hostname, then validate or truncate the whole id.
- Holder granularity (implementer's choice, design note §"Holder id"): one holder per run, `loomwright@<host>/<run-id>`, not one per machine.
- 2026-11-28 (orca-plugin-dev, via the coordinator): Orca's `github.labeled` trigger ignores labels the owner's own account adds, so keep `loomwright:parked` and ADD a direct `orca orchestration send --to bot:pr-merge --type handoff` after it, on a trusted-auto-merge gate PARK only, in scope only, fail-safe (log and park as today, never fail the run), isolated in one helper and detected at runtime. Body: HANDOFF.md v1 (Part B). The request wrote the fields as `repo=… from=… reason=…`; `parseHandoff` refuses that single-line form, so the helper sends the v1 header plus `key: value` lines, with `from` as `dev-bot` and `reason` as an extra line the parser skips.
- 2026-11-28 (orca-plugin-dev, final answer; supersedes the "release, then label, then send" order and `dev-bot: <holder>` above): the park is HANDOFF.md §5: `claim-step handover --to pr-merge` (no gap, never two holders), then `loomwright:parked`, then the send; a refused handover falls back to release plus the label. pr-merge removes the label once it holds the claim. The body is the HANDOFF.md v1 form with `head` the live 40-hex SHA and `round: 1`, plus `reason:` and `holder: loomwright@<host>/<run_id>`. `dev-bot` must be an Orca bot, read from `LOOMWRIGHT_ORCA_DEV_BOT` (set by whoever starts the run: `lw-dev` for loomwright, `studio-dev` for loomwright-studio), else `dev-bot: none`; replies go to the dev bot, never to the Loomwright run. Loomwright sessions carry `LOOMWRIGHT_CLAIM_HOLDER=loomwright@<host>/<run_id>` in their environment; a command prefix does not count. On a project set up with `loomwright: true` the guard lets `loomwright@*` merge alongside pr-merge; nobody pushes to a set-up project's base branch. Counterpart shipped on loomwright-orca main: PR #7 `a1de67b`, PR #9 `5ad9434`.
- Send-failure after a handover (implementer's choice, mirroring loomwright-orca `handoff-step`): hand the claim back, then release, so a failed send never leaves pr-merge holding a PR it was not told about.

## Priority: MVP
**Rationale:** Orca bots already honour and enforce the claim; until Loomwright takes it, a drain can be refused mid-round by the `claim-guard` hook, and the merge bot has no signal.

## Assumptions
- `gh` is authenticated as an account whose `author_association` on in-scope repos is OWNER/MEMBER/COLLABORATOR.
- GitHub's add-labels endpoint creates a missing label (the reference `src/gh.ts` relies on this).
- The drain driver is called at least once per fix-worker spawn, so a 60-minute lease with half-life renewal covers the longest single step; a fix worker longer than the lease ends `claim_lost` at its pre-push assert rather than pushing unclaimed.

## Dependencies
- Depends on: none (contract merged in loomwright-orca PR #1).
- Blocks: the shared PR-merge bot's wake-on-park.
- Runtime-optional: the Orca CLI (`$ORCA_CLI_COMMAND`, else `orca` on PATH) and a loomwright-orca checkout with its compiled `claim-step.js` (`$LOOMWRIGHT_ORCA_CHECKOUT`, PR #7 `a1de67b` or later) plus `node`. Without either the park falls back to release plus label and everything else behaves the same.

## Risks
- The `claim-guard` hook is installed on the owner's Mac. It takes identity from the session env; a command prefix is ignored for merges whenever the env is set, and counts otherwise only as an unauthenticated declaration (loomwright-orca `docs/GUARD.md`). A session missing the holder means a refused push mid-drain, so stories 02 and 03 have one AC per spawn path, and an in-scope run whose session lacks the holder refuses before taking the claim.
- A handover to `pr-merge` on a machine where the `pr-merge` bot does not exist: the send fails, the hand-back runs, and the PR ends released with the label (step 6). If the hand-back also fails, pr-merge's marker blocks the PR for up to 60 minutes.
- Clock skew eats into the lease (UTC everywhere, `date -u`).

## Validation (must pass before merge)
1. **Static — claim helper:** `bash loomwright/scripts/test-pr-claim.sh` passes (stub gh: every case above, including the lost-race and the no-GitHub-call scope cases, plus parity with a fixture of `src/claim.ts`'s marker strings and regex); `bash scripts/ci-local.sh --affected` green.
2. **Running system — live claim round trip:** against a throwaway PR in `vikashruhilgit/studio-sandbox`: take on a PR carrying a stale `loomwright:parked` (removed) → a second holder's take is refused → renew → `release --parked` shows the marker gone, `loomwright:claimed` removed and `loomwright:parked` present; the Orca panel shows the claim while held. On a second take, `release --parked` with `LOOMWRIGHT_ORCA_MERGE_BOT` pointed at a throwaway bot (the shared `pr-merge` bot may not exist yet) and `LOOMWRIGHT_ORCA_CHECKOUT` at a loomwright-orca checkout at `a1de67b` or later prints `handover=done handoff=sent`: the PR's one marker is the throwaway bot's, `loomwright:parked` is on, and the message shows in that bot's Home Chat with the v1 body (`dev-bot: none` with the env unset). With `ORCA_CLI_COMMAND` pointed at a missing path, the same call prints `handover=skipped handoff=skipped reason=orca_unavailable`, leaves no marker and the label on, and exits 0. With the bot name pointed at a bot that does not exist, it prints `handoff=failed … restored=true` and leaves no marker. Evidence: `docs/evidence/pr-claim-live.md`.
