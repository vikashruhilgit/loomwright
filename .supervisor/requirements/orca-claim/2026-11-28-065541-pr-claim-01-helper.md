# PR claim 01 — `pr-claim.sh` helper (CLAIM.md v1 take / renew / release / assert)

## Status: pending

Owner approval: 2026-11-28, request from `orca-plugin-dev` (relayed by the Orca coordinator). Contract: `vikashruhilgit/loomwright-orca` `docs/CLAIM.md` (v1), reference implementation `src/claim.ts` (PR #1, merged). Design note: `loomwright/docs/SPIKES/ORCA_PR_CLAIM_DESIGN.md`. Set: 01 helper → 02 drains → 03 /automate.

**As a** repo owner running both Orca bots and Loomwright on my `vikashruhilgit` repos,
**I want** a deterministic claim helper that implements the contract exactly,
**so that** every Loomwright surface takes, renews and releases the claim the same way and the Orca bots read our markers as valid.

## Acceptance Criteria

**Part A — one claim helper (`scripts/pr-claim.sh`)**

- [ ] Given a PR on a repo whose owner is in `LOOMWRIGHT_CLAIM_OWNERS` (default `vikashruhilgit`), when `pr-claim.sh take <pr_url>` runs and no counting live marker exists, then it posts exactly one comment whose first line is `<!-- loomwright-claim v1 holder=<id> kind=loomwright lease_until=<now+lease, ISO second precision, Z> -->`, re-reads the comments, and only once that re-read shows our marker as the holder adds the `loomwright:claimed` label and removes `loomwright:parked` if present (a lost race leaves both labels untouched), prints `taken holder=<id> lease_until=<ts> comment=<id>` and exits 0.
- [ ] Given a counting live marker from another holder, when `take` runs, then it writes nothing and prints `held holder=<their id> kind=<their kind> lease_until=<ts>` with exit 10.
- [ ] Given a live marker of this holder, when `take` runs, then it edits that comment in place (a renew), deletes any duplicate markers of this holder, removes `loomwright:parked` if present, prints `renewed …` and exits 0. It never posts a second marker.
- [ ] Given a rival marker created before ours appears between our create and our re-read, when `take` runs, then it deletes its own comment and prints `held holder=<winner> … reason=lost-race` with exit 10.
- [ ] Given markers whose author's `author_association` is not `OWNER`, `MEMBER` or `COLLABORATOR`, a version other than `v1`, a kind other than `orca-bot|loomwright`, an invalid holder or an unparseable `lease_until`, then those markers never count (each case a test fixture).
- [ ] Given two counting live markers, then the holder is the one with the earlier `created_at`, ties broken by the lower comment id; an expired marker (`now >= lease_until`) never counts.
- [ ] Given an expired marker of this holder and no live one, when `renew` runs, then it refuses with `expired` (exit 11) and writes nothing; the caller must `take` again.
- [ ] When `release <pr_url>` runs, then it deletes every marker comment of this holder, removes `loomwright:claimed` only when no other counting live marker remains (404 = already gone), and exits 0 on every path (fail-safe).
- [ ] When `release <pr_url> --parked` runs, then it first releases as above and THEN adds the `loomwright:parked` label (release before label, so a bot woken by the label finds the PR free), prints `released parked=added|failed`, exits 0.
- [ ] Given a repo whose owner is not in scope, or no `gh` binary on PATH, when any subcommand runs, then it makes no GitHub call (asserted by an empty stub-gh call log), prints `skipped reason=out_of_scope|gh_unavailable` and exits 0.
- [ ] Given an in-scope repo and a failing comment read or write (non-zero `gh`, unparseable JSON, a comment that does not read back as a counting marker), when `take`, `renew` or `assert` runs, then it prints `unreadable reason=<first error line>` and exits 12 (fail CLOSED); `release` stays exit 0.
- [ ] `pr-claim.sh assert <pr_url>` exits 0 only when this holder holds a live claim with at least 5 minutes left (or the scope check printed `skipped`), else 10/11/12 as above. It writes nothing.
- [ ] Given any successful `take` (taken or renewed) on a PR carrying `loomwright:parked`, then the label is gone afterwards, so a stale label never wakes the merge bot. A failed removal is reported (`parked_label=remove_failed`) and does not undo the take. Test legs: fresh take, take-as-renew, lost race (label kept).
- [ ] `pr-claim.sh holder [--run-id <id>]` prints the holder id, resolved in this order: `--holder <id>` flag, then `$LOOMWRIGHT_CLAIM_HOLDER`, then a generated `loomwright@<host>/<run-id>`. `<host>` is `hostname -s` with a trailing `.local` stripped, every character outside `A-Z a-z 0-9 . _ : @ / + -` replaced by `-`, cut to 40 chars; `<run-id>` gets the same character rule. The whole id is cut to 100 chars. A result that is empty or still fails `^[A-Za-z0-9._:@/+-]{1,100}$` exits 2, and so does an explicit flag or env value that fails it (refused, never silently rewritten). Test legs: host `My Mac.local` ⇒ `loomwright@My-Mac/<id>`; a 150-char run id ⇒ a 100-char holder; a space in the env value ⇒ exit 2.
- [ ] `pr-claim.sh write-prefix <holder>` prints `LOOMWRIGHT_CLAIM_HOLDER=<holder> ` (with a trailing space) when the current `$LOOMWRIGHT_CLAIM_HOLDER` is not exactly `<holder>`, and nothing when it is. Every caller that hands a model a direct PR-write command builds it with this, so the prefix is decided in one place.
- [ ] Lease defaults to 60 minutes (`LOOMWRIGHT_CLAIM_LEASE_MIN`, 10–120 accepted, else exit 2). 120 is the contract's soft cap, so no marker is ever written with `lease_until` past now+120 min; a longer job renews instead. `renew-if-due` renews only when under half the lease remains (half-life).

**Part B — direct handoff to the merge bot on a park (`handoff-parked`)**

Orca's `github.labeled` trigger does not fire for a label added by the owner's own GitHub account, which is the account Loomwright's `gh` runs as, so `loomwright:parked` alone cannot wake the `pr-merge` bot (orca-plugin-dev, 2026-11-28; loomwright-orca `docs/bots/pr-merge.md` §"Wake-ups"). The label stays; a direct Orca message is added after it.

- [ ] `pr-claim.sh release <pr_url> --parked [--reason <text>] [--holder <id>]` runs, in this order: the release, the label add, then `pr-claim.sh handoff-parked <pr_url> --reason <text>` (also callable on its own). The handoff runs whatever the label result was. Output becomes `released parked=added|failed handoff=sent|skipped|failed[ reason=<why>]`, exit 0. A plain `release` (no `--parked`) never sends a handoff.
- [ ] `handoff-parked` sends exactly one message, with this argv (the body on stdin, so no shell quoting touches it):
  `"${ORCA_CLI_COMMAND:-orca}" orchestration send --to bot:${LOOMWRIGHT_ORCA_MERGE_BOT:-pr-merge} --type handoff --subject "parked <owner/repo>#<n>" --body-file -`
  The body is the loomwright-orca `docs/HANDOFF.md` v1 handoff (`src/handoff.ts` `parseHandoff` is the parser that reads it):
  ```
  loomwright-handoff v1
  repo: <owner/repo>
  pr: <n>
  project: <repo name, the part after the slash>
  dev-bot: <the run's claim holder>
  head: <40-char lower-case head SHA>
  round: 1
  reason: <park reason>
  ```
  Field mapping from the request's `repo= pr= project= from= head= reason=`: `from` is `dev-bot` (HANDOFF.md's name for the sender's holder id; holder ids already match its `HOLDER_RE`). `reason` is not a `parseHandoff` field. Unknown `key: value` lines are skipped, so it travels for people without breaking the parse. A value runs to the end of its line, so spaces in it stay parseable. The helper collapses every whitespace run in the reason (newlines included) to one space, trims it, cuts it to 200 chars, and uses `unspecified` when it is empty. A single-line `repo=… pr=…` body is refused by `parseHandoff` ("no `loomwright-handoff v1` line"), so the helper never sends that form.
- [ ] The head comes from one live read, `gh pr view <n> -R <owner/repo> --json headRefOid`, never from the caller. A failed read or a value that is not 40 hex chars means nothing is sent: `handoff=skipped reason=head_unreadable`.
- [ ] **Detected at runtime, no hard dependency, fail-SAFE.** Every path exits 0 and leaves the release and the label exactly as they were without the handoff:
  - out of scope (owner not in `LOOMWRIGHT_CLAIM_OWNERS`) or no `gh`: `skipped reason=out_of_scope|gh_unavailable`, no orca call;
  - `LOOMWRIGHT_ORCA_PARK_HANDOFF=0`: `skipped reason=disabled`, no orca call;
  - `${ORCA_CLI_COMMAND:-orca}` does not resolve with `command -v` to an executable: `skipped reason=orca_unavailable`, no orca call;
  - the send exits non-zero, or runs past a 20 s watchdog (background child + kill; macOS has no `timeout`), or prints nothing parseable: `failed reason=<first stderr line, max 120 chars>|timeout`. The watchdog leaves no child process behind.
  Every `failed` and `skipped` (except `out_of_scope`) also writes one `pr-claim: handoff <status> reason=<why> pr=<owner/repo>#<n>` line to stderr, so the caller can log it.
- [ ] **One place.** `handoff-parked` is the only code in `loomwright/` that runs `orchestration send` or reads `ORCA_CLI_COMMAND`. A test greps `loomwright/scripts`, `agents`, `skills` and `commands` (tests and docs excluded) and fails on any other hit.
- [ ] **Tests** (`test-pr-claim.sh`; a stub orca named by `ORCA_CLI_COMMAND` writes its argv, one per line, and its stdin to a log, and its exit code and stderr are set per leg):
  - (a) `release --parked --reason "gate: required check ci failed (ubuntu)"`: the logged argv equals the line above exactly. The body has the header first and each field once. `head` is the stub-gh SHA and `dev-bot` the holder. A test-local copy of `parseHandoff`'s rules (header line, required fields, 40-hex head, `HOLDER_RE`) accepts it. The reason reads back as one line with its spaces. A reason with a newline and tab reads back collapsed;
  - (b) orca absent (`ORCA_CLI_COMMAND` unset and a PATH without `orca`): `handoff=skipped reason=orca_unavailable`. The stub-gh call log is identical to leg (a)'s apart from the head read, exit 0;
  - (c) stub exits 1 with stderr `no such bot: pr-merge`: `handoff=failed reason=no such bot: pr-merge`, the stderr log line is present, the gh call log is the same as in (a), exit 0;
  - (d) the order: one shared log shows the marker deletes, then the label add, then the orca send;
  - (e) a stub that sleeps past the watchdog: `failed reason=timeout`, exit 0, and no child still running (found by a marker file the stub writes, not by a `pgrep -f` on the test's own command text);
  - (f) out of scope, `LOOMWRIGHT_ORCA_PARK_HANDOFF=0`, a head read failure, and a plain `release`: each makes no orca call (an empty stub log).

## Non-goals
- Changing `gate-eval`'s seven conditions, its PARK reasons or its merge command.
- Claiming during Supervisor Phase 4.5 / FINALIZE pushes inside `/autonomous` RUN (the PR is brand new; no drain is working it yet).
- A background renew heartbeat process.
- Implementing the merge bot, or enforcing claims for other tools (the Orca worker and `claim-guard` hook do that).
- Repos outside `LOOMWRIGHT_CLAIM_OWNERS`.

## Owner decisions
- 2026-11-28 (owner, via orca-plugin-dev): adopt CLAIM.md v1; `kind=loomwright`; scope is `vikashruhilgit` repos only; park signal is either a marker field or a `loomwright:parked` label, implementer's choice with justification — chosen: the label (release deletes the marker, so a marker field would vanish with it).
- Fail mode: fail-OPEN (no GitHub call) out of scope and when `gh` is absent; fail-CLOSED in scope when the claim cannot be read or written. Agreed by orca-plugin-dev 2026-11-28.
- 2026-11-28 (orca-plugin-dev answers): `loomwright:parked` agreed. Loomwright adds it after releasing, on a trusted-auto-merge gate PARK only. The merge bot removes it when it takes the claim, and Loomwright removes it on any take of its own. CLAIM.md gains the label on their side. A 60-min lease with half-life renewal is fine; the contract's soft cap is 120 min (renew, never lease longer). Holder ids must match `[A-Za-z0-9._:@/+-]{1,100}`: sanitise the hostname, then validate or truncate the whole id.
- Holder granularity (implementer's choice, design note §"Holder id"): one holder per run, `loomwright@<host>/<run-id>`, not one per machine.
- 2026-11-28 (orca-plugin-dev, via the coordinator): Orca's `github.labeled` trigger ignores labels the owner's own account adds, so keep `loomwright:parked` and ADD a direct `orca orchestration send --to bot:pr-merge --type handoff` after it, on a trusted-auto-merge gate PARK only, in scope only, fail-safe (log and park as today, never fail the run), isolated in one helper and detected at runtime. Body: HANDOFF.md v1 (Part B). The request wrote the fields as `repo=… from=… reason=…`; `parseHandoff` refuses that single-line form, so the helper sends the v1 header plus `key: value` lines, with `from` as `dev-bot` and `reason` as an extra line the parser skips.

## Priority: MVP
**Rationale:** Orca bots already honour and enforce the claim; until Loomwright takes it, a drain can be refused mid-round by the `claim-guard` hook, and the merge bot has no signal.

## Assumptions
- `gh` is authenticated as an account whose `author_association` on in-scope repos is OWNER/MEMBER/COLLABORATOR.
- GitHub's add-labels endpoint creates a missing label (the reference `src/gh.ts` relies on this).
- The drain driver is called at least once per fix-worker spawn, so a 60-minute lease with half-life renewal covers the longest single step; a fix worker longer than the lease ends `claim_lost` at its pre-push assert rather than pushing unclaimed.

## Dependencies
- Depends on: none (contract merged in loomwright-orca PR #1).
- Blocks: the shared PR-merge bot's wake-on-park.
- Runtime-optional: the Orca CLI (`$ORCA_CLI_COMMAND`, else `orca` on PATH). Without it the handoff is skipped and everything else behaves the same.

## Risks
- The `claim-guard` hook is installed on the owner's Mac. It admits a PR write only when the session env, or the command's own `LOOMWRIGHT_CLAIM_HOLDER=` prefix, names the live holder exactly. A missed spawn path means a refused push mid-drain, so stories 02 and 03 have one AC per path.
- Clock skew eats into the lease (UTC everywhere, `date -u`).

## Validation (must pass before merge)
1. **Static — claim helper:** `bash loomwright/scripts/test-pr-claim.sh` passes (stub gh: every case above, including the lost-race and the no-GitHub-call scope cases, plus parity with a fixture of `src/claim.ts`'s marker strings and regex); `bash scripts/ci-local.sh --affected` green.
2. **Running system — live claim round trip:** against a throwaway PR in `vikashruhilgit/studio-sandbox`: take on a PR carrying a stale `loomwright:parked` (removed) → a second holder's take is refused → renew → `release --parked` shows the marker gone, `loomwright:claimed` removed and `loomwright:parked` present; the Orca panel shows the claim while held. Then `handoff-parked` on the same PR with `LOOMWRIGHT_ORCA_MERGE_BOT` pointed at a throwaway bot (the shared `pr-merge` bot may not exist yet) prints `handoff=sent`, and the message shows in that bot's Home Chat with the v1 body. With `ORCA_CLI_COMMAND` pointed at a missing path, the same call prints `handoff=skipped reason=orca_unavailable` and exits 0. Evidence: `docs/evidence/pr-claim-live.md`.
