# PR claim 03 — `/automate` item claim and the `loomwright:parked` signal on a gate PARK

## Status: pending

Owner approval: 2026-11-28, request from `orca-plugin-dev` (relayed by the Orca coordinator). Contract: `vikashruhilgit/loomwright-orca` `docs/CLAIM.md` (v1), reference implementation `src/claim.ts` (PR #1, merged). Design note: `loomwright/docs/SPIKES/ORCA_PR_CLAIM_DESIGN.md`. Set: 01 helper → 02 drains → 03 /automate.

**As a** repo owner running both Orca bots and Loomwright on my `vikashruhilgit` repos,
**I want** `/automate` to hold the claim across an item's drain and gate, and to leave the `loomwright:parked` label when the trusted auto-merge gate parks instead of merging,
**so that** the shared PR-merge bot wakes on exactly the PRs Loomwright's gate declined, and nothing else touches a PR mid-item.

## Acceptance Criteria

**Part D — `/automate` (item-level claim, gate park signal)**

- [ ] **One holder per run.** INIT resolves `pr-claim.sh holder --run-id <run_id>` (`loomwright@<host>/<run_id>`; an explicit `$LOOMWRIGHT_CLAIM_HOLDER` wins) and writes it once to `## Run Config` as `claim_holder:`. `--resume`, `--merge-parked` and every later step read that line and never regenerate it, so a resumed run renews its own live claim. Under `--parallel N` each lane has its own `run_id`, so it has its own holder. Test: two lanes of one wave get two distinct holders, and a resume keeps the recorded one.
- [ ] **Holder on every spawn path (claim-guard).** Each path that can write to the item's PR carries the run's holder, each with a test leg:
  - **fresh phase sessions** (`phase-launch`, `automate-lanes.d/phase.sh`): `LOOMWRIGHT_CLAIM_HOLDER=<claim_holder>` is in the launched session's `env` for every phase (launch-pad, supervisor, drain), so the session and its Task fix workers inherit it;
  - **lanes** (`lane-launch`, `automate-lanes.d/launch.sh`): the same, with the lane's own holder;
  - **`--inline-phases` drain and the coordinator's fix-now re-drain** (they run in the owner's session, whose env Loomwright cannot set): the drain invocation carries `--claim-outer --claim-holder <claim_holder>`, so the driver emits prefixed write commands (story 02);
  - **the merge**: `gate-eval`'s `gh pr merge` runs inside `automate-helpers.sh`, so the guard cannot see it; the `gate-eval` step still runs it with `LOOMWRIGHT_CLAIM_HOLDER=<claim_holder>` in its env, and the coordinator never hands the model a bare merge command;
  - **engine-posted PR comments and label writes** go through scripts with the holder in their env.
  The test asserts each captured launch env or invocation names the holder, and that no model-facing instruction the engine prints carries an unprefixed `gh pr comment|edit|merge` or push when the session env is not the holder.

- [ ] Given an item with a PR, when `automate-next-step.sh`'s `drain` step runs, then it takes the claim before printing the owned-drain spawn and passes `--claim-outer --claim-holder <claim_holder>` in the drain invocation; `held` ⇒ the item parks `pause_reason: claimed` with the park message `claimed by <holder> (lease until <ts>)`, run lock released, no drain spawned; `unreadable` ⇒ the same park with `claim_unreadable`.
- [ ] The fix-now re-drain, `--resume` RECONCILE of an open-PR item, and `--merge-parked` each take (or renew) the claim before touching the PR, with the same `claimed` park on `held`.
- [ ] Given `--auto-merge`, when the `gate-eval` step runs, then it first runs `pr-claim.sh assert`; not held ⇒ park `claimed` (gate-eval not called). `automate-helpers.sh gate_eval()` is byte-for-byte unchanged (a test diffs its body against a pinned hash).
- [ ] Given `gate-eval` prints `PARK: <reason>` (the loop's gate and `--merge-parked`'s merge-gate), when the park writes run, then `release --parked` runs once, and the park's Progress line records `claim released (parked label: added|failed)`.
- [ ] Given `gate-eval` prints `MERGE`, or the item parks in safe mode (`awaiting_merge`) or as `escalated`, then plain `release` runs (no `loomwright:parked` label).
- [ ] `pause_reason: claimed` is added to the run-file template's list, `docs/result-schemas/automate-run.md` and every surface that restates the enum, in the same change.

## Non-goals
- Changing `gate-eval`'s seven conditions, its PARK reasons or its merge command.
- Claiming during Supervisor Phase 4.5 / FINALIZE pushes inside `/autonomous` RUN (the PR is brand new; no drain is working it yet).
- A background renew heartbeat process.
- Implementing the merge bot, or enforcing claims for other tools (the Orca worker and `claim-guard` hook do that).
- Repos outside `LOOMWRIGHT_CLAIM_OWNERS`.

## Owner decisions
- 2026-11-28 (owner, via orca-plugin-dev): adopt CLAIM.md v1; `kind=loomwright`; scope is `vikashruhilgit` repos only; park signal is either a marker field or a `loomwright:parked` label, implementer's choice with justification — chosen: the label (release deletes the marker, so a marker field would vanish with it).
- Fail mode: fail-OPEN (no GitHub call) out of scope and when `gh` is absent; fail-CLOSED in scope when the claim cannot be read or written. Agreed by orca-plugin-dev 2026-11-28.
- 2026-11-28 (orca-plugin-dev answers): only a trusted-auto-merge gate PARK adds `loomwright:parked` (after release); safe-mode `awaiting_merge` and escalated parks never do. Any Loomwright take removes a stale `loomwright:parked`. 60-min lease, half-life renewal, 120-min soft cap.
- 2026-11-28 (owner, via the coordinator): the `claim-guard` hook is installed in `~/.claude/settings.json` on this Mac for `vikashruhilgit` repos. It admits a PR write only when the session's `LOOMWRIGHT_CLAIM_HOLDER`, or the command's own `LOOMWRIGHT_CLAIM_HOLDER=` prefix, equals the live holder exactly. Every Loomwright session or command that writes to a PR it claimed must carry the holder.
- Holder granularity (implementer's choice, design note §"Holder id"): one holder per run (`loomwright@<host>/<run-id>`), not one per machine.

## Priority: MVP
**Rationale:** Orca bots already honour and enforce the claim; until Loomwright takes it, a drain can be refused mid-round by the `claim-guard` hook, and the merge bot has no signal.

## Assumptions
- `gh` is authenticated as an account whose `author_association` on in-scope repos is OWNER/MEMBER/COLLABORATOR.
- GitHub's add-labels endpoint creates a missing label (the reference `src/gh.ts` relies on this).
- The drain driver is called at least once per fix-worker spawn, so a 60-minute lease with half-life renewal covers the longest single step; a fix worker longer than the lease ends `claim_lost` at its pre-push assert rather than pushing unclaimed.

## Dependencies
- Depends on: none (contract merged in loomwright-orca PR #1).
- Blocks: the shared PR-merge bot's wake-on-park.

## Risks
- A spawn path that does not carry the holder has its PR writes refused by the installed `claim-guard` mid-drain. Each path below has its own AC and test, and the live validation runs with the real hook installed.
- Clock skew eats into the lease (UTC everywhere, `date -u`).

## Validation (must pass before merge)
1. **Static — engine:** the `test-automate-next-step*.sh` suites and `bash loomwright/scripts/test-automate-helpers.sh` pass with new legs for the drain-step take, the `claimed` park, `--claim-outer` in the drain invocation, `release --parked` after a `PARK:` (loop gate and `--merge-parked`), plain release after `MERGE` / safe park / escalated park, the per-run holder in `## Run Config` across a resume, the holder in every phase/lane launch env and in the inline drain invocation, and the pinned `gate_eval()` body hash; the `gh pr merge --squash` invariant grep is unchanged; `bash scripts/ci-local.sh --affected` green.
2. **Running system — park signal:** a `/automate --auto-merge` item on `studio-sandbox` whose gate parks (e.g. `--trust-unprotected` absent on an unprotected branch) ends with no claim marker, `loomwright:claimed` gone and `loomwright:parked` present; an item whose PR carries a live `orca-bot` claim parks `claimed` before any drain. With the installed `claim-guard` active, a default fresh-phase item and an `--inline-phases` item each drain (fix pushed) and reach the gate with no guard refusal. Evidence appended to `docs/evidence/pr-claim-live.md`.
