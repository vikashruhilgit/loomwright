# PR claim 02 — `/review-pr` drains take, renew and release the claim

## Status: pending

Owner approval: 2026-11-28, request from `orca-plugin-dev` (relayed by the Orca coordinator). Contract: `vikashruhilgit/loomwright-orca` `docs/CLAIM.md` (v1), reference implementation `src/claim.ts` (PR #1, merged); guard: `docs/GUARD.md` (PR #9, `5ad9434`). Design note: `loomwright/docs/SPIKES/ORCA_PR_CLAIM_DESIGN.md`. Set: 01 helper → 02 drains → 03 /automate.

**As a** repo owner running both Orca bots and Loomwright on my `vikashruhilgit` repos,
**I want** every `/review-pr` run (until-mergeable driver, detached dispatch, default loop) to hold the claim while it works a PR and to stand down when someone else holds it,
**so that** a drain never pushes to or reviews a PR an Orca bot is working.

## Acceptance Criteria

**Part B — the drain driver (`/review-pr --until-mergeable`, standalone, detached and `/automate`'s owned drain)**

- [ ] Given another holder's live claim, when the driver's `start` step runs, then no round runs, no fix worker is spawned, nothing is pushed, and the run ends `decision: ESCALATED`, `termination_reason: claimed`, `escalation_cause: other`, a summary starting `claimed by <holder>`, and a new optional `claim` field `held_by_other`.
- [ ] Given an `unreadable` claim answer in scope, then the run ends `ESCALATED`, `termination_reason: claim_unreadable` (never READY, nothing pushed). `claimed`, `claim_unreadable`, `claim_lost` and `claim_holder_not_in_session` are added to the `termination_reason` enum in `docs/result-schemas/review-heal-result.md` and every surface that restates it, in the same change.
- [ ] Given a held claim, when every later driver call runs, then it calls `renew-if-due`; immediately before printing a `fix worker` spawn it renews to a full lease; a renew answering `held` or `expired`-and-retake-refused ends the run `ESCALATED` `claim_lost` before the spawn.
- [ ] The `fix worker` spawn prompt tells the worker to run `pr-claim.sh assert <pr_url>` immediately before its push and not push on a non-zero exit, reporting `claim_lost`; a prompt-lint test pins the sentence.
- [ ] Given the run took the claim itself (no `--claim-outer`), when the run reaches `finish` on ANY terminal path (READY, ESCALATED, error escalation), then it runs `release` once. Given `--claim-outer`, it never releases.
- [ ] Given an out-of-scope repo or no `gh`, then the driver behaves byte-for-byte as today except the result block's `claim: skipped_out_of_scope|skipped_gh_unavailable` field.
- [ ] **Holder per drain run, taken from the session env.** `--start drain` resolves the holder once and stores it in the driver sidecar, and every later call of the run reuses it. Resolution: `--claim-holder <id>` (passed by `/automate` and by the detached dispatcher), else `$LOOMWRIGHT_CLAIM_HOLDER`, through `pr-claim.sh holder`. The driver never generates a holder for a session it did not start: in scope it then runs `pr-claim.sh session-check <holder>`, and an unset env or a mismatch ends the run `ESCALATED`, `termination_reason: claim_holder_not_in_session`, before any claim read or write, with a summary naming the fix (start the session with `LOOMWRIGHT_CLAIM_HOLDER=loomwright@<host>/<label>`, or use the detached dispatch, which sets it). Out of scope the check is skipped. The detached dispatcher generates a fresh `loomwright@<host>/review-<pr#>-<6 hex>` per run, so a second detached drain on the same PR gets a different holder and is refused (`claimed`), never treated as a renew. Two inline sessions started with the same env value share a holder; that is the owner's choice of value.
- [ ] **Holder reaches every PR write through the session env (claim-guard).** The guard reads identity from the session's own environment; a `LOOMWRIGHT_CLAIM_HOLDER=` command prefix is ignored for merges when the env is set and is only a declaration otherwise (loomwright-orca `docs/GUARD.md` §"Who the session is"). So no instruction the driver prints carries a prefix: the fix worker's push is plain `git push origin HEAD:<head_ref>` and any PR comment plain `gh pr comment …`. They pass the guard because the session (and its Task fix workers, which inherit its env) already carries the holder, which the `session-check` above guarantees. Every `gh`/script child the driver runs itself also gets `LOOMWRIGHT_CLAIM_HOLDER=<holder>` in its env. Test: with the env equal to the holder, no emitted command carries a prefix, and a test-local copy of the guard's admit rule (session env == live holder) admits every emitted write and refuses the same writes from a session with a different holder; with the env unset in scope, the run ends `claim_holder_not_in_session` and emits no write command.
- [ ] **Detached path (`dispatch-pr-review.sh`, including the `gh pr create` PostToolUse backstop that calls it).** The dispatcher generates the holder (`pr-claim.sh holder --run-id review-<pr#>-<hex>`), puts `LOOMWRIGHT_CLAIM_HOLDER=<holder>` in the detached `claude -p` process env and passes `--claim-holder <holder>` through the runner's env contract (`LOOMWRIGHT_CLAIM_HOLDER` is the one variable), so the runner session, its Task fix workers (same process, inherited env) and the driver all agree. The pinned exact push allowlist entry stays unchanged and unprefixed: the env carries the holder. The only allowlist addition is exactly `Bash(bash <scripts>/pr-claim.sh assert *)` (no raw `gh api`). Test: the `DRY_RUN_DISPATCH` line shows the env assignment, the `--claim-holder` equal to it, and the unchanged push entry.

**Part C — the default `/review-pr` loop (no `--until-mergeable`)**

- [ ] Step 1 of `skills/review-heal/SKILL.md` resolves the holder (`pr-claim.sh holder`, same rule as Part B), runs `pr-claim.sh session-check <holder>` in scope (unset or mismatch ⇒ `ESCALATED` `claim_holder_not_in_session`, nothing read or written), and takes the claim before any review. `held` ⇒ `ESCALATED` with a summary `claimed by <holder>` and no new PR comment. Each iteration runs `renew-if-due`; the fix worker asserts before its push; every exit releases. No write the loop or its fix worker makes carries a `LOOMWRIGHT_CLAIM_HOLDER=` prefix. A lint test pins the five calls (holder, session-check, take, renew-if-due, release) and the pre-push assert, and fails on a prefix.

## Non-goals
- Changing `gate-eval`'s seven conditions, its PARK reasons or its merge command.
- Claiming during Supervisor Phase 4.5 / FINALIZE pushes inside `/autonomous` RUN (the PR is brand new; no drain is working it yet).
- A background renew heartbeat process.
- Implementing the merge bot, or enforcing claims for other tools (the Orca worker and `claim-guard` hook do that).
- Repos outside `LOOMWRIGHT_CLAIM_OWNERS`.

## Owner decisions
- 2026-11-28 (owner, via orca-plugin-dev): adopt CLAIM.md v1; `kind=loomwright`; scope is `vikashruhilgit` repos only; park signal is either a marker field or a `loomwright:parked` label, implementer's choice with justification — chosen: the label (release deletes the marker, so a marker field would vanish with it).
- Fail mode: fail-OPEN (no GitHub call) out of scope and when `gh` is absent; fail-CLOSED in scope when the claim cannot be read or written. Agreed by orca-plugin-dev 2026-11-28.
- 2026-11-28 (orca-plugin-dev answers): only a trusted-auto-merge gate PARK adds `loomwright:parked` (after release); safe-mode `awaiting_merge` and escalated parks never do. Any Loomwright take removes a stale `loomwright:parked`. 60-min lease, half-life renewal, 120-min soft cap.
- 2026-11-28 (owner, via the coordinator): the `claim-guard` hook is installed in `~/.claude/settings.json` on this Mac for `vikashruhilgit` repos. and admits a PR write only when the writer is the live holder.
- 2026-11-28 (orca-plugin-dev, final answer; supersedes the `write-prefix` design): Loomwright sessions carry `LOOMWRIGHT_CLAIM_HOLDER=loomwright@<host>/<run_id>` in their environment; a command prefix does not count. On a project set up with `loomwright: true` the guard lets `loomwright@*` merge alongside pr-merge; nobody pushes to a set-up project's base branch. Counterpart on loomwright-orca main: PR #7 `a1de67b`, PR #9 `5ad9434`.
- An inline session whose env lacks the holder (implementer's choice): fail closed with `claim_holder_not_in_session` rather than generate a holder the guard would not see.
- Holder granularity (implementer's choice, design note §"Holder id"): one holder per run (`loomwright@<host>/<run-id>`), not one per machine.

## Priority: MVP
**Rationale:** Orca bots already honour and enforce the claim; until Loomwright takes it, a drain can be refused mid-round by the `claim-guard` hook, and the merge bot has no signal.

## Assumptions
- `gh` is authenticated as an account whose `author_association` on in-scope repos is OWNER/MEMBER/COLLABORATOR.
- GitHub's add-labels endpoint creates a missing label (the reference `src/gh.ts` relies on this).
- The drain driver is called at least once per fix-worker spawn, so a 60-minute lease with half-life renewal covers the longest single step; a fix worker longer than the lease ends `claim_lost` at its pre-push assert rather than pushing unclaimed.

## Dependencies
- Depends on: none on our side (contract merged in loomwright-orca PR #1; guard identity rule in PR #9 `5ad9434`).
- Blocks: the shared PR-merge bot's wake-on-park.

## Risks
- A spawn path that does not carry the holder has its PR writes refused by the installed `claim-guard` mid-drain. Each path has its own AC and test, an inline session without the env stops before it claims, and the live validation runs with the real hook installed.
- An inline `/review-pr` now needs the owner to start Claude Code with `LOOMWRIGHT_CLAIM_HOLDER` set on in-scope repos. Without it the drain stops with `claim_holder_not_in_session`; the detached dispatch is the path that needs no setup.
- Clock skew eats into the lease (UTC everywhere, `date -u`).

## Validation (must pass before merge)
1. **Static — driver and dispatcher:** `bash loomwright/scripts/test-review-heal-next-step.sh` and `bash loomwright/scripts/test-dispatch-pr-review.sh` pass with new legs for `claimed`, `claim_unreadable`, `claim_lost`, renew-before-fix, release-on-every-terminal-path, `--claim-outer` never releasing, the per-run holder (two detached drains get different holders), `claim_holder_not_in_session` (env unset, env mismatch), the no-prefix legs with the guard's admit rule, and the out-of-scope byte-identical path; the prompt-lint legs pin the pre-push assert sentence and Part C's five calls and fail on any `LOOMWRIGHT_CLAIM_HOLDER=` prefix; `bash scripts/ci-local.sh --affected` green.
2. **Running system — drain stands down:** with an `orca-bot` marker live on a `studio-sandbox` PR, `/review-pr <pr> --until-mergeable` ends `ESCALATED` `claimed by <holder>` without pushing. After release, with the installed `claim-guard` active, (a) an inline `/review-pr` in a session started with `LOOMWRIGHT_CLAIM_HOLDER=loomwright@<host>/<label>` and (b) a Supervisor-dispatched detached drain each take the claim, push a fix without a guard refusal, and release at the end (marker gone, label removed). (c) An inline `/review-pr` in a session started without the env ends `claim_holder_not_in_session` with no marker written. A hand-run `gh pr comment` from a session without the holder is refused while the claim is live. Evidence appended to `docs/evidence/pr-claim-live.md`.
