## Task
**Goal:** Wire the proven findings→community **bridge** into the plugin's **Phase 4.5 self-heal review** and **Launch Pad risk** so each run can answer *"what do we already know about the areas of code this change touches?"* — surfacing prior misses / churn / lessons for the touched graph-**communities** as **advisory** context. This is the APPLY step that aims to move the self-heal catch-rate above its 0% baseline. **Advisory, non-gating, fail-safe throughout.**

The bridge's value over the existing exact-path `read-postmortem.sh` reader: it joins by **graph community** (`finding.changed_paths → graph node.source_file → node.community`), so a near-miss path that exact-path matching drops (the documented `read-postmortem.sh` / Launch Pad action-0b limitation) still surfaces area knowledge when it falls in a community with prior recorded misses.

## Acceptance Criteria
- [ ] Given a repo WITH a graph+bridge, when Phase 4.5 reviews a diff touching a community that has prior recorded misses, then the `code-reviewer` receives that area-knowledge as advisory context (observable in the review output) — and it never changes the verdict by itself.
- [ ] Given a repo WITHOUT a graph (or without a built bridge), when any phase runs, then behavior is unchanged (the bridge read is a silent no-op).
- [ ] Given the graduated bridge tool, when run, then it rebuilds the per-community index from the current graph + findings, READ-ONLY toward graph/findings, gitignored output. **Builder** exits 0 on missing graph/python (jq is optional/guarded, not required); the **reader** exits 0 on missing graph/bridge/jq.

- [ ] No `heal_decision` / gate / review verdict can be changed or blocked by the bridge (advisory-only verified by reading the wiring).

## Hard Constraints (invariants — do not break)
- **Advisory / non-gating:** the bridge NEVER changes `heal_decision`, a review `decision`, or any gate; NEVER blocks a PR. `CODE_REVIEW_RESULT` stays the sole gating signal. (Mirror the `prior_churn` HARD ADVISORY CONTRACT in `skills/self-heal-advisory/SKILL.md`.)

Every new script ALWAYS exits 0 on its read/advisory paths (the bimodal rule: advisory emitters fail SAFE; only correctness gates fail CLOSED — and this introduces NO new gate).

- **Keep the two review lenses independent** — do NOT homogenize CI review and self-heal review; the bridge feeds the self-heal REVIEW lens only (never workers/fixers, mirroring `prior_churn`).
- **Honor the staleness rule** (`skills/brain-context/SKILL.md` §"staleness rule"): graph authoritative for committed structure only, never for files the session is editing; compare bridge `built_at_commit` vs HEAD and downgrade to a "hint" when HEAD has advanced.
