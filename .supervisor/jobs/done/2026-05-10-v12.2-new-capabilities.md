### S4 — Webhook Notification (`type: command` wrapper)
**Goal:** Add optional webhook notification on Supervisor completion; gated on `AGENT_MANAGER_WEBHOOK_URL` env var presence. Implemented as `type: command` hook invoking a shell wrapper, NOT `type: http` — Claude Code hook env-var interpolation only works for HTTP `headers`, not `url`, so the URL must be resolved inside a script.

**Acceptance criteria:**
- New file `ai-agent-manager-plugin/scripts/send-webhook.sh` is a fire-and-forget wrapper that:
  - Reads `AGENT_MANAGER_WEBHOOK_URL` from env; if unset → exit 0 immediately (no-op)
  - Reads hook payload from stdin (Claude Code passes hook input on stdin)
  - Extracts SUPERVISOR_RESULT fields and constructs JSON: `{agent, status, pr_url, summary, timestamp}`
  - Runs `curl -X POST -H "Content-Type: application/json" -d "<json>" "$AGENT_MANAGER_WEBHOOK_URL"` with a short timeout (5s)
  - **Always exits 0** regardless of curl outcome (fire-and-forget, never blocks Supervisor)
  - Script is executable (`chmod +x` set in commit)
- `hooks/hooks.json` adds new hook on Supervisor SubagentStop:
  - `type: command`
  - `command`: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/send-webhook.sh"` — MUST follow the existing telemetry hook quoting convention (quoted path inside `bash "..."`) to survive plugin install paths containing spaces. Reference: existing `send-telemetry.sh` invocation in `hooks/hooks.json`.
  - Coexists with existing telemetry SubagentStop hook (both fire on the same event)
- `docs/TELEMETRY.md` adds new "Webhook Notifications" section explaining: complement to GitHub Issues telemetry; different purpose (real-time ops alerts vs. longitudinal analytics); env var setup; payload schema; why command-wrapper not type:http (env interpolation limitation)

## Risk Assessment

| Risk | Severity | Source | Mitigation |
|---|---|---|---|
| `curl` not installed on host running Supervisor | LOW | Webhook wrapper depends on curl | Wrapper detects missing curl, exits 0 silently (fire-and-forget contract preserved); document in TELEMETRY.md as install requirement |
| JSON extraction from stdin payload fails (malformed SUPERVISOR_RESULT) | MEDIUM | Wrapper parses Claude Code hook payload | Use `jq` with safe defaults (`-r // empty`); on parse failure, log to stderr and exit 0 (do not block Supervisor); test against fixture before merge |
| `AGENT_MANAGER_WEBHOOK_URL` set to internal/sensitive URL by mistake | MEDIUM | User-controlled env var | Document in TELEMETRY.md that the env var is user responsibility; payload contains only PR URL + summary, no secrets/tokens; recommend webhook receivers validate origin |
| Plugin install path contains spaces — script invocation breaks | LOW | Existing telemetry hook precedent | Hook command MUST use `bash "${CLAUDE_PLUGIN_ROOT}/scripts/send-webhook.sh"` with quoted path (matches existing telemetry convention) |
| Outcomes Rubric grader may produce inconsistent scores across runs | LOW | LLM grading variance | S2 grader uses Haiku in plan mode (read-only); rubric items must be observable (testable assertions, not subjective) |
| `/dreaming` may consume large context reading session logs | LOW | Log size variance | S3 default `--sessions 5` limits scope; longer histories require explicit opt-in via `--sessions N` |
