## Task
**Goal:** Ship `/verify <ticket>` — a `commands/verify.md` that shells its main-thread steps out to a new self-tested `scripts/verify-run.sh` (`acs` AC extraction for both ticket kinds, `preflight` = contract read → `assert-non-prod` → diff summary → run dir + `run_start`/`env` lines, `walk` = generate a per-run Playwright config and run the agent-authored `[ACn]` specs with `--reporter=json`, then **ingest** the reporter JSON into one `ac` evidence line per AC through `verify-helpers.sh evidence-append`, `verdict` for the browser-less `NOT_VERIFIABLE`/`BLOCKED` lines, `finish` = `run_end` + `summary-build`), a `skills/verify-walkthrough/SKILL.md` protocol authority (AC extraction rules, AC → spec derivation, the four verdicts, the V7 mutation carve-out, evidence-per-AC, budget), a new top-level `--verify <run_dir>` branch in `agents/qa-executor.md` (skips planning/discovery/strategy/generation/audit; env start → author specs → `walk` → `finish`; emits a `VERIFY_RESULT` block whose counts are COPIED from `summary-build`'s derived counts row, never tallied), a `VERIFY_RESULT` schema + a `VERIFY_RESULT` acceptance branch in `validate-qa-result.py` (hook command unchanged), `commands/qa-executor.md` flag prose synced, and `scripts/test-verify-walkthrough.sh` whose fixture app + broken-form mutation control proves every verdict comes from observation — so that a ticket's acceptance criteria are walked in the running app with one evidenced verdict per criterion, advisory only.

**Problem Statement:**
No surface verifies a ticket against the running app: `## Executable Acceptance` is `cmd:`/`corpus-task:` only, `/qa-executor` crawls the whole app from discovery and forbids form submission, Phase 4.5 and CI review read the diff. The owner's ask — "run the app, walk through it, fill the form, check the implementation" — has no home. Items 01 (`.agent/verify.json` contract + `verify-env.sh` executor) and 02 (append-only `evidence.jsonl` + derived `summary.md`) are merged; nothing yet reads a ticket, starts the app, drives it, and records a verdict.
Currently a human does this by hand or not at all. This causes tickets that "landed" without anyone having observed the acceptance criteria in the product, and QA findings with no ticket to attach to.
Success looks like: `/verify <ticket>` reads the ticket's ACs, refuses to touch anything that is not proven non-prod, starts the app from the contract, walks each AC with Playwright, and appends one of exactly four verdicts per AC with evidence — where `PASS` is emitted ONLY when the Then was observed, `NOT_VERIFIABLE` says so when it cannot be, and a test proves that breaking the app flips a `PASS` to a `FAIL` with a reason and an artifact.
