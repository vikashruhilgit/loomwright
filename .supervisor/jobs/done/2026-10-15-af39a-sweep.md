**Problem Statement:**

Currently this primary checkout carries 20 local branches that are not ancestors of `origin/main` (squash merges hide them from ancestry), 6 sibling worktrees that `worktree-audit.sh report` lists as merged orphans, and 2 app-made worktrees; `fleet-closeout` prints the placeholder `sweep: unavailable (automate-followups/22 not shipped)`. ### Implementation notes (both subtasks)
- **Candidates.** Worktrees from `git worktree list --porcelain` (never the primary). Origin: under `<primary>/.claude/worktrees/` ⇒ `app` (report only); under `<primary>-lanes/` ⇒ `lane` (report only); path present in `worktree-audit.sh`'s log as a `created` worktree, or a `<parent>/<project>-<suffix>` sibling ⇒ `plugin`; anything else ⇒ `kept other — origin unknown`. Worktrees are judged first, then branches, so a branch checked out in a worktree removed this run becomes a candidate in the same run (a dry run reports what `--apply` would do).
- **Rule (exactly `closeout`'s, no new heuristic).** Newest PR for the branch via `gh pr list --state all --head <B> --json number,state,headRefOid,mergedAt` (newest = highest number); removable only on `MERGED` AND local tip == `headRefOid`. A detached-HEAD worktree has no branch to prove ⇒ kept.
- **Gitignored salvage.** `worktree-salvage.sh --ignored` copies each PRESENT entry of `.supervisor/logs/`, `.supervisor/postmortem/`, `.claude/settings.local.json` to `<salvage>/ignored/<rel>`, verifies each landed byte-identical, and prints as its LAST stdout line `ignored: ok <n>` or `ignored: failed <rel> — <reason>`; exit stays 0. Callers treat anything but an `ignored: ok` line (including no line at all) as a failure and keep the worktree — fail closed on a fail-safe emitter's output (lesson dba90cf3: test the empty case).
- **Liveness.** A worktree that is any live process's cwd (`lsof -a -d cwd`, prefix match on the worktree path) is kept with the pid named; `lsof` absent or failing ⇒ kept (`liveness unverifiable`). No kill.
- **Entry point name.** The implementation function in `automate-trail.sh` is `sweep_run()` (the `outputs_verified` token); its `main()` arm is `sweep)`. The `fleet-closeout` call passes `sweep --root <primary>`; the run-end summary line keeps the `sweep: summary — …` text.
- **Run-end line.** `<ts> sweep (dry run): <the summary line>` appended once per run at `## Status: done` (§6 Termination prose, `finalize-empty` after its trail line, `fleet-closeout` finalize). Never `--apply`.
- **`/automate --sweep [--apply]`.** The owner's typed flag is the authorization — no new question gate. `--sweep` combined with a source or `--resume` is refused with one line, nothing run.
- **Tests (Subtask 1).** Real git repos in `mktemp -d`, `gh` stubbed by PATH, every listed leg in AC1–AC6 plus the closeout 3a ignored-salvage leg; the dry-run leg compares a checksum of `git worktree list --porcelain` + `git branch -v` before/after.
