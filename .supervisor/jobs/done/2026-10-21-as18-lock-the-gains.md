## Task
**Goal:** Add a fail-CLOSED CI lint that counts history references in runtime prompt files against a committed baseline that may only go down, and re-baseline every prompt-size ceiling in `prompt-token-budgets.json` to its post-diet measure + ~10%.

**Problem Statement:**
The plugin maintainer needs the automate-speed diet (items 13–16, 26) to stay won, because nothing stops the next fix PR from writing "the case seen on #NNN" back into a runtime prompt, and the item-17 ceilings still sit at pre-diet sizes.
Currently, runtime prompts carry about 354 history references (prototype count at the base commit, over `loomwright/agents/`, `loomwright/commands/`, `loomwright/skills/`), and 19 of the 79 ceilings sit more than 10% above their live measure (e.g. `execute-manager` 42568 budget vs 19342 live, `skills/automate-loop` 77733 vs 43965, `commands/autonomous` 11846 vs 3964). This leaves room for the prompts to grow back unnoticed.
Success looks like: a new history reference in a runtime prompt turns CI red, a raised baseline entry turns CI red, and every ceiling is within ~10% of its live measure.

**Design (binding for the worker):**
- **Scanned set (runtime prompts):** every `*.md` under `loomwright/agents/`, `loomwright/commands/`, `loomwright/skills/` (recursive, `SKILLS_INDEX.md` included), **plus** `loomwright/docs/command-parts/**/*.md`. The command parts are counted because `check-token-budget.sh` already treats them as part of a command's runtime weight (its `.commands` header: "every *.md under <command parts dir>/<stem>/"). The set is enumerated by a filesystem walk (`find … -name '*.md'`), never `git ls-files`. That way a new untracked prompt is counted by a local pre-push `ci-local.sh` run without the temp-index special case `check-vendor-coupling.sh` needs. Nothing else under `loomwright/docs/` is scanned (not `docs/rationale/`, not `CHANGELOG.md`, not `changelog.d/`, not `docs/evidence/`).
- **Reference patterns (ERE, counted per match):** `#NNN` (`#` + 2–5 digits, not preceded by `&`, a letter/digit or `_`, so HTML entities and anchors like `foo#12` are not counted); `<queue>/<NN>` (a lowercase slug, `/`, two digits and an optional letter suffix, e.g. `automate-speed/26`, `harness-port/03`, `af39b`-style suffix allowed); `YYYY-MM-DD` (`20[0-9]{2}-[0-9]{2}-[0-9]{2}`); `item NN` (case-insensitive `item` + 2 digits + optional letter); `vX.Y.Z` (`v` + three dot-separated integers, not preceded by a letter/digit). The patterns live in ONE place in the script, and the test file uses that same definition. They are not restated in prose elsewhere.
- **Frozen example values stay exempt** (the convention `scripts/check-doc-currency.sh` documents under `FROZEN, VERSION-AGNOSTIC EXAMPLE VALUES ARE INTENTIONALLY LEFT ALONE`): a line holding a sample `session_end` record (`"event":"session_end"`, any spacing), a `"plugin_version"` key, or a `POSTMORTEM_RESULT` sample record is not counted. Known instance at base: `loomwright/skills/state-management/SKILL.md`'s `{"ts":"2026-03-09T14:34:00Z","event":"session_end",…}` line.
- **Baseline:** `loomwright/docs/prompt-history-refs-baseline.json` — `{"_comment": "<one line>", "files": {"<repo-relative path>": <non-negative integer>, …}}`, one entry per scanned file (zero-count files included), generated by the script itself (`--write-baseline`, used once to create it and by a later lowering PR, never by CI).
- **Verdicts (`check-prompt-history-refs.sh`, exit 0 / 1):**
  - file count > its entry ⇒ exit 1; the output names the file and prints each matched reference in it as `path:line: <token>`. Where the base copy of the file can be read, it prints only the matches the base copy lacks.
  - file count < its entry ⇒ exit 0, prints `lower the baseline: <path> <entry> -> <count>`.
  - **raise check (the baseline may only go down):** the base ref is `$PROMPT_HISTORY_REFS_BASE` if set, else `git merge-base origin/main HEAD`, else `origin/main`. Read the base's baseline with `git show <base>:loomwright/docs/prompt-history-refs-baseline.json`. Any entry higher than the same entry at base ⇒ exit 1 (`baseline rose: <path> <base> -> <now>`). New entries are allowed only while the baseline's total does not rise above the base total (so a move-only split can redistribute references, but cannot add new ones). There are three distinct base cases. Keep them separate in the code and in the script header:
    - **(a) the base REF does not resolve** (no `origin/main`, a fetch that failed) ⇒ `raise_check: skipped (<reason>)`, no failure; with `PROMPT_HISTORY_REFS_REQUIRE_BASE=1` it is an ERROR (exit 1). This mirrors `check-vendor-coupling.sh`'s `raise_skip() {` / `VENDOR_COUPLING_REQUIRE_BASE` design.
    - **(b) the base ref resolves but has NO baseline file** (the bootstrap case: THIS PR creates the file, so `main` at base `e1f51ed` lacks it) ⇒ `raise_check: skipped (no baseline at base — bootstrap)` and exit 0 **even under `PROMPT_HISTORY_REFS_REQUIRE_BASE=1`**. This deliberately differs from vendor-coupling, whose "manifest path does not exist at base" skip is an ERROR under require-base. Without the bootstrap carve-out, this PR's own GitHub CI would go red. Say so in the header.
    - **(c) the base has a baseline file that is malformed JSON or holds a non-integer entry** ⇒ ERROR, exit 1 (fail-CLOSED).
  - **fail-CLOSED errors (exit 1):** jq missing; baseline file missing or malformed JSON (the reader validates with `jq -e` before reading any value); a non-integer or negative entry; a scanned file with no entry; an entry naming a file that is not in the scanned set (orphan); a scanned dir missing or empty (zero scanned files is never green).
  - Flags: `--root <dir>` (scan a fixture tree; default repo root), `--baseline <file>`, `--write-baseline`. Bash 3.2 safe, BSD/GNU portable (`wc -c`/`grep -oE`, no `${var//…}` on large strings, no GNU-only flags).
- **CI:** a new `ci.yml` step placed after the vendor-coupling step, written in the same shape: `git fetch --no-tags --depth=1 origin +refs/heads/main:refs/prompt-history-refs/base`, env `PROMPT_HISTORY_REFS_BASE: refs/prompt-history-refs/base` + `PROMPT_HISTORY_REFS_REQUIRE_BASE: "1"`, then `bash scripts/test-check-prompt-history-refs.sh` and `bash scripts/check-prompt-history-refs.sh`, with no `|| true`. **`scripts/ci-local.sh` needs no edit:** it derives its gates from every `bash scripts/<gate>.sh` line in `ci.yml` (its header: `derived, not hand-listed`). The requirement's "wire it into `scripts/ci-local.sh`" is met by that derivation and verified with `--list` (AC9), not by hand-listing.
- **Ceiling re-baseline:** for EVERY row of `.agents`, `.skills`, `.commands` in `prompt-token-budgets.json`: `measured` = the live proxy that `check-token-budget.sh` prints at the end of the change, and `budget` = `ceil(measured × 1.10)`. This lowers the loose rows and also gives the near-breach rows their full ~10% margin back (e.g. `product-owner` 23 headroom). Each `note` stays one line, under 200 chars. The mirror tables in `ARCHITECTURE_CONTRACTS.md` §"Prompt Token Budgets" (agent table, `### Skill size ceilings`, `### Command size ceilings`) carry the same budget and measured cells. Every agent row becomes a LIVE re-measure row. In the SAME edit: (i) give the `rubric-grader` table cell a ¹ marker; (ii) update the ¹ footnote; (iii) update the bold enumeration paragraph that holds the authoritative list of ¹-marked rows. That paragraph begins `**\`measured\` and the "Preloaded skills" column are frozen, decorative authoring-time metadata, not enforced values, EXCEPT the ¹-marked rows above**`. Add `rubric-grader` to its list, remove `the unmarked row is \`rubric-grader\``, and reword its frozen/decorative and "do not chase" wording so it states that automate-speed/18 re-baselined every row to live, while a later raise still changes only the budget column; (iv) rewrite `rubric-grader`'s JSON `note` (currently `measured = frozen v15.10.0 baseline; …`) as a one-line live note. `scripts/check-token-budget.sh`'s drift message `the measured column is a FROZEN baseline; a raise changes only the budget column` is NOT edited.
