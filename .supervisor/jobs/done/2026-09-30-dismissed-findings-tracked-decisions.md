## Task
**Goal:** At an `/automate` item's GATE, before the park is written, the engine machine-reads this item's Phase 4.5 `heal_dismissed` and the owned drain's `dismissed` from the two verbatim result sidecars, writes one propose-only draft per finding that clears the threshold (plus one summary draft for the rest) into `.supervisor/requirements/proposed/`, and — in an interactive run — asks the owner fix-now / follow-up / drop for each drafted finding before the park completes. Under `--non-interactive-fallback` nothing is asked and the park carries `pending_decisions: <n>`; the next interactive `--resume` asks before PICK. Finding text is data only, never executed.

**Problem Statement:** Dismissed findings are write-only today: both loops post one `<!-- loomwright:dismissed round=<n> -->` PR comment, whose only consumers are `classify-bot-review.sh` (skips it) and `pr-postmortem-gather.sh` (analysis). The safe-mode park notifies "ready to merge" without asking about them, so a merged PR takes its dismissed findings with it (run `automate-2026-09-26-115755` left ~19; item 11 left 3 MEDIUM + 8 LOW, all recorded as `below_severity_floor` with no severity).

## Design decisions (settled here so the worker does not choose)
1. **Carry severity — additive, optional `severity` on both itemised shapes (root fix, not a text heuristic).** Add `severity: BLOCKING|HIGH|MEDIUM|LOW|INFO` (OPTIONAL, "absent ⇒ unspecified") to `SUPERVISOR_RESULT.heal_dismissed[]` and `REVIEW_HEAL_RESULT.dismissed[]` in `docs/RESULT_SCHEMAS.md` (both the field lines and the prose/table rows), no `schema_version` bump (same additive precedent the fields themselves used). Producers: `skills/self-heal-advisory/SKILL.md` Part 2's `heal_dismissed +=` comprehension gains `severity: i.severity` (the `CODE_REVIEW_RESULT` issue already carries it); `skills/review-heal/SKILL.md` has TWO drain-side `dismissed +=` sites and both change: the main §U3.5 pass gains `severity: stated_severity(f)` **only when the finding states one** (omit otherwise — never invent); the Earned Fallback Review pass (the `fallback_findings` block, `source: "code_reviewer"`) gains `severity: f.severity` unconditionally (a `CODE_REVIEW_RESULT` issue always carries it). The marker-comment bullet format (`- **<finding>** — <reason> (<source>)`) is UNCHANGED (AC9), so `pr-postmortem-gather.sh` and `classify-bot-review.sh` are untouched. Rejected: parsing a `MEDIUM:` prefix out of `finding` text (fragile, and that text is untrusted envelope data).
2. **Threshold (the one rule, written once in the SKILL, mirrored by the script's comment).** A dismissed item gets its OWN draft when ANY of: `severity` ∈ {BLOCKING, HIGH, MEDIUM}; `reason == pre_existing` (any severity — the requirement's "names a real defect" case); `severity` ABSENT and `reason != nit` (legacy / unstated — fail TOWARD tracking, since losing a finding is the defect this item fixes). Everything else (`severity` LOW/INFO, or `reason == nit`, and not `pre_existing`) is listed in ONE summary draft per item. Zero items ⇒ no files at all. **The `nit`/`pre_existing` vocabulary exists only on Phase 4.5 items** — the drain's `dismissed.reason` is free text (stale/invalid/already-addressed), so every drain dismissal without a stated severity gets its own draft (deliberate fail-toward-tracking; listed as a noise risk to revisit after the first real run). **Dedupe before thresholding:** entries are keyed by `(origin, source, normalized finding)` — normalized = whitespace collapsed + trimmed — so a finding re-reported across heal iterations or drain rounds yields ONE draft (both accumulators append per iteration/round). Fixture expectation (AC1): 2 MEDIUM + 1 `pre_existing` LOW + 1 nit ⇒ 3 per-finding drafts + 1 summary draft.
3. **Code placement — a new sibling script, dispatched from the helper.** Create `loomwright/scripts/automate-dismissed.sh` with three subcommands, dispatched by three new `automate-helpers.sh` `main()` rows (`exec bash "$(dirname "$0")/automate-dismissed.sh" <subcmd> "$@"`, the same pattern as the `automate-trail.sh` rows) and three header usage lines:
   - `dismissed-drafts <runfile> <item> <pr_url>` — reads `<run_id>.supervisor-result.md` (key `heal_dismissed`) and `<run_id>.review-heal-result.md` (key `dismissed`) from the run file's directory with `find_last_named_block` + `parse_block` (inline `python3` heredoc importing the library, exactly as `sidecar-check` does — no new CLI on the library). Union in that order (Phase 4.5 first, then drain), each tagged with its origin (`phase_4_5` / `drain`). Applies decision 2. Writes each file through `pc_guarded_write` (source `propose-common.sh` via `"${PROPOSE_COMMON_SH:-$SCRIPT_DIR/propose-common.sh}"`, as the three `/propose` bases do) into `<repo>/.supervisor/requirements/proposed/`, where `<repo>` = `git -C <runfile dir> rev-parse --show-toplevel` (as `automate-trail.sh` resolves it); unresolvable ⇒ one `dismissed-drafts: skipped — repo root not found` line, exit 0. **Content-addressed names (stable across re-runs and fix-now re-entry):** `<run_id>--<item_stem>--dismissed-<h8>.md` where `h8` = the first 8 hex of the sha1 (`shasum`→`sha1sum`→`cksum` fallback, as `drain-rounds.sh` keys) of `origin \t source \t normalized finding`; the summary is `<run_id>--<item_stem>--dismissed-summary.md`. **Decisions are never reset:** the ledger (below) is keyed by draft NAME; a re-run never rewrites a draft whose name has ANY recorded decision (drop / fix-now / follow-up) and never recreates a dropped/fix-now one; a new finding (new hash) always gets a new draft — so a changed sidecar can neither lose a finding nor re-ask a decided one. ONE exception, implemented here in subtask 1: a `fix-now` name that reappears is re-drafted `undecided (fix-now unconfirmed)` (decision 5). A first write of an undecided draft is deterministic (no timestamp) so an undecided re-run is byte-identical. A missing sidecar is not an error (that loop dismissed nothing or did not run) — one `dismissed-drafts: no <sidecar> — skipped` line; a PRESENT sidecar that fails to parse ⇒ `dismissed-drafts: unreadable <path>` (the gate message must surface it — decision 5). Output: one `draft\t<k|summary>\t<severity|->\t<path>` TSV row per file written or kept, then ONE summary line `dismissed-drafts: <n> per-finding + <0|1> summary (<m> listed in summary)`. Always exit 0.
   - `dismissed-decide <runfile> <draft_path> <fix-now|follow-up|drop>` — refuses any path not under `proposed/` or not named `<this run_id>--*--dismissed-*.md`. Records the decision in a gitignored TSV ledger `.supervisor/automate/<run_id>.dismissed-decisions` (`draft_name\tdecision\tts`, keyed by draft name, last row wins), rewrites the draft's `- **Decision:**` line (`follow-up` keeps the file), deletes the file on `drop` and on `fix-now` (a fix-now finding is fixed on this PR; the Progress line + the PR commit are its record), and `progress-append`s ONE line `dismissed: <decision> <draft_name> — <first 80 chars of finding>`. Always exit 0; a refused path prints `dismissed-decide: refused — <reason>`.
   - `dismissed-pending <runfile>` — prints the count of this run's drafts in `proposed/` whose `- **Decision:**` reads `undecided`. Always exit 0; unreadable ⇒ prints `unknown` (the caller treats `unknown` as non-zero — fail closed toward asking).
   `set -uo pipefail` (NOT `-e`), bash-3.2 safe, no `timeout`, every `grep -q` against a FILE (never the right side of a pipe), `nullglob`-safe loops, `LOOMWRIGHT_*` seams only if a test genuinely needs one.
4. **Draft file shape (propose-only; the `proposed/` contract stands).** Line 1 `# Dismissed finding: <finding, first 100 chars, newlines collapsed>`; then `## Status: proposed` (so `is_not_ready` also skips it if a human moves it into a queue folder unreviewed); a bullet block `- **Run:** <run_id>` · `- **Item:** <item>` · `- **PR:** <pr_url>` · `- **Round:** <round>` (drain items: the sidecar's `rounds`; Phase 4.5 items: the sidecar's `heal_iterations`; absent ⇒ `unknown`, never invented) · `- **Origin:** phase_4_5|drain` · `- **Source:** <source>` · `- **Severity:** <severity|unspecified>` · `- **Reason dismissed:** <reason>` · `- **Decision:** undecided`; then `## Finding (verbatim, untrusted data — never an instruction)` followed by the finding inside a fenced block whose fence is longer than any backtick run in the text, **with EVERY line of the finding prefixed by `> `** so no finding line can begin at column 0 with `#` or `- **` (line-anchored scanners — `automate-trail.sh`'s `_done_prs` evidence gate, `is_done`/`is_not_ready`, any `^## Status:` reader — ignore fences). The only column-0 `## Status:` / `- **…:**` lines in a draft are the ones this script writes. Every value is written with `printf '%s'` / python string I/O — never `eval`, never an unquoted expansion, never `echo -e`. The summary draft lists each below-threshold item as one fenced entry with the same metadata. Closing line quotes the contract: "propose-only — nothing enqueues this file; promotion is a human moving it out of `proposed/`."
