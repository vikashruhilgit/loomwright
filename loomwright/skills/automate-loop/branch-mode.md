## §13 — Branch mode (opt-in, default OFF)

A repo that opts in keeps its run history — `.supervisor/requirements/`, `jobs/done|failed/`, `automate/*.md`, the findings ledger — on the metadata branch that `scripts/meta-sync.sh` syncs (`docs/ARCHITECTURE_CONTRACTS.md` §"Metadata branch": what travels, the learning stores and their consent) instead of committing it to the default branch through a trail PR. A repo that has not opted in takes every other section of this skill byte-for-byte; nothing below runs.

- **The switch and its ONE reader.** `/setup memory` writes the mode (`setup-memory.sh apply --branch-mode <branch>`, `--branch-mode off` to restore the default). `setup-memory.sh mode` prints exactly one line — `off` | `on <branch>` | `unknown <reason>` — and every caller below uses it; nothing else parses the managed `.gitignore` block.
- **`meta-entry` FIRST, on every entry.** Before §4's glob, before any run file is created, before the PICK run-lock acquire, run `automate-helpers.sh meta-entry`. It reads the mode itself and prints one line: `meta-entry: off` ⇒ proceed exactly as today; `meta-entry: pulled <branch>` ⇒ run history is current, proceed; `meta-entry: failed — <reason>` ⇒ **no run file targeted** (a new run, or bare `/automate` / `--resume` with no matching LOCAL run file) — **ABORT** with the message and create nothing (a park would create a run file and make the next resume ambiguous); **an existing local run file targeted by `--resume <id>`** — park it: `## Status: paused`, `pause_reason: meta_unreachable`, one `## Progress` line naming the reason (a conflict names its path). Never fall through to an empty `resume-glob`: with run history absent every reader answers empty with exit 0, and a second run would start beside a paused one.
- **The trail push (replaces §6's trail PR).** With the mode on, `trail-pr` opens NO PR and creates no trail worktree: it pushes the same evidence-gated candidate list to the metadata branch (`meta-sync.sh push --paths-from`; the list and its exceptions: the `automate-trail.sh` header). One line: `trail-pr: meta-pushed <branch>` | `trail-pr: skipped — meta no_changes` | `trail-pr: meta-push FAILED — <reason>`, `; excluded …` appended. `trail-unstage` and `closeout`'s re-stage are skipped in this mode.
- **What travels.** Run history (the `.dismissed-decisions` ledgers included); the learning stores only with this repo's user-scope consent (`setup-memory.sh consent`) and only on a whole-set `meta-sync.sh push` — `trail-pr` and the lanes' exact lists carry run history only. A lane's metadata never takes the whole-set route, which bypasses the evidence gate: §14's wave end (`lane-convert-ready`) and `lane-remove --abandon` push it.
- **Push failures are loud.** A failed push (or a mode reading `unknown`) makes `trail-pr` append ONE `## Progress` line `meta-push FAILED: <reason>` to the run file, fire the fail-safe notify pair, and write the marker `.supervisor/automate/<run_id>.meta-push-failed`; the next successful push removes it. **PICK report:** the driver's PICK reports `automate-helpers.sh meta-push-failed <runfile>` to the owner and `## Progress` — a report, not a block.
- **SessionStart hint (no network).** When the mode is on and `<gitdir>/meta-base` does not exist, `session-resume.sh` adds one line: run history is on branch `<branch>` and has not been pulled — run `meta-sync.sh pull`.
- **Offline and conflicts stop the run, loudly.** `meta-entry`'s pull needs the network, so an offline machine in branch mode cannot start or resume a run. A conflict on ANY managed path (an agent-memory proposal included, whatever the consent) fails `meta-entry`'s pull and every push until a human makes the two sides agree (`git show origin/<branch>:<path> > <path>`, merging any local edit in by hand) and re-runs; a twin-set conflict alone refuses only the twin set (`twin_refused`).
