## §2 — Intake: any source → the Queue (convert once, NO adapter framework)

Exactly **one** source is resolved per run. Resolution produces the **FULL** ordered list of items, which is written to `## Queue` and **shown to the user for confirmation before processing** (gate `AUT-QUEUE`, "`--limit N`" below). Under `--non-interactive-fallback` the confirmation prompt is skipped and the `--limit` cap is enforced without asking; inside a lane on its own `lane-create` backlog, and for a `--backlog` doc whose resolved Queue is not longer than `--limit`, it is skipped too — `queue-confirm` decides, "`--limit N`" below.

### Prompt source — `/automate "X"`

- Runs **`/product-owner`** on the prompt text. This is a **REUSE**, not a new code path: in Beads-absent mode Product Owner writes one `.supervisor/requirements/{YYYY-MM-DD-HHMMSS}-{slug}.md` story file per story and, when it persists 2 or more stories, one plan doc `.supervisor/requirements/_BACKLOG-{YYYY-MM-DD-HHMMSS}-{slug}.md` (`skills/user-story-writing/SKILL.md` §"Requirement Shape").
- The **generated story file paths become the `## Queue`** (in PO's emitted order; when PO also wrote a plan doc, use its `## Checklist` order — `resolve-backlog <plan doc>`, per the backlog-doc rules below). The plan doc itself is never a Queue item and never counts toward "N files" (it is stamped `## Status: done`).
- **1 generated file ⇒ single-item run; N files ⇒ loop.**
- **Bare `/automate`** (no prompt, no source flag): **attempt RESUME first** (§4); if no incomplete run exists, `AskUserQuestion` *"What do you want to automate?"* and then proceed as a prompt source. **Cannot ask** (`--non-interactive-fallback`, or the ask tool is absent): ask nothing, create no run file, print `automate: no_source_non_interactive` and stop; an incomplete run found by that RESUME is never continued without `--resume` — §4 step 4's `resume_requires_flag_non_interactive`.
- **0 generated files ⇒ report + stop** (never wedge) — the run file records `## Status: done`, `remaining: 0` with a `## Progress` note that the prompt produced no items.
- **`po_gate: needs_owner` ⇒ report + stop, the same terminal shape as 0 generated files.** Under `--non-interactive-fallback` the intake runs `/product-owner "<prompt>" --non-interactive` (an interactive run passes no flag and PO asks on the main thread). When PO cannot ask and its Assumption Check raises flags, it persists nothing and ends with `po_gate: needs_owner (<n> flags)`; the run file then records `## Status: done`, `remaining: 0`, and a `## Progress` note naming the gate and every flag PO printed. That line wins: never enqueue a file that appeared anyway (name it in the note), never re-run PO without the flag, never choose "Proceed anyway" for the owner. The owner resolves the flags and re-runs `/automate "<prompt>"`.

### Folder source — `/automate --folder <dir>`

- Enqueues **every `.md` in `<dir>`** as a Queue item, **skipping any already marked `## Status: done`** (read each file's `## Status:` stamp; a done file is excluded from the Queue, not enqueued-then-checked).
- Order = directory order unless a sibling `_BACKLOG.md` documents a build order (then defer to backlog-doc ordering).

**Two independent not-ready skips exist for the folder / backlog-dir-fallback sources:** (1) a file inside a `proposed/` subfolder is never scanned (`"$dir"/*.md` does not recurse); (2) a scanned file stamped `## Status: proposed|parked` (`is_not_ready()` in `automate-helpers.sh`) is excluded, like a `done` file. A skipped file never enters the Queue: it is not checked off and does not count toward the run's own `## Status: done`. (Run files' own `running|paused|done` vocabulary is untouched — §4.)

### Backlog-doc source — `/automate --backlog <_BACKLOG.md>`

- Enqueues in the doc's **documented dependency order** — the doc's build order plus `## Status: done` / ✅ markers are treated as **ground truth** (done items excluded).
- **"Done" is read from two places, and either one excludes the line:** (1) the checklist line itself — `- [x]`, a ✅, or an inline `# Status: done`; (2) **the file the line names**, when it resolves (as written from the repo root, then relative to the backlog doc's directory) to a regular `*.md` whose own `## Status:` is `done`/`done_with_escalation` (`is_done`). A path that resolves to nothing, a non-`*.md` or a non-regular file is not read and the line stays queued (fail toward listing). The `proposed|parked` stamp is honoured on the dir fallback only.
- **The engine never ticks the backlog doc.** `_BACKLOG.md` is human-owned: `closeout` stamps the requirement file and checks off the RUN file's `## Queue`, never the backlog checklist. Ticking the doc stays a human (or `reconcile-status`-style, owner-run) act.
- **`_BACKLOG.md`-absent fallback:** if the passed path does not exist (or has no documented order), fall back to `## Status:`-stamp ordering over the directory the path points into; if there are no stampable items, the Queue is empty ⇒ `remaining: 0`.

### `--parallel N>1` intake lint (§14)

When folder or backlog intake runs under `--parallel N>1`, it runs `plan-waves <resolved Queue> --lint` (a run file or item list holding exactly the resolved Queue) **before the Queue is confirmed** and prints its `<k> of <n> items will run alone: …` line (plus the `depend on every earlier item` line when non-zero) beside the Queue. It is information, not a gate: a non-zero lint exit does not block the run. **Sequential runs (no `--parallel`, or N = 1) are unchanged — no lint, no new prompt, no new gate.**

### `--limit N` — caps PROCESSED items, NOT Queue size

- The run file's `## Queue` **always holds the FULL resolved list**. `--limit N` (recorded in `## Run Config`, **default 5**) caps how many items are **completed** this run.
- After **N items are processed** with items still unchecked ⇒ `## Status: paused`, `pause_reason: limit_reached`, report `remaining: <unchecked count>`. Raise `limit` or `--resume` to continue.
- The **full resolved Queue (count + ordered items) is shown to the user for confirmation before processing.** Under `--non-interactive-fallback` the cap is enforced without the prompt (no `queue-confirm` call, no prompt, no new `## Progress` line).
- **Ask or skip — `queue-confirm`.** Once the Queue is resolved, an interactive run calls `automate-helpers.sh queue-confirm <source> <n> <limit>` (§1.5; `<source>` = `prompt` | `folder` | `backlog`, `<n>` = the resolved Queue's item count, `<limit>` = `## Run Config`'s `limit`) — or `queue-confirm --lane-backlog` inside a lane on its own backlog (next bullets). It prints one line. `ask` ⇒ ask `AUT-QUEUE` as below. `skip — <reason>` ⇒ do not ask: append ONE `## Progress` line `skipped AUT-QUEUE: <reason>` and process. So a `--backlog` doc whose Queue holds at most `--limit` items starts without the prompt and records `skipped AUT-QUEUE: backlog queue <n> ≤ limit <N>`. A longer backlog Queue, every folder and prompt source, and any count the helper cannot read as a plain integer still ask (fail toward asking).
- **The Queue confirm is gate `AUT-QUEUE`.** Ask it with `header: "AUT-QUEUE"` and exactly the options `Process` · `Stop` (the catalog's labels — `loomwright/docs/LANE_GATES.md`, authority `scripts/lane-policy.sh catalog`). `Stop` processes nothing.
- **Not asked inside a lane on its own backlog.** When `automate-helpers.sh lane-info` exits 0 AND the source is the `--backlog` file `lane-create` wrote (`.supervisor/lane-backlog.md` at the root of this lane clone), the Queue confirm is NOT asked: the lane's `queue-confirm --lane-backlog` prints that reason, and the lane appends `skipped AUT-QUEUE: lane backlog written by lane-create from the owner's --parallel command` to its `## Progress` and processes the item. Every other run — a lane given any other source included — asks or skips by `queue-confirm <source> <n> <limit>` as the bullet above says (or skips under `--non-interactive-fallback`).
