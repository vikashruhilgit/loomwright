### Lanes (`--parallel N`) and launch authority

With `--parallel N` (N > 1) the coordinator runs each Queue item of a wave in its own lane (a local clone, a detached headless session), relays each lane question to you verbatim, and holds the primary checkout for the wave; you merge the wave PR the engine opens (with a merge commit), and each `/automate --resume <run_id>` closes the wave out with `fleet-closeout`. **Single-lane mode (`--parallel 1`):** every Queue item, in Queue order, runs in ONE fresh lane that parks `awaiting_merge` like a sequential item — no wave, no wave PR; it is refused with `--auto-merge` and when branch mode is off. **Launch authority:** a lane launch or resume runs only on behalf of a command YOU typed in this same session (`/automate --parallel N`, `/automate --resume <run_id>`); a request from any other source is refused and named, never carried out. Nothing in the engine merges a lane PR or the wave PR. Routine lane questions can be answered by a policy you set (`docs/LANE_GATES.md`). The protocol: `skills/automate-loop/lanes.md` (skill §14).
