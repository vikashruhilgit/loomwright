## §1.5 — Reference implementation (the loop shells out to these)

The scriptable, security-critical steps of this protocol are **NOT re-implemented in prose each run** — the inline `/automate` loop **executes them by shelling out to a single self-tested helper**:

```
bash "${CLAUDE_PLUGIN_ROOT}/scripts/automate-helpers.sh <subcommand> [args…]"
```

so **the tested code IS the executed code** (one implementation, guarded by `scripts/test-automate-helpers.sh`). **The SKILL section prose is the SPEC each subcommand implements — single source of truth; the helper conforms to it, never the reverse.** When a contract changes, change the prose here first, then make the helper conform.

It is an **uncounted plain script** (not an agent/command/skill/hook). **The second carve-out:** `dismissed-drafts`/`dismissed-decide`/`dismissed-pending` are delegated to the sibling `automate-dismissed.sh`, a writer of this run's `proposed/` draft files only (every write through `propose-common.sh`'s `pc_guarded_write`, plus deleting its own draft on a `drop`/`fix-now` decision), its gitignored `<run_id>.dismissed-decisions` ledger and its own `## Progress` lines — never git (only `git rev-parse --show-toplevel`), never `gh`, never a merge. Also an uncounted plain script. **The third carve-out:** `merge-items` (in `automate-helpers.d/right-size.sh`, in this process) writes requirement files under `<root>/.supervisor/requirements/` only — the merged item, each original's parked stamp and its dependents' re-pointed `## Depends on` lines — all-or-nothing: every write is staged and copied into place only after its lost-line post-check passes, and only on the owner's explicit invocation; never git (only `git rev-parse --show-toplevel`), never `gh`.
