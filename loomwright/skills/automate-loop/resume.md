## §4 — RESUME = glob + reconcile (run-file is BELIEF; git/gh is TRUTH)

> **Run by the driver, not re-implemented:** `automate-next-step.sh <runfile> --resume` runs this section's steps, through `automate-helpers.sh resume-glob <automate_dir> --finalize` and `automate-helpers.sh reconcile-item <pr_url> <belief>` ⇒ `merged` / `awaiting_merge` / `gone` (§1.5; the `git branch --contains <sha>` corroboration below is the loop's). This file is read only when a `next-step --resume` call exits non-zero; report the exit, never redo a step by hand.

**On every start** (including bare `/automate` and any `--resume`):

> **Branch mode (opt-in):** when `setup-memory.sh mode` reads `on`, `automate-helpers.sh meta-entry` runs FIRST — before step 1's glob — and a `failed` verdict aborts or parks `meta_unreachable`; see §13.

**Start order (automate-followups/32):** `init-check` (only when `--parallel` was passed) → `meta-entry` (branch mode) → **`closeout-others`** → `resume-glob --finalize` (step 1) → list / ask (step 4) → `pick-guard` (a NEW run only, before §2's intake). With `--parallel`, `automate-helpers.sh init-check --parallel N [--auto-merge]` runs before any write, and a `refuse: …` line (`auto_merge_with_parallel`, `parallel_out_of_range`, `single_lane_requires_branch_mode`) stops the start with nothing written. When step 4 resolves to a NEW run (sequential, `--parallel N>1` or single-lane `--parallel 1`, §14), `mkdir -p .supervisor/automate` and then `automate-helpers.sh pick-guard .supervisor/automate` run before §2's intake: `ok` proceeds and writes nothing; `refuse: live_lane <lane_run_id> <lane>` or any other `refuse: …` line stops the start — no intake, no run file. A `--resume` is guarded at every PICK instead (§6 step 1). **Cross-run close-out first:** `automate-helpers.sh closeout-others .supervisor/automate [--record <runfile>]` (§1.5) closes out every OTHER run whose `## Current` names a not-`done` item whose PR reads `merged`, BEFORE the PICK-time run lock is taken (inside it, that run's `automate-closeout:<run_id>` lock would be refused). Pass `--record <runfile>` when the target run is known (`--resume <run_id>`); otherwise append each printed `closeout-others: record — <line>` with `progress-append` once the run file is created or selected. Its `leftover` rows go through §6 step 1's close-out leftover gate before the first PICK; a `run_lock_held` row (a LIVE holder) is not a leftover and is retried at the next start. Inside a lane clone it closes nothing (`closeout-others: skipped — lane clone`) and `resume-glob --finalize` finalizes only the lane's own run; the coordinator runs `closeout-others` once in the primary before it launches a wave.

1. **Glob** `.supervisor/automate/*.md` for **run files** — a `*.md` carrying the `# Automate Run:` title line (`is_run_file`, a shape check implemented once as `RUN_TITLE_ERE` in `automate-helpers.sh`, so the §6 result sidecars are never listed) — **NOT** marked `## Status: done`. **Finalize before listing:** `resume-glob --finalize` first runs `finalize-empty` (§1.5) on every candidate: a run whose Queue is fully resolved and whose `## Current` item `closeout` already marked `done` is written `## Status: done` with its `--reason done` trail and is not listed. Every other run is listed untouched; a run whose lock is held is not finalized.
2. The run file is the loop's **belief**. **Repair an unset `## Current` first:** `automate-helpers.sh current-rebuild <runfile>` (§1.5). A `current_rebuilt: <item> pr <url|null> state <s>` line means the item was rebuilt as `status: running` (`pause_reason: null`) from the last `picked` line; it never claims a park and never triggers a close-out: the RESUME stops at step 4's **continue / start new / archive** ask with the rebuilt `## Current` shown, or — under `--non-interactive-fallback` — parks `resume_ambiguous`-style (one `## Progress` line naming the item and its `state`, `current-set <rf> --pause-reason resume_ambiguous`). **Then reconcile each in-flight item against GROUND TRUTH before trusting a checkbox:**
   - **PR merged?** `gh pr view <url> --json state,mergedAt` — a merged PR ⇒ the item is `- [x]` even if the file still shows `- [ ]`/`awaiting_merge`; that merge is the evidence §6 step 1's `closeout` acts on (its `brief-repair` step, then cleanup, stamp, check-off, trail) before the next pick. An `owned drain started` line with no later terminal drain line is first recorded `owned_drain_result: superseded_by_merge` (the driver's `superseded` write), never `null`.
   - **PR open?** ⇒ the item stays `awaiting_merge`; only the merge watcher armed at that park runs `closeout` on a merge, and the next item is picked only on the owner's explicit `--resume` (§8).
   - **PR closed-unmerged or vanished?** ⇒ the item is `gone`: treat it like an `escalated` park (§9) — paused until a human redoes the work or marks the item `skipped`/`abandoned` in `## Queue` (§5). Never silently re-pick or auto-check a `gone` item.
   - **Branch landed?** `git log "origin/<base>" --oneline` / `git branch --contains <sha>`, `<base>` = `resolve-base-branch.sh --repo .`'s one line (the plugin's script; a non-zero exit ⇒ unverified, never `main`) — never assert "merged" from memory.
   - **Requirement stamped?** the requirement file's `## Status: done` stamp.
   - **No PR yet (`pr: null`, `pause_reason: rate_limit`)?** nothing to reconcile: the item stays as parked, and resuming re-picks it and retries RUN.
   - **A DETACHED drain died for this item's PR (`drain_died`)?** A `.supervisor/review-dispatch/*.died` marker whose `pr_url` equals `## Current`'s `pr:` (only the detached `dispatch-pr-review.sh` writes one — never this engine's owned drain) ⇒ `owned_drain_result: died`, `## Status: paused` / `pause_reason: drain_died` — **explicitly NEVER `awaiting_merge`**: no verdict exists to park on. Checked BEFORE the merged/open/closed reconcile.
   - Reconcile each item, then rewrite `## Queue` checkboxes + `## Current` atomically (§3) so belief matches truth.
3. **RECONCILE also restores a crash-stranded config backup** (§7) — a `config_backup` sidecar still on disk means the prior tick died with `.auto_review` suppressed: restore it (or delete `config.json` if originally absent) before proceeding.
4. **If an incomplete run exists**, `AskUserQuestion`: **continue / start new / archive** — gate `AUT-RESUME`: ask it with `header: "AUT-RESUME"` and exactly the options `Continue` · `Start new` · `Archive` (the catalog's labels, `loomwright/docs/LANE_GATES.md`; a `(Recommended)` marker is allowed). Any other header or wording is not a catalog gate, so no policy ever answers it.
   - **Cannot ask** (`--non-interactive-fallback`, or the ask tool is absent) with exactly ONE incomplete run and no `--resume`: **fail closed — no option is auto-picked.** Ask nothing, PICK no item, resolve no source, create no run file, and write nothing to the incomplete run; print `automate: resume_requires_flag_non_interactive <run_id>` with the hint to re-run with `--resume [<run_id>]` (or interactively, to start new / archive), plus — verbatim — every `closeout-others` `record` line and `leftover` row from this start (no run file carries them on this path), and stop. **Bare and source-bearing starts take the same rule:** a `"<prompt>"` / `--folder` / `--backlog` source is NOT an implied `start new` while an incomplete run exists.
   - `--resume [<run_id>]` targets one explicitly; with the id omitted it targets the **most-recent incomplete** run.
   - Under **`--non-interactive-fallback`**, an **ambiguous** resume (more than one incomplete run and no explicit id) **fails closed**: `pause_reason: resume_ambiguous` in `## Current`, with the same verbatim printout as the stop above.
5. **Re-pass non-persisted passthrough flags.** `## Run Config` does NOT store `--notify` / `--non-interactive-fallback` / `--cheap` (§11), nor `--inline-phases` — re-pass them on **every** `/automate --resume` and `/loop` tick; omitting `--cheap` reverts the rest of the queue to the full-cost profile.
6. **Resuming a `rate_limit` park** goes through this same flow: its `pr: null` has nothing to reconcile, and `continue` re-enters §6 step 1 RECONCILE and falls through to RUN on the SAME item.
7. **RECONCILE also runs reconcile-status** — after step 4 resolved to continue, **BEFORE PICK**: `automate-helpers.sh reconcile-status .supervisor/requirements` (no `--apply` — promoting a requirement's `## Status:` is a human act), then one `automate-helpers.sh progress-append <runfile> "reconcile-status: would stamp <file> (<status>)"` line per `plan` row; `info` rows are never appended. Never on step 4's can't-ask stops.
8. **Pending dismissed-finding decisions.** `## Current`'s `pending_decisions: <n>` is BELIEF; the truth is `automate-helpers.sh dismissed-pending <runfile>`. RESUME never parks or blocks on it: an interactive resume asks the undecided set at §6 step 1 PICK; a `--non-interactive-fallback` resume asks nothing. A `fix_now_reentered: true` line means that item's one fix-now re-pass already ran.

## §5 — Skipped / abandoned items

An item the human (or the loop) abandons is written in `## Queue` as:

```md
- [x] <path>  # skipped: <reason>
- [x] <path>  # abandoned: <reason>
```

- **Checked-off ⇒ never re-picked** ("next unchecked item" skips it). The reason is ALSO logged in `## Progress`.
- **`remaining` counts only `- [ ]` items**, so a skipped/abandoned item does **not** block `## Status: done`.
- This is the **documented way to unblock an `escalated`-parked run without merging** (§9): mark the parked item `skipped`/`abandoned`, then `--resume`.
- **A skip/abandon check-off runs `trail-pr`** (`--reason skipped`/`--reason abandoned`) — trigger (c) of "Trail PR after merge and at run end". The item's requirement rides only when it carries no done stamp or its PR merged, so an abandoned escalated item never lands a done claim.
