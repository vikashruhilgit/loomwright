## §6 — The per-item loop

`scripts/automate-next-step.sh` runs every step below; this file is read only when a driver call exits non-zero or an instruction does not say what to do. Report a non-zero exit — never redo a driver step by hand. Each helper's contract is its §1.5 row ([helpers.md](helpers.md)) and its script header.

For each `- [ ]` Queue item (top-down, single-open-PR invariant permitting — §8):

1. **RECONCILE** — re-check ground truth for any in-flight item before picking (§4); never pick a new item while one has an open unmerged PR (§8). An item parked `awaiting_merge` (or `escalated`) that `reconcile-item` now reads `merged` is closed out with `automate-helpers.sh closeout <runfile> <item> <pr_url> --session-id <this loop's session id>` BEFORE any PICK (`--session-id` re-enters this PICK's run lock; closeout's step 2 is `brief-repair`; advisory — its result never changes the reconcile verdict). A live `<run_id>.merge-watch` marker for the in-flight PR gets one `progress-append` line, never a second watcher. A parked `## Current` item checked off `# skipped:`/`# abandoned:` by a human (§5) runs `automate-helpers.sh trail-pr <runfile> --reason skipped|abandoned`, its line appended, BEFORE PICK. An `escalated` item with `escalation_cause: validation_unrun` and an `OPEN` PR is re-checked first ("Re-check at RECONCILE (step 1)" below). The PICK itself is `current-set <runfile> --item <path> --status running --pr null --branch null --pause-reason null` FIRST, then the `<ts> picked <item>` line (the reverse order trips `progress-append`'s `current_not_set` guard).

   **Close-out leftover gate (driver step `leftover` — after RECONCILE's `closeout`, before the trail gate and the PICK's `current-set`; the `leftover` rows §4's `closeout-others` printed at start go through it before the first PICK).** Each `closeout` output is classified ONCE, on its own: `automate-helpers.sh closeout-classify --run <run_id> --item <item> --pr <pr_url> --record <runfile>`. Anything but exactly `complete` is a leftover, and the run never proceeds silently — except, at start only, a `closeout-others` answer made only of `run_lock_held` rows (a LIVE holder), which is retried at the next start. **Interactive** (gate `AUT-LEFTOVER`): ONE owner question batching ≤4 leftovers (more ⇒ further questions of ≤4), options **Clean up now** / **Keep and continue** / **Stop**. *Clean up now* re-runs `closeout <that run's file> <item> <pr>` — idempotent, with its own safety checks (`worktree-salvage.sh` runs before any `git worktree remove`, removal only at the PR's merged head, no `--force`, no reset, no stash) — then re-classifies ONCE; a leftover that survives is asked **Keep and continue** / **Stop** only. *Keep and continue* ⇒ `progress-append "closeout leftover kept: <run_id> <step> <detail>"`. *Stop*, and every leftover under `--non-interactive-fallback`, parks: `## Status: paused`, `current-set <runfile> --pause-reason closeout_leftover` (run-level form), one `closeout leftover: <run_id> <step> <detail>` line per leftover, then `run-lock.sh release`; no `trail-pr` at this park.

   **PICK-time trail gate (driver step `trail-gate` — after RECONCILE, its `closeout` and any skip/abandon trail; BEFORE the trail un-stage).** `automate-helpers.sh trail-gate <runfile>`, its line appended. `PARK — …` (this run's own `chore/<run_id>-trail-<n>` PR open, or its state unreadable — fail CLOSED) parks `pause_reason: trail_pr_open` with `## Current`'s other lines unchanged, then `run-lock.sh release`; no `trail-pr` at this park. The owner merges or closes that PR, then `--resume`. `clear — …` proceeds (the gate already synced the primary over a merged trail); a `sync skipped — <reason>` answer is reported and never parks.

   **PICK-time trail un-stage (driver step `trail-unstage` — after the trail gate, BEFORE RUN).** `automate-helpers.sh trail-unstage <runfile>`, its line appended: drops the trail paths `trail-pr` left staged in the primary index, so the next item's commit never carries them. Fail-SAFE, never gates the pick.

   **PICK-time run-lock acquire (driver step `pick` — BEFORE anything else at PICK, RECONCILE included).** `scripts/run-lock.sh acquire --owner "automate:<run_id>" --session-id "<session_id>"`. A lock held by another run/process parks `pause_reason: run_lock_held` (one `## Progress` line naming the `run_lock_held owner=<label> pid=<pid> age=<s>` output) and stops without touching `## Queue`/`## Current`/`.auto_review`; a `run_lock_degraded` stderr line is noted once and is not a park. The lock is held until CHECK OFF (step 6) or the park that stops this item; `--force-unlock` is human-only (§11). **Lane guard** (driver step `lane-guard`), right after the acquire: `automate-helpers.sh pick-guard .supervisor/automate` — `ok` proceeds with no line; `refuse: live_lane <lane_run_id> <lane>` or any other `refuse: …` line (fail CLOSED) parks: `## Status: paused`, `current-set <runfile> --pause-reason live_lane` (run-level form), the refusal quoted in one line, then `run-lock.sh release --owner "automate:<run_id>"`; no `trail-pr` at this park. The owner `--resume`s once the wave is over (`lane-status`).

   **Phase guard (driver step `phase-guard` — fresh phases only, after the lane guard; skipped under `--inline-phases`).** `automate-helpers.sh phase-check` (read-only, fail CLOSED): `phase-check: ok` proceeds; `phase-check: unavailable — <reason>`, or a `--session-id` outside `[A-Za-z0-9_-]+`, parks `phase_relay_unavailable` (run-level form) with the lock released — nothing picked, nothing spawned. The owner fixes the cause and `--resume`s, or re-runs with `--inline-phases`.

   **PICK-time token-ceiling check (driver step `ceiling` — only with `--max-tokens N`; after the guards, BEFORE RECONCILE).** `automate-helpers.sh ceiling-check <runfile> <N>`: `PARK: token_ceiling …` or `PARK: ledger_unreadable` parks `pause_reason: token_ceiling` with the lock released; no `trail-pr` at this park. `OK …` proceeds.

   **PICK-time pending-decisions ask (automate-followups/12 — driver step `pending`; interactive runs only, after the lock and the ceiling check, BEFORE RECONCILE's `closeout`).** `automate-helpers.sh dismissed-pending <runfile>` non-zero or `unknown` ⇒ ask over this run's undecided drafts (≤4 per call, one per draft) with **Follow-up (keep draft)** / **Drop** ONLY; a summary draft (`…--dismissed-summary*.md`) is gate `AUT-SUMMARY` (`Keep summary` ⇒ `follow-up` · `Drop summary` ⇒ `drop`), asked in a call of its own. fix-now is offered only at the park ("Dismissed-findings decision step (before the park)", behind `park-ask-gate`), never at PICK. Each answer ⇒ `automate-helpers.sh dismissed-decide <runfile> <draft_path> follow-up|drop`. Under `--non-interactive-fallback` it never runs; the count stays in `## Current`.
2. **RUN — run next-step** — call `automate-next-step.sh <runfile> --start run --mode safe|auto-merge --session-id <this loop's session id>`, plus `--non-interactive` under `--non-interactive-fallback`, and `--trust-unprotected`, `--notify`, `--cheap`, `--max-tokens N` when they were passed to `/automate` (they persist for the item's pass). The `run` step suppresses `.auto_review` (`config-suppress`, §7; a malformed config exits 2 `config_malformed`) and prints `{"do":"spawn","what":"/autonomous run",…}`: run its `invocation`, then call again with the RUN report — also when `/autonomous` failed: the verbatim `SUPERVISOR_RESULT` (`supervisor_result` or `supervisor_result_file`), `.supervisor/state.md`'s `session_id` and a one-line `run_note`; with no PR, `status_reason` (its bare `AUTONOMOUS_RUN` token) and `no_pr_why` instead (after a Supervisor checkpoint, its `SUPERVISOR_RESULT` too: its `task_id` names the resume). The driver restores `.auto_review`, writes the run lines — the pinned no-PR line is `<ts> ran /autonomous — no PR: <status_reason> (<one-line why>)`, whose bare token the `/lanes` timeline reads — and the sidecar, then runs the rate-limit read ("Rate-limit park (end of RUN, before DRAIN)"). A report whose SUPERVISOR_RESULT carries a nested object off its key set (a `ground_truth` without `checked`, or with `pass_rate`) exits 2, nothing written: re-emit the block in its schema shape (`ground_truth` = the runner's `GROUND_TRUTH_NESTED:` line verbatim) and report again. Report shapes: `docs/result-schemas/automate-run.md` §"next-step instruction".
   **Fresh phases (the default; `--inline-phases` keeps the inline form above).** The `picked` line leads to the `plan` step: a fresh launch pad phase (`/loomwright:launch-pad goal: <item>`) whose report (`launch_pad_result_file` + `session_id`, or `status_reason: phase_died` + `no_pr_why`) goes to `plan-result`, which applies `/autonomous` PLAN's result handling; a saved brief is recorded as the pinned line `<ts> launch-pad saved <brief>`, byte for byte — Plan's end and Build's start for `read-token-ledger.sh` and the `/lanes` step timeline, which both read it through the one matcher `scripts/progress-line-match.sh` (never a reader's own pattern; `--inline-phases` writes no such line) — and leads to `run` and the Supervisor phase (`/loomwright:supervisor job: <brief>`), whose RUN report adds the `session_id` `phase-wait` printed. A re-picked item whose last RUN checkpointed (the no-PR `checkpoint` line, its brief still in `.supervisor/jobs/in-progress/`) skips `plan`: `run` resumes it with `/loomwright:supervisor --continue task: <id>` (under `--inline-phases`, run inline in place of `/autonomous`; `--notify` is not forwarded). A fresh spawn is run as the Coordinator loop's step 2 in `SKILL.md` says (never inline: `launch` → `phase-wait` → `--result`). Pass the `/automate` command the owner typed as `--owner-command` — `phase-launch` refuses a line without it (`BLOCKED`, exit 3) — never an invented one.
3. **DRAIN — run next-step** — after the RUN report the `drain` step prints `{"do":"spawn","what":"owned drain",…}`: run its `invocation` (`/review-pr <pr> --until-mergeable --no-auto-postmortem`) — the pass's one owned drain, at most one owner-requested fix-now re-drain per item, strictly sequential (never concurrent); another owned-drain request in the same pass exits 2 `drain_already_owned` (§7) — then call again with the DRAIN report: the verbatim terminal `REVIEW_HEAL_RESULT` (`review_heal_result` or `review_heal_result_file`), or `{"no_terminal_block":true}`, plus its `drain round N: …` lines as `progress_notes` and the terminal line's parenthetical as `drain_note`. The driver records the drain and goes on to GATE; a `no_terminal_block` report over a PR that reads `merged` is `superseded_by_merge` (`closeout`, then the `awaiting_go` park). Fresh phases: the owned drain is its own session (`phase: "drain"`), run through the same `launch` → `phase-wait` loop, its report adding `session_id`; the fix-now re-drain stays the coordinator's own spawn.
4. **GATE — run next-step** — the driver's steps `gate` → `validation` → `gate-eval` (`--auto-merge`) or the safe-mode park → `dismissed` / `decide` / `fix-now` → `park`. The DRAIN report goes straight on to GATE; a bare `automate-next-step.sh <runfile> --result '<the drain report as JSON>' --mode safe|auto-merge --session-id <this loop's session id>` (plus `--non-interactive` / `--trust-unprotected` as passed) starts the tail on its own, and those flags persist for the item's tail. Each call prints exactly ONE JSON instruction: `spawn` — run the named work, then call again with `--result <its report>`; `ask` — ask its `questions` with their `header` and `options` through the ask tool, then `--result '{"answers":[…],"note":"…"}'` (no ask tool ⇒ `--result '{"cant_ask":true}'`, the named `cant_ask` outcome); `park` — stop; `done` — `status: done` ends the run, `status: running` goes to the next PICK. A call with no `--result` re-prints the pending instruction and writes nothing to the run file (a new `--session-id` / `--owner-command` it gives is persisted for the item's tail — `docs/result-schemas/automate-run.md` §"next-step instruction"). Between calls the loop writes nothing to the run file; a non-zero driver exit is reported, never worked around. The driver itself merges nothing — `--auto-merge`'s merge is `gate-eval`'s (§10). Rules: §9, §10 and "Dismissed-findings decision step (before the park)".
   **Re-check at RECONCILE (step 1).** On `--resume`, a `## Current` item `status: escalated` with `escalation_cause: validation_unrun` whose PR reads `OPEN` re-runs the read-only `validation-gate` and `progress-append`s its line. `ok` / `waived` ⇒ the READY park this GATE would have written, through the item form of `current-set`: sequential or a single lane, `--status awaiting_merge --pr <pr_url> --branch <branch> --pause-reason awaiting_merge` with no second watcher; an N > 1 lane, `--status ready_for_release --pause-reason ready_for_release`, then §14's `lane-park-notify` and `lane-readiness`. RECONCILE runs no `gate-eval`, so an `--auto-merge` run gets the same park and a human merges. Anything else ⇒ nothing written, the item stays `escalated`; the re-check never asks `AUT-WAIVE`. The owner clears the park by pasting the step's fenced output into the PR body and `--resume`, or as §9 says.

5. **SYNC — run next-step.** After `gate-eval` printed `MERGE`, the `sync` step runs `closeout <runfile> <item> <pr_url> --no-trail --session-id <this loop's session id>` (closeout's step 2 IS `brief-repair`) and classifies its output through the step-1 Close-out leftover gate (`AUT-LEFTOVER` interactively, the `closeout_leftover` park under `--non-interactive-fallback`).
6. **CHECK OFF + PROGRESS — run next-step, except a skip/abandon.** After a gate-merged item the `checkoff` step appends the `## Progress` line and `terminate` takes "Termination (two exits)" below. A `# skipped:`/`# abandoned:` check-off is still the loop's own: one atomic write (`queue-checkoff` with the reason), report `remaining: N`, then `automate-helpers.sh trail-pr <runfile> --reason skipped|abandoned` (its line appended), then `run-lock.sh release --owner "automate:<run_id>"` as the step's LAST action. Every other stop of this item (the driver's parks, the `limit_reached` exit; `drain_died` in prose) releases the lock too.

### Termination (two exits)

- **Queue fully resolved** (no `- [ ]` left) ⇒ `## Status: done`, `remaining: 0`, the `/loop` driver stops.
- **`limit` items processed** with the queue NOT empty ⇒ `## Status: paused`, `pause_reason: limit_reached`, `remaining: <unchecked count>`, loop stops.

Both exits are written by the driver's `terminate` step (§6 step 6).

On the **`## Status: done`** exit ONLY, the loop runs `trail-pr --reason done`, then appends ONE `<ts> sweep (dry run): <summary line>` line (the last line of `automate-helpers.sh sweep` — a DRY run, never `--apply` unattended; none ⇒ `sweep: summary — skipped: no output`), and only then `run-lock.sh release`; the `limit_reached` exit is a park and releases the lock without a trail.

Every park (`awaiting_merge`, `ready_for_release`, `escalated`, `rate_limit`, `drain_died`, `trail_pr_open`, …) also stops the loop with its `pause_reason`. All `/autonomous` correctness gates still bubble up (NO-GO, Plan Review FAIL×3, adjudication, rubric gate); `--notify`, `--non-interactive-fallback` and `--cheap` pass through to the inner `/autonomous` (§11).

### Brief-repair at RECONCILE and SYNC (merge-evidenced lifecycle repair)

`automate-helpers.sh brief-repair <item> <pr_url>` (§1.5) runs as step 2 of `closeout` at both seams — RECONCILE's `closeout` and SYNC's `closeout … --no-trail` — and its one output line lands in `## Progress` verbatim. It repairs only on a forge `MERGED` read, through `reconcile-jobs.sh --repair --evidence <item>=<pr_url>` (the one mover; an ambiguous match repairs nothing).

- **Advisory / fail-SAFE — NEVER gating.** `brief-repair` ALWAYS exits 0 and the loop ignores its exit status: a failure never changes `owned_drain_result`, the GATE decision, `## Status`, `## Current` or any inner `/autonomous` gate. It never touches the run file and never merges.
- **Idempotent.** A second call for the same item prints `skipped — no in-progress brief matches …`.

### Trail PR after merge and at run end

> **Branch mode (opt-in):** with the mode on, `trail-pr` pushes to the metadata branch through `meta-sync.sh` instead of opening a PR — same triggers, same evidence gate, loud on failure; see §13.

`automate-helpers.sh trail-pr <runfile> --reason <closeout|done|skipped|abandoned>` commits this run's tracked `.supervisor` trail as ONE PR (`chore/<run_id>-trail-<n>`, re-used while open; explicit paths, never `git add -A`). Its paths, branch reuse, retractions and output are `scripts/automate-trail.d/trail-pr.sh`'s (§1.5 `trail-pr`).

- **When — this is the ONE authoritative trigger list (and the ONE park-path list).** Exactly three triggers, each after the evidence that the work it records is final: **(a)** inside `closeout`, after its evidence gate read the PR `MERGED` and after its sync, stamp and check-off (`--reason closeout`) — unless its caller passed `--no-trail` (§6 step 5 SYNC, §14's merged-lane re-run); **(b)** at the `## Status: done` termination, after that state is written and BEFORE `run-lock.sh release` (`--reason done`); **(c)** when an item is checked off `# skipped:`/`# abandoned:` — by the loop at §6 step 6, or found so marked by a human at RECONCILE (before PICK) — (`--reason skipped` / `--reason abandoned`). At (b) and (c) its line is appended with `progress-append`. **No park calls it:** `awaiting_merge`, `escalated`, `rate_limit`, `drain_died`, `token_ceiling`, `trail_pr_open`, `ready_for_release`, `live_lane`, `phase_relay_unavailable`, `closeout_leftover`, `limit_reached` write the park state and release the run-lock directly (`run_lock_held`, `resume_ambiguous` and `meta_unreachable` never held the lock) — a parked item's trail lands with its `closeout`, a skip/abandon or the run end. A gate-merged `--auto-merge` item is closed out by `closeout … --no-trail`, so its trail rides the next `closeout`, skip/abandon check-off or run end.
- **Lane calls (§14) — not a fourth trigger, and the one exception to "no park":** inside a lane, `lane-convert-ready` runs `trail-pr <the lane's run file> --reason wave-end` at the wave end and `lane-remove --abandon` runs it with `--reason abandoned` on a `gone` lane, both through the same evidence gate.
- **Evidence-gated stamps (defense in depth — in the script, not only this prose).** A done claim rides only for merged work: a requirement whose `is_done` heading names a `- **PR:**` (its first `https?://…/pull/<n>` token, stopping at whitespace and `[]()<>`) that does not read `merged` via `reconcile-item`, or names none, is EXCLUDED and named (`; excluded <path> — pr not merged`). The one exemption is the exact owner-abandon heading `## Status: done_with_escalation — ABANDONED (- [x] <path>  # abandoned: <reason>)`; a heading that merely contains "ABANDONED" is a done claim like any other. `done/` briefs follow the same rule on their `## Outcome` / `### Outcome` section (never `## Outcomes Rubric`). On a reused trail branch a failing done claim is put back to `origin/<default>`'s blob and named `; retracted <path>`, and the checkout contract never stages a gate-excluded path. A transient `gh pr view` failure excludes (on a reused branch, retracts) a legitimate stamp until the next `trail-pr` — a missed done stamp is recoverable (`reconcile-status` finds merged work), a false one is not.
- **Checkout contract:** after a push `trail-pr` stages the trail-branch tip blobs in the primary INDEX (never the working copies), so the owner's plain `git pull` after merging the trail PR fast-forwards; `trail-unstage` drops them at PICK and `closeout`'s sync re-stages the recorded ones that landed (`<run_id>.trail-staged`). No `git reset`, no stash; the trail branch is never rebased.
- **Output:** exactly ONE line — `trail-pr: opened <url>` / `trail-pr: pushed <url>` / `trail-pr: skipped — <reason>` — exclusions and retractions appended to it.
- **Advisory / fail-SAFE — NEVER gating.** Always exit 0; the loop ignores its exit status. A trail failure never blocks a close-out, a check-off or the run end, and never changes a gate decision, `## Status` or `## Current`. `trail-pr` never calls `run-lock.sh`, never merges (the sole merge executor stays `gate-eval`, §11), and never force-pushes.

### Post-merge close-out (`closeout` + the merge watcher)

When the owner merges a parked item's PR, ONE script closes it out: `automate-helpers.sh closeout <runfile> <item> <pr_url> [--session-id <sid>] [--no-trail]` (§1.5; `scripts/automate-trail.d/closeout.sh`). Its callers: `--resume` RECONCILE (§6 step 1, with `--session-id`), the merge watcher (without it), `--auto-merge` SYNC (§6 step 5, `--no-trail --session-id`), a merged lane's `lane-convert-ready` re-run (§14, `--no-trail`), and `closeout-others` at start for another run (§4). It never merges anything and never picks the next Queue item — the owner's explicit go still starts it (`paused` / `awaiting_go`, §3); it does not tick `_BACKLOG.md` (§2).

- **Guards:** a missing run file or an unavailable `gh` is one `closeout: skipped — …` line; then `reconcile-item <pr_url>` must say `merged`, else ONE `closeout: skipped — pr not merged (<state>)` line and nothing else runs.
- **Steps (execution order; the labels are the script's):** brief repair → run-lock acquire → **3a** salvage and remove a linked worktree only at the PR's `headRefOid` and only when clean → **4 sync** the primary to `main` (`git pull --ff-only`; a refusal is a `skipped` line, never a reset) → **3b** delete the local head branch only when its tip == the PR's `headRefOid` → **5** stamp the requirement (the ONLY engine writer of its done stamp) → check off with `queue-checkoff <runfile> <item>` (NO reason argument) → **7b** reconcile `## Current` through `current-set` only when it names this item and this PR → `progress-append` one line per step that changed something (a `synced` line alone never appends) → **trail** via `automate-helpers.sh trail-pr <runfile> --reason closeout` (`--no-trail` skips this step alone) → release.
- **Output:** one `closeout: removed|synced|stamped|checked|reconciled|skipped — <detail>` line per step, plus the passed-through `brief-repair:` and `trail-pr:` lines. Idempotent. **Always exit 0.**
- **Concurrency:** steps 3–7 run under `run-lock.sh acquire --owner automate-closeout:<run_id>` (plus `--session-id <sid>` when given, which RE-ENTERS the PICK's `automate:<run_id>` lock). Release is by `--owner` only, never `--session-id`. A held, non-re-enterable lock ⇒ `closeout: skipped — run lock held by <owner>`.
- **The merge watcher — `scripts/automate-merge-watch.sh <runfile> <item> <pr_url>`.** Armed by the driver's `park` step at §9's `awaiting_merge` and `escalated` parks: detached, pure bash, no Claude session. It polls the PR; `MERGED` ⇒ `closeout` (a transient skip is retried), `CLOSED` ⇒ one `gone` line + notify, the lifetime cap ⇒ one line. At an `escalated` park whose `escalation_cause` is `check_pending|check_red_unrelated` it also reports `merge-watch: now mergeable: …` or `merge-watch: still failing: … — rerun: gh run rerun <run_id> --failed` once per line; it never reruns, merges, pushes or approves. One watcher per run (marker `.supervisor/automate/<run_id>.merge-watch`); count watchers by the marker pid, never `pgrep -f`. Contract: the script's header.
- **SessionStart surfacing (`session-resume.sh`):** on every SessionStart, one `automate: merge watcher live pid=<p> PR <url> (run <run_id>)` line per live watcher; on `resume`/`clear`/`compact` only, one `automate: <run_id> item <item> PR <url> merged but not closed out — /automate --resume closes it out` line per run whose `## Current` PR reads MERGED while its item is not `done` (time-bounded `gh` reads; otherwise `… merge state unverified`, never a guess).

### Rate-limit park (end of RUN, before DRAIN)

Run by `automate-next-step.sh` step `rate-limit` (step 2): after `run-result` restored `.auto_review`, a main-scope `agent_lifecycle` `failed` row in the loop's own session log dated after this item's `picked` line — `reason: rate_limit`, or `reason: unknown` with a `429` hint (recorded as `reason_hint`, never promoted into `reason`) — parks the item `rate_limit` (item and `pause_reason`), releases the run lock and stops before DRAIN, with no `trail-pr`; RUN is never retried in the same tick. Every other classified reason is unchanged. The pinned lines are `docs/result-schemas/automate-run.md`'s.

### Dismissed-findings decision step (before the park)

Run by `automate-next-step.sh` steps `dismissed` → `decide` → `park` / `fix-now` (step 4; the instruction schema is `docs/result-schemas/automate-run.md` §"next-step instruction", the drafting threshold is `scripts/automate-dismissed.sh`'s header). A sequential interactive READY park is written, watched and released FIRST and asked after `park-ask-gate --wait 75`; an `escalated` park, every park under `--non-interactive-fallback` and a lane's READY park decide first. A fix-now answer runs ONE owner-requested fix pass and full re-drain — at most one owner-requested fix-now re-drain per item, strictly sequential (never concurrent).

**A clean review is not a finding.** A bot review that raises no issue is validated `clean` (`findings_clean`), never `dismissed`, so it is never drafted or asked; `dismissed-drafts` also skips a whole-text no-finding verdict.

**Honest limits.** `drain-rounds.sh init` resets the per-PR round ledger, so the real bound on one item is 2 × `--max-rounds` drain rounds. `learning-emit` writes at most one complete line per run/item/PR/source, so the engine-native learning line reflects the FIRST drain only. The re-dismissed fix-now check is drain-origin ONLY: `<run_id>.supervisor-result.md` is written once per item, so a Phase 4.5-origin fix-now name stays suppressed.

## §7 — Single drain (no double-dispatch) + the config-toggle contract

`/autonomous` already triggers Supervisor's **default detached until-mergeable drain** (Phase 4.5 step 5.5 **and** the `PostToolUse[Bash]` `gh pr create` hook backstop); if the engine *also* drained, two until-mergeable loops would race the branch. The engine therefore **suppresses the default dispatch and owns exactly ONE inline drain per pass** — at most one owner-requested fix-now re-drain per item, strictly sequential (never concurrent) (§6 "Dismissed-findings decision step (before the park)").

**Run by `automate-next-step.sh`** (automate-speed/07). The suppress window is the driver's `run` → `run-result` steps: `config-suppress` before the `/autonomous` (fresh phases: the Supervisor phase) spawn, `config-restore` when the RUN report arrives and before the owned-drain spawn — never at DRAIN; a malformed `config.json` is refused (`config_malformed`, nothing written), and a backup still present at `--start run` is crash-stranded (`config_backup_stranded`), restored by RECONCILE (§4). The owned drain is the `drain` step's one spawn per pass — at most one owner-requested fix-now re-drain per item, strictly sequential (never concurrent); a second request exits 2 `drain_already_owned`. Verifiable via `## Current`'s `owned_drain_started` / `owned_drain_result` / `suppressed_default_dispatch: true` plus the absence of any detached `dispatch-pr-review.sh` artifact for the PR.

## §8 — Single-open-PR invariant (BOTH modes)

**While ANY item has an OPEN unmerged PR — status `awaiting_merge` OR `escalated` — or this run's own trail PR is open, the loop MUST NOT PICK a new item.** At most ONE open PR exists at any time, the engine's trail PR included.

- **Lanes (`--parallel N`, §14 — a single lane, `--parallel 1`, holds exactly one item): one open PR per lane.** Each lane is its own clone with its own run file, so the invariant holds per lane; the coordinator itself opens no item PR.
- **`awaiting_merge`:** the run is stopped (`paused` also stops a `/loop` driver, §12); only the **merge watcher** armed at the park (§6 "Post-merge close-out") re-checks the PR, running `closeout` on a merge, as does an `/automate --resume` RECONCILE. Either way **the owner's explicit go is still required before the next item is picked**; it then branches off **fresh `main`**. (`--auto-merge` skips this park by merging at the gate — §10 — but still parks on `escalated`.)
- **Other runs' merged items (`closeout-others`, §4 start order).** At start — before any PICK and before the run lock is taken — every OTHER run whose `## Current` names a not-`done` item whose PR reads `merged` is closed out; anything it could not safely finish goes through §6 step 1's close-out leftover gate. It is not repeated per PICK: the PICK's `automate:<run_id>` lock would refuse another run's close-out.
- **`escalated`:** the run stays **paused** (`## Status: paused`, `pause_reason: escalated`) until a human resolves it (§9); stacking a second PR would violate this invariant.
- **This run's trail PR (`trail_pr_open`).** A trail PR merged while the next item's PR is open moves the base under it, and with `strict` required status checks the item PR then reads `mergeStateStatus: BEHIND`. So the PICK-time trail gate (§6 step 1) parks `pause_reason: trail_pr_open` while a `chore/<run_id>-trail-<n>` PR is open — or its state cannot be read (fail CLOSED) — and syncs the primary over a merged one before the next branch is cut; the owner's go then means "merge the trail PR, then `--resume`". Rejected: **(a) Refresh a READY-but-BEHIND PR** by merging `origin/main` (not the drain's job; it would weaken `gate-eval`'s condition 2); (b)'s second form, holding the trail until run end; **(c) Exempt `.supervisor/**`-only changes** from the up-to-date requirement — not possible (`strict` has no path filter).
  - **Honest limits.** The gate covers this run's trail PR only: another merge to the base while an item's PR is open (a hand-merged PR, another run's trail PR) still leaves it `BEHIND` under `strict` — the owner updates the branch (GitHub's "Update branch" button, or a hand merge of the base), and under `--auto-merge` the gate's `gh pr merge --squash` fails and parks `merge_command_failed`. Under `--auto-merge` a skip/abandon check-off opens a trail PR mid-run, so an unattended run parks `trail_pr_open` at the next PICK until the owner merges it.
