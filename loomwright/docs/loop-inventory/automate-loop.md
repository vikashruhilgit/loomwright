# Loop inventory — automate-loop

This file lists every branch and rule the `/automate` engine prose states — the `skills/automate-loop/` skill (its index and every split file) plus the `commands/automate.md` command body — one row per `###`/`####` heading outside fenced code blocks and split-index blocks, and one row per list item (or rule-bearing table row or paragraph) that states a condition→action branch or a rule. It restates the prose on purpose, so later items can move control flow into scripts and stories out without an edge case silently disappearing. `loomwright/scripts/test-loop-inventory.sh` keeps it in sync with the prose: heading coverage, live anchors, real script subcommands, existing test files, unique ids, and the gap list and counts below, which are computed from the table, never hand-maintained. A `home` follows the grammar in `test-loop-inventory.sh`'s header (automate-speed/08 re-homed every row, owner decision D1): `global` rows sit in the default read set (`SKILL.md`, `invariants.md`, the command body) and are anchor-checked like `prose`; `step-scoped` rows sit in a split file that `commands/automate.md` Step 0 reads only when its trigger fires; a `script:<file> <sub>` row's rule is executed by that script's `case` arm (`automate-next-step.sh` for the per-item loop and resume), so its prose, where it remains, is a reference read only when that step fails; a `rationale:` row is a story kept under that heading of `docs/rationale/automate-loop.md` (automate-speed/16 moves every story there; until each split file's diet lands, some still point at a heading of a split file outside the default read set). Only rows of kind `judgment` keep home `prose` — `judgment` is a kind, not a home, so this is how the requirement's "homed `global` or `judgment`" is read.
