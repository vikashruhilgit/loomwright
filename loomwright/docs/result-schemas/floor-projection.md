## FLOOR_PROJECTION

The on-disk shape of `.supervisor/floor/floor.json`, the single derived artefact emitted by `loomwright/scripts/build-floor.sh`. Unlike the RESULT blocks above this is **not an agent-emitted result block** — it is a read-only projection of the scattered `.supervisor/` / `.agent/` surfaces, plus the installed plugin's own agent roster, into one contract, so a downstream view consumes this file instead of re-implementing every parser. The projection currently carries **fourteen** surfaces — counting one key under `surfaces`, which is not the same as the number of directories read (the four `jobs/` lifecycle folders are four surfaces, while `logs/*.jsonl` yields two: `logs` counts the files, `sessions` reads their contents). No hook validates it (the producer is a standalone script, the same precedent as `EVAL_RESULT` / `GROUND_TRUTH_JSON`); instead `loomwright/scripts/test-build-floor.sh` **parses the required-key set out of the annotated block below** and validates a real payload against it, so a doc/validator divergence fails CI.

**Evidence-only derivation — the invariant this schema exists to encode:** absent evidence yields an **omitted key**, never a plausible default. A surface that could not be counted carries **no `count` key at all** (never `0`) and names the reason; an input that could not be fully parsed reports `status: unverified`, never `counted`; an mtime that could not be read portably is omitted rather than defaulted to the Unix epoch. A consumer must be able to render "unknown" and must never be handed a fabricated zero.

```yaml
FLOOR_PROJECTION:
  schema_version: 1                    # integer, required — always 1
  generated_at_epoch: integer|null     # integer|null, required — Unix seconds UTC of the run; the script's ONE wall-clock read, overridable via FLOOR_SOURCE_DATE_EPOCH. `null` ONLY when the clock read itself failed — the key is always present
  generator: string                    # string, required — producing script name, always "build-floor.sh"
  repo_head: string                    # string, optional — short HEAD SHA; OMITTED outside a git repo or when git is unavailable
  surfaces: object                     # object, required — map of surface key → surface entry. Keys are stable snake_case names (state, jobs_pending, jobs_in_progress, jobs_done, jobs_failed, automate_runs, logs, sessions, insights_runs, postmortem, drain_rounds, worker_summaries, rules, agents). Every entry carries the four-space keys below
    source: string                     # string, required — the repo-relative path or directory the entry was derived from. ONE exception: `agents`, whose source is the plugin's own install directory (resolved from the producing script's own location, overridable via FLOOR_AGENTS_DIR) — the agent roster is a property of the INSTALLED PLUGIN and is identical for every project it runs in, so there is no repo-relative path that could name it
    basis: string                      # string, required — the glob or predicate that produced `count`, stated inline so `logs: 65` can never be confused with `logs: 99` (the same directory holds 34 plain .log files a `*.jsonl` glob does not count)
    status: enum [counted, absent, unverified]   # enum, required — counted = the number is proven; absent = the input is not there; unverified = the input exists but could not be fully parsed or read
    count: integer                     # integer, optional — present ONLY when status == counted. ABSENT, never 0, for absent/unverified
    reason: string                     # string, optional — present when status != counted; names why the count was omitted
    mtime_epoch: integer               # integer, optional — Unix seconds mtime of `source`; OMITTED when unreadable or non-numeric (never 0), and omitted by design for surfaces spanning many files
    detail: object                     # object, optional — surface-specific evidence already in hand (e.g. `sessions` reports lines_scanned / lines_with_session_id / lines_without_session_id / lines_malformed / lines_blank_skipped; `state` reports phase / branch / run_status / session_id). Each inner field is itself omitted when absent. The three inner keys below are documented because a consumer renders them directly; the rest of `detail` stays free-form per surface
      roster: array                    # array, optional — `agents` only: one object per agent file, sorted by name, each carrying name / color / model / max_turns / read_only. Every one of those is OMITTED when the frontmatter does not state it, `read_only` included — a file listing no disallowedTools is silence, and `false` there would be a derivation from silence. `read_only` is true only when disallowedTools lists both Write and Edit as WHOLE tokens (a substring test matches NotebookEdit)
      current: object                  # object, optional — `sessions` only: the SHOWN session — the one that recorded plugin work (an `agent_type` starting `loomwright:`, or an `autonomous_session_start`), falling back to the session owning the newest `ts` only when none qualifies. Carries `selection` (`"plugin_run"` \| `"newest_recorded"`, naming which rule produced the row), an optional `sessions_not_plugin_work` count of ts-bearing sessions that recorded no plugin work and are not this one (OMITTED when zero, and it excludes the shown session on BOTH branches), an optional top-level `branch` taken from the shown session's own lines (distinct from the per-agent `agents[].branch` below), plus cc_session_id + last_event_ts + an `agents` array sorted by agent_id whose rows carry events / first_ts / last_ts / identified_at / agent_type / agent_scope / branch / last_checkpoint / lifecycle, plus a sibling `feed` array (see the additive-field entries below for both). `agent_scope` (`"main"` \| `"subagent"`, omitted when neither is provable) says WHICH THREAD a row is, which is a different question from `agent_type`'s WHICH ROLE — a row with no type but `agent_scope: "main"` is the session's own thread, not an unidentified agent. `events` counts every line the agent appears on (including one with no `ts`) EXCEPT an `agent_identity` line, which is a fact about an agent rather than an event of one; first_ts/last_ts span only the lines that carried a `ts`. `identified_at` is the `recorded_at` of that agent's `agent_identity` line and is taken from THAT line only — it is a second clock for ageing a lane that has never emitted, never a substitute for `last_ts`, and a consumer must not read it as an event time. `last_checkpoint` is the text of the last `worker_checkpoint` line attributed to that lane by file-position window (see the additive-field entry above) — exact on Single-Agent/Sequential, best-effort under Parallel-path interleaving; also folded into `lifecycle.last_checkpoint` verbatim, never re-derived. OMITTED entirely when no record carries a `ts` — file order is not evidence of recency
      subtasks: array                  # array, optional — `state` only: one {id, title, status} object per row of the `## Subtasks` table, in table order. `status` is omitted for a table with no Status column, never guessed
      rules: array                     # array, optional — `rules` only: one row per rule object parsed out of the category files, ordered by (category, id, source_file). Each row carries source_file plus id / category / statement / enforcement / provenance, and `applies_to` / `check` / `supersedes` ONLY when the source object carries the key. OMITTED entirely when the merged set holds ZERO rule objects — which covers BOTH "no file could be parsed" and "every file parsed cleanly but yielded no rules" (an empty-array store); the gate is `($rules | length) == 0`, not a parse failure, and the distinction matters precisely because this section exists to separate "examined and found nothing" from "could not examine" — an empty array here would read as "examined and found nothing", which is not the same claim
      rules_parsed: integer            # integer, optional — `rules` only: the number of rule OBJECTS. Deliberately NOT `count`, which keeps meaning category FILES for this surface; redefining `count` would change a number three other surfaces publish under the same shared contract
      files_parsed: integer            # integer, optional — `rules` only: how many category files were read successfully
      files_unparseable: array         # array, optional — `rules` only: one {file, reason} per document that would not parse, named with the parser's own message. OMITTED when every file parsed — its PRESENCE is the "could not examine" signal, and it must never be confused with "examined and clean"
      files_not_an_array: array        # array, optional — `rules` only: files that parse but are not the top-level array this store uses, so they contribute no rows. Named rather than silently skipped
      read_completeness: enum [all, partial, none]   # enum, optional — `rules` only: the finer read distinction the three-value `status` enum cannot carry alone. all = every file was both parsed AND understood as this store's array-of-rules shape; partial = some were, some were not; none = files were present but nothing usable was read. **A file that parses cleanly but is not an array counts as NOT understood, exactly like an unparseable one** — keying this only on parse failure reported `all` beside a file the projector had just refused to read, which is the examined-and-clean claim this projection exists never to make; `files_not_an_array` names those files separately. The last two are both status `unverified`, so this key is what separates "read some" from "read nothing". A fourth `status` value was deliberately NOT introduced: `status` is required and consumers branch on its enum, so extending it would break them
      supersedes: object               # object, optional — `rules` only: the curation graph as chains / dangling / cycles / self_referential / duplicate_ids, each omitted when empty. `chains` are TRANSITIVE and in walk order; `dangling` names each {from, to} whose target exists in no parsed file; `cycles` — the pinned field name for the cycle report — holds one array per cycle, rotated to start at its smallest member, with EVERY member listed rather than dropped. **This deliberately diverges from `read-rules.sh`**, whose pinned routing contract instead HIDES a superseded rule, resolves single-hop only and never transitively, and treats a dangling pointer as an ignored no-op. Those semantics are right for a reader answering "which rules apply to this diff" and wrong for a browser whose purpose is to show the curation history, including what was retired and what points nowhere. Only that reader's FIELD SCHEMA is reused. Its TERMINATION property is NOT diverged from: every walk here is the same bounded, non-recursive fixed-length pass per node, bounded by the total edge count, so a cyclic or malformed graph can never loop the projector
      correlations: array              # array, optional — `rules` only: one entry per rule for which a rule/churn correlation was computable, as {rule_id, label, basis, matched[], evidence_by_line} where each match carries line / path / pattern, and the ledger's own evidence for those lines is carried ONCE PER CORRELATION in `evidence_by_line` (a line-number-keyed object; `matched[].line` is the key into it). The evidence travels WITH the correlation it was derived from — it is simply stated once per line rather than re-serialised once per (rule, path) match, which measured 612 occurrences for 154 distinct strings on an artefact the page re-fetches every 2 s. A line with no recorded evidence is absent from the map rather than present-and-empty. `label` is the literal `observation` and `basis` says so: this is a PATH OVERLAP between a rule's applies_to globs and a ledger line's changed_paths, matched with the same native shell case-glob semantics that reader routes with, and it is NOT evidence the rule was violated. Nothing is rated, scored, ranked or topped-N. A rule with no computable correlation (applies_to null or absent, an unread ledger, or globs matching nothing) is OMITTED — a zero would read as "measured no violations" when the truth is "no correlation was computable"
      class_distribution: object       # object, optional — `postmortem` only: root-cause class → number of category objects carrying it. A key-addressed object, never an array ordered by desirability
      class_basis: string              # string, optional — `postmortem` only: the literal `.categories[].class`, the predicate `class_distribution` was computed over
      flow_stage_distribution: object  # object, optional — `postmortem` only: flow stage → number of category objects carrying it, over the SAME denominator as the class half
      flow_stage_basis: string         # string, optional — `postmortem` only: the literal `.categories[].flow_stage`. **The ledger carries TWO flow-stage representations that do not agree** (see the caveat below), so a flow-stage number without its basis is ambiguous; this key is what makes the published one checkable
      categories_total: integer        # integer, optional — `postmortem` only: the number of category objects, i.e. the one denominator both distributions are over
      lines_without_categories: integer   # integer, optional — `postmortem` only: lines that parsed but carry no category object. Counted separately rather than attributed to any class
      flow_stage_counter_disagreements: integer   # integer, optional — `postmortem` only: how many lines' `flow_stages` counter disagrees with a reduce over their own `categories[].flow_stage`. Records what the unpublished representation would have said
      entries: array                   # array, optional — `postmortem` only: one row per category object carrying line / index plus class / flow_stage / round / self_heal_miss / evidence when present. This is where the per-category `evidence` string each number was derived from travels, so a reader can check a number rather than trust it
      lines_malformed: integer         # integer, optional — `postmortem` only: lines that do not parse as a JSON object. Such a line is counted and named, NEVER folded into a class
      malformed_lines: array           # array, optional — `postmortem` only: the 1-based line numbers of those lines. OMITTED when there are none
  notes: string[]                      # string[], required — one human-readable line per omitted or unverified surface, in surface-processing order. MAY be `[]` when every surface was counted
```

**The two flow-stage representations, and why only one is published (the `postmortem` caveat):** the churn ledger records flow stage TWICE and the two do not agree. Every line may carry a `flow_stages` COUNTER object (`launch_pad` / `worker` / `self_heal` / `unknowable`), and every element of that line's `categories[]` carries its own single `flow_stage`. They diverge because the emitter derives the counter from a line's drain fix-cycle count while emitting at most one drain category object plus at most one `self_heal_churn` object, so on an engine-drain line the counter can read several where `categories[]` holds one or two entries — and, because `self_heal_rounds` never feeds the counter, a self-heal-only line reads counter `self_heal: 0` against one `self_heal`-stage category (a line with `fix_cycles: 1` plus self-heal reads 1 vs 2) — measured on this repo when this field was added, they disagree on a MINORITY of lines, all of them `automate_drain`. No count is pinned here: `learning-emit` appends to that ledger on every engine tick, so three measurements taken hours apart returned 89/26, 88/25 and 90/27 — the projector's own `flow_stage_counter_disagreements` field is the live answer, and `build-floor.sh` carries the jq one-liner that re-derives it. **The projector publishes `.categories[].flow_stage` and nothing else, and names that choice in `flow_stage_basis`.** The reason is denominator coherence rather than preference: `evidence` is a field ON the category object, so the class distribution is necessarily computed over category objects, and taking the counter for the flow-stage half would place two different denominators side by side inside one `detail` — in the one view whose entire premise is an honest basis. `flow_stage_counter_disagreements` records how often the unpublished representation would have said something different, so the choice is falsifiable rather than merely declared.

**Validation rules:**
- `schema_version` must equal `1`.
- Every top-level key marked `required` must be **present**; `generated_at_epoch` is nullable but its key is still mandatory (a present-but-null value is meaningful — "the clock read failed" — while a missing key is a producer bug).
- Every entry in `surfaces` must carry `source`, `basis` and `status`.
- `count` present ⇒ `status == counted`; `status != counted` ⇒ `count` **absent**. Emitting `count: 0` for an absent surface is a contract violation, not a rounding convenience.
- `status` must be one of `counted`, `absent`, `unverified`. An input that exists but could not be read or parsed is `unverified` — never `counted`.
- Sessions are segmented by the `cc_session_id` **field**, never by log filename: one file routinely spans many sessions (its name derives from a `state.md` `status:` that can read `running` for weeks) and one session can span many files.
- **Determinism:** two runs over an unchanged tree differ only in `generated_at_epoch`. Every enumeration is `LC_ALL=C` sorted and the artefact is emitted through `jq -S`, so the byte layout is a function of the data alone.
