# Changelog

Full release history for the Loomwright plugin. The two most recent entries are also summarized at the top of `CLAUDE.md`; this file is the complete record.

> Entries are historical: the version and count claims in each describe **that** release, not the current state. The authoritative current version/counts live in `plugin.json`, `hooks.json`, and the `agents/`/`commands/`/`skills/` directories.

**v15.33.0 — validate before you write: five shared checks across six sole writers, a real write path for agent memory, and a stated capability contract:** the curated stores only ever grew. The five sole writers appended without looking around first, so a store quietly accumulated entries that had stopped being true — and on the agent-memory side there was no sanctioned write path at all, so every write was hand-pasted, which is how one index rotted to a single pointer over eighteen files and made seventeen of them invisible to the agent that owns them. This release adds one uncounted plain script, **`scripts/validate-entry.sh`**, holding five checks (duplicate, contradiction, provenance, dead reference, cross-repo reference) behind one aggregate entry point, and wires it into the write path of all six sole writers. It adds the sixth writer, **`scripts/write-agent-memory.sh`**, which does not *maintain* a store's `MEMORY.md` but **rebuilds** it from the files on disk on every write — a file can now only be missing from the index if it is also missing from the directory — plus a `.supervisor/agent-memory-proposals/` queue mirroring the shipped orientation-proposal pattern. Counts are unchanged: no new agent, command, skill or hook.

**One helper, sourced defensively, because a broken helper must degrade into the failure mode the design already sanctions.** Five independent copies were rejected (they make "one allowlist, two consumers" drift-prone by construction) and so was a hard dependency (it inverts the writers' fail-safe convention). Each writer's load guard is three clauses, all required: the `source` must exit 0, all five validator functions must be present, and a sentinel version string must match the literal the writer hardcodes. Two clauses would not be enough — bash defines every function **above** a syntax error before aborting the parse, so a truncated helper leaves *some* validators defined and a one-function probe would report "examined and clean" over half a validator. `|| true` is forbidden on that source line: this repo's otherwise-pervasive convention applied there yields exactly the silent unvalidated append the design forbids, and a mutation control proves that replacing the guard with `|| true` turns the test red. Every check refuses on an input it **cannot examine** (unreadable file, absent `jq`, unparseable JSON, an allowlist that resolved to nothing) with a named reason, rather than reporting clean — the examined-vs-could-not-examine split v15.28.0 was built to close.

**The cross-repo check's direction was INVERTED in the source requirement, and a literal implementation would have gone fully green while behaving backwards.** The requirement said to derive the check "from the allowlist's known foreign slugs", which presumes the allowlist is a deny list of other people's repos. It is not: it is *this* repo's own permitted slugs, defaulting to the current git remote, and the shipped ledger filter **keeps** records whose repo is in it. Implemented as written, the check would have refused citations of this repo and passed genuinely foreign ones — worse than a no-op, because every acceptance criterion would still have been satisfiable. Caught at Plan Review and corrected before any code was written; the direction is now stated in the helper's own header next to the membership test, and a mutation control inverting the test is required to turn the own-repo case red. A second consequence is pinned in the tests: no fixture may add a foreign slug to the **live** allowlist, because that would make `setup-memory.sh apply` judge foreign ledger records clean and emit the negation that un-ignores the churn ledger — publishing another repo's analysis from this public repo. Fixture allowlists therefore move through the process-global env var or a `--root` fixture repo, and a negative control asserts the publication gate still withholds the negation on a foreign record.

**The first wired implementation falsely refused 12 of 21 live curated entries — 57%, every one a false positive.** Replaying the real `LESSONS.md` + `PROJECT_MEMORY.md` corpus through the validator was the only thing that surfaced it; the hand-written fixtures were all green, because fixtures are written by the same person who wrote the checks and inherit their blind spots. The refusals were: a dead-reference check that could not resolve a script living under `loomwright/scripts/` rather than the repo root; glob-shaped and tilde-shaped paths (`test-*.sh`, `~/.claude/settings.json`) treated as dead references when they are *unresolvable by shape* and must skip rather than refuse; and six ordinary English prose pairs (`yaml/json`, `dev/ci`, `budget/zone`, `user/pr-text`, `shell/wget`, `worker_result/code_review_result`) read as `owner/repo` slugs. The corpus replay now ships as a permanent regression test, with a seeded-synthetic control proving the replay harness itself discriminates and an assertion that an empty corpus is a failure rather than a pass. For the two over-recognising checks the bias is stated in the code rather than left implicit: **a false refusal is worse than a miss**, because it blocks a legitimate write and the check's whole value is that a human trusts its verdict.

**A residual bound, stated rather than papered over: a bare all-lowercase `word/word` whose owner is not a known owner is a deliberate miss.** `otherco/othersvc` standing alone in prose is shape-identical to `budget/zone`, and there is nothing in the text to separate them — refusing that shape is precisely what refused six live entries above. The check therefore recognises a slug only when it is *marked*: by a `github.com` URL, a `#123`/`@sha`/`.git` citation, a neighbouring cue word, a known owner, or slug-only structure such as a hyphen, digit or CamelCase — plus the identifier-shaped `NAME #123` form. A paired test pins both halves for the same reason: `otherco/othersvc` unmarked **passes**, `budget/zone` **passes**, and the marked forms of the former are refused. The refusal message itself carries the bound, so a reader of a real refusal is told what the check does not see. **The cross-repo check is not complete coverage and is not described as such anywhere** — a clean verdict is not proof that no cross-repo reference is present.

**TWO OF THE FIVE CHECKS NO LONGER REFUSE, AND THIS CONTRADICTS SCOPE 2 OF THE SOURCE REQUIREMENT** ("a validation failure is a refusal to write"). It is an owner decision taken on measurement, and it is recorded here in the form that lets a later reader disagree with it rather than in the form that makes it sound inevitable. **`dead-reference` and `cross-repo` are now ADVISORY: they report on stderr and always return 0. `duplicate`, `contradiction` and `provenance` are unchanged and still refuse.** The reason is that six consecutive review rounds found false refusals and **every single one was in those same two checks** — the other three have never produced one. That is structural, not luck: the three that block key on input whose shape the writer controls, while the two that scan free English prose for file paths and repository names are looking at a medium where a citation and an ordinary sentence are frequently the same characters. The rounds, in order: 12 of 21 live curated entries refused (57%, every one a false positive); then prose pairs (`YAML/JSON`, `ground-truth/conformance`, `Count/version`), numeric ratios (`117/117`), a git branch name (`fix/v14.23.1-combined`), in-repo directory paths (`docs/Spikes`) and prose shorthand (`CHANGELOG/CLAUDE.md`), each of which refused a legitimate write and each of which was fixed by a narrowing that did not end the class. **The last round is the one that settled it: the fix for "gitignored but real files are unresolvable" made the verdict MACHINE-DEPENDENT.** Unioning an on-disk `find` into the path index was green on the author's working tree, where `.supervisor/state.md` exists, and red on every clean checkout, where it does not — measured with a `git archive HEAD` extraction at **231 passed / 0 failed locally versus 229 / 1 clean, 3 of 28 live curated entries falsely refused** — and the flagship corpus-replay guard could not see it because it replayed `$REPO_ROOT`, the one environment where the artifact exists. A write-time gate whose answer depends on which files happen to be lying around is not a gate. **What is bought:** a false positive can no longer block a legitimate write, and the verdict of a write no longer depends on the machine it runs on. **What is sold, stated plainly:** a genuinely dead reference and a genuinely foreign repository citation are now written, with a warning, and only a human reading that warning will act on it. Their could-not-examine paths (unusable `--root`, absent `jq`, unparseable record, unresolvable allowlist) are advisories too — an advisory check has nothing to fail closed *for* — while decision (b) governs the three blocking checks exactly as before, which is why they keep the 0/1/2 verdict codes and an unreadable store is still a refusal.

**An advisory nobody reads is worse than no check, so the reporting is the load-bearing half of this change.** Every finding prints a stable `ADVISORY:` marker carrying the *same* detail the refusal used to carry, in a shape no grep can confuse with a refusal (no advisory token begins with `REFUSE_`); the count and tokens are left in `$VALIDATE_ENTRY_ADVISORY_COUNT` / `$VALIDATE_ENTRY_ADVISORY_TOKENS`; and all six sole writers call a new `validate_entry_advisory_notice` on the write path so the finding is repeated at the call site, in the writer's own name, next to the fact that the write went ahead. `validate_entry_all` runs the three blocking checks first and returns the first non-zero among them, then runs the two advisory ones and **absorbs** their status — not because they are trusted to return 0 (they are, and a static test asserts neither function contains `_ve_refuse`, `_ve_unexaminable`, `return 1` or `return 2`), but because "this long function contains no non-zero return" is a property a future edit can break silently, and if it broke, an advisory finding would block a write again. A mutation control makes an advisory check return 1 and requires the aggregate to still exit 0 *and* name the anomaly. The contract sentinel moves to **`validate-entry/2`**: a writer built against `/1` was entitled to read "rc 0" as "all five checks passed", and that is no longer what it means, so a stale writer paired with this helper must refuse rather than write under a contract it does not implement. **The corpus replay was re-aimed rather than dropped** — it now resolves cited paths against a `git archive HEAD` extraction instead of the working tree, which is the method that exposed the defect, and it still gates the three checks that *can* refuse a live entry. Its probe is constructed, not derived from whatever gitignored files happen to exist: the first version picked the first ignored file it found and measured 0-vs-0 on another machine, because that file's owner directory existed in one tree and not the other — deriving a probe from the environment, inside the guard whose purpose is to stop the environment deciding the verdict, is the same defect one level up. A paired assertion now pins that the *verdict* is identical whether or not a cited runtime artifact exists while the *advisory* still moves with it, and a re-blocking mutant reproduces the original 1-vs-0 divergence on demand.

**Two writers gained a worktree guard they never had, and provenance stopped being a per-writer opinion.** The "existing sole-writer worktree invariant" was only 3 of 5: `add-rule.sh` and `add-orientation.sh` carried none and resolved their store with a bare toplevel lookup, which in a linked worktree returns the worktree's own toplevel, so both wrote happily from a worktree. They now refuse — guarding the **resolved** store root, so an explicit `--root` pointing at a worktree is refused too, which a cwd-only guard would miss — while their deliberate non-git-repo fallback is left unchanged rather than inheriting `write-lessons.sh`'s hard exit. Provenance moved into the shared helper: a source qualifies only if it carries a real reference (a digit, or a `:`/`/`/`#`/`@` id separator), so the shipped `/dreaming` accept path passing a bare command name is refused and now passes the session id it already held. And `write-project-memory.sh`'s benign "already stored" no-op had been turned into a hard failure by the validator firing first; the dedup now runs **before** validation, pinned by a test.

**Agent memory finally says what an agent may do with it.** `memory: project` agents may **not** write their own store: they write proposals, and every store write goes through the sole writer under a human `--confirm`. The trigger is **surprise-only** — an entry is proposed when something genuinely contradicted what the agent expected, not once per run — and queue volume is recorded rather than acted on, so widening the trigger stays a later decision made on data. Both rules are now stated under an identical `### Agent memory write permission` heading in the root `AGENT_GUIDELINES.md` and in all six `memory: project` prompts; the silence was the actual defect, because the tool surface gives the **wrong** answer. `disallowedTools` blocks `Write`/`Edit` for some of these agents, but Bash is not restricted by the harness, so a shell-redirection store write is reachable for all six whatever the allowlist says — which is exactly why this had to be prose and not an inference. `scripts/test-agent-memory-permission.sh` asserts **content, not a heading**: a heading grep is satisfiable by adding seven empty headings, so each file is reduced to the text under its heading and four literals are required there, with a control proving an empty section is rejected, a control proving a deleted refusal sentence goes red naming **only** that file, and a check that no forked contract has appeared under `loomwright/` — a copy there would satisfy the self-reported outputs gate while writing the rule into a document nothing reads.

**Then three of those writers turned out to accept flags they had never implemented — and write anyway.** `write-lessons.sh`, `write-project-memory.sh` and `write-system-contract.sh` ended their argument loop in a catch-all that silently dropped every unmatched argument and returned a clean success. All three derive their store from the **current directory**, never from anything the caller passes, so an argument that looks like it redirects the store parses, is discarded, and the write lands in whatever repo the caller happened to be standing in. This was not theoretical when it was found: during review of the work above, a reproduction run passed `--repo <temp repo>` believing it isolated the store, the flag was ignored, and a junk entry landed in this repo's real `LESSONS.md` and its provenance chain — caught only because someone ran `git status` afterwards. **The reach is ordinary, not exotic: `--repo` and `--store` are REAL flags on `write-agent-memory.sh` and `add-orientation.sh`**, so a caller reaching for one on a sibling writer is following house vocabulary, not making a typo. All three now refuse with **exit 2** — each writer's own could-not-examine convention, verified against its other argument checks rather than assumed — naming both the offending argument and itself, and writing nothing. `write-lessons.sh` also refuses stray *positionals*, since `add` takes none and `retract`/`supersede` take exactly two; its documented positional curation forms are unchanged, and every call site in the repo was read before narrowing them.

**The guard is deliberately NOT harmonised with the validator's parser, and each copy says so in place.** `validate-entry.sh`'s `_ve_parse_args` ignores unknown flags **on purpose**, so that a stray argument can never crash a fail-safe validation path. That reasoning is right for a validator and wrong for a writer, and the asymmetry is the whole point: a validator that refuses costs a diagnostic, a writer that silently retargets costs the store. The contrast is stated in a comment at all three guards, because the two parsers sit next to each other in the same vocabulary and unifying them would reopen this. **No `--repo` flag was added.** Rejecting unknown arguments and adding a real store-root flag are separate decisions, and adding one here would make the ignored-argument class invisible again — so: reject first. The other three writers already refused, but **no suite asserted it**, so those guards could have been deleted silently; all six now carry a test. **Two mutation controls caught defects in the tests themselves rather than in the code.** Stripping only the `--*)` arm from `write-lessons.sh` left the mutant still refusing — the dropped flag's *value* fell through to the positional arm and was rejected there — so the test would have passed against a writer with no flag guard at all, and the mutation now removes both halves. In the two positional writers a softened guard **drops** the stray flag rather than promoting it, so the stray must follow a complete positional set or the mutant dies on the usage check instead of writing. Both are recorded where the mutation is built, not worked around. Counts unchanged.

**v15.32.0 — the citation-drift guard stops policing one line in one file and polices every live `file.ext:<N>` in the repo:** v15.31.0 hit the "absolute line-ref drift in prose edits" defect class three times in a single change, and the guard that landed with it — `(j4b)` in `test-read-rules.sh` — was scoped to exactly one shape: `session-resume.sh:<N>` citations under `loomwright/scripts` that also said "no-arg" on the same line. The sibling instance in that same PR (`add-rule.sh`'s `--applies-to` comment citing the `category` traversal reject at `:245` when the guard was at `:274`) was invisible to it, which is precisely why that one survived two follow-up commits that were hunting this defect class. `(j4b)` is retired here and replaced by `scripts/test-citation-drift.sh`, which runs on every live surface. **It found twelve already-rotted citations on its first run**, all corrected in this change: `emit-token-ledger.sh:94→:128`, `read-postmortem.sh:124→:159` (three citing sites), `RESULT_SCHEMAS.md:249→:789`, `context-keeper.md:15→:26`, `brain-context/SKILL.md:42→:100`, `supervisor.md:140`→ a descriptive anchor, `write-lessons.sh:125→:46`, `setup-memory.sh:920→:949`, `async-orchestration/SKILL.md:576→:557` and `:120-122→:564-566`, `hooks.json:88→:112`, plus two off-by-one frontmatter references in `IMPROVEMENTS_ROADMAP.md` converted to descriptive anchors.

**What is and is not mechanically decidable, stated rather than over-claimed.** "Line N holds what the surrounding prose claims" needs the semantics of the prose, so the gate does not pretend to decide it. It runs three checks of increasing strength and asserts nothing beyond them. **(A) A line-count floor** — the cited file must resolve and must have line N. This is a floor, not a proof: it caught **none** of the three motivating defects, all of which cited a line that existed and merely said something else. It is kept because it is free and false-positive-proof, but a green (A) means "the line exists", never "the citation is right". **(B) Pinned anchors**, the check with teeth — a citation may carry `[pins: <literal>]`, and that literal must appear within ±3 lines of N. Auto-deriving the anchor from the prose was prototyped against this repo's real corpus first and measured at 1 hit / 11 false alarms / 8 no-signal, so it was rejected: the author chooses the literal, which makes (B) false-positive-free by construction. The ±3 window is deliberately tighter than the 8-line insertion that caused the original defect. **(C) A bare-citation ratchet** — every unpinned citation must be in an allowlist, so a *new* bare `file:N` fails the gate and authors are pushed toward `[pins:]` or a descriptive anchor ("the `category` guard in §1 above"), the style v15.31.0 converged on and the only one that cannot rot at all. The allowlist is itself checked for stale entries, so it can only ratchet down. Frozen historical surfaces — `CHANGELOG.md` and `docs/SPIKES/` — are excluded by design: they legitimately cite lines as they were, and a sweep without that exclusion fails immediately on correct history. Unresolvable citations SKIP rather than fail, because agent prompts carry illustrative output (`path/to/file.ts:67`) and some real references point into gitignored `.supervisor/` artifacts.

**The guard is mutation-tested, because the one it replaces shipped vacuous.** `(j4b)` reported success over an empty set on first write — its citation and its keyword sat on two different lines, so its `git grep` matched nothing. Eight synthetic mutation controls now run through the *same* `scan_surface()` code path as the real scan and are each required to catch a deliberate corruption; three further mutations were run against the real repo, including re-inserting eight lines above a cited line, which is the exact v15.31.0 defect. Two scanner bugs were caught this way and would otherwise have shipped silently: a pin written on the wrapped continuation line was not seen (the identical two-line footgun that made `(j4b)` vacuous — the scanner now takes a one-line lookahead, and refuses to borrow a pin across a line carrying its own citation), and a partial-path citation like `async-orchestration/SKILL.md` resolved to nothing because 41 skills share the basename `SKILL.md` (resolution is now a unique *suffix* match). A third bug was found in the guard itself: reading a zero-byte file into an array under `set -u` killed the subshell and **silently truncated** the result set from 34 citations to 14 — the scan would have reported fewer citations and passed. Review then found a fourth and a coverage gap, both fixed: a pin literal containing `]` (a JSON snippet, a `[0-9]` character class) was truncated at the bracket rather than at its closing backtick, which could yield a spurious PINMISS or a false OK on the truncated fragment; and the SKIP verdict had **no** mutation control, so a regression in the resolution chain could have routed a real, drifted citation into SKIP and silently exempted it from all three checks — vacuity by the back door. SKIP is now pinned from both sides (M9 unresolvable, M10 ambiguous, against M1/M8 proving a resolvable citation does *not* skip), and forcing total resolution failure is confirmed to trip 11 assertions rather than passing quietly. A later round caught two more of the same shape: both ratchet membership tests were substring matches, so as the allowlist grows one entry could silently exempt a *different* citation (`a.md|b.sh:1` is a substring of `xa.md|b.sh:12`) — now exact whole-line comparisons; and the `(A)` floor used `grep -c '' f || echo 0`, which on a zero-byte file prints `0` **and** exits 1, so the `||` appends a second `0` and the comparison errors out into a silently-false `if` — a citation into an empty file bypassed the check entirely. It now uses `awk 'END{print NR}'`, chosen over the obvious `wc -l` because `wc -l` counts newlines and under-reports by one on a file with no trailing newline (measured: 1 for a 2-line unterminated file). Both are covered by controls that were confirmed to fail against the old code. A final round closed the last two vacuity gaps in the guard's own bar — the anti-vacuity floor and `(C2)`'s stale-entry detector both sat *outside* the per-citation loop and had no control proving they could fire, the floor being the one check that exists specifically to catch what killed `(j4b)` — and replaced a `grep -e "/$cpath\$"` suffix match, where the cited path was interpolated as a **regex** (so the `.` in `regex.probe/` also matched `regexXprobe/`), with a literal `case` glob. Writing that last control was itself instructive: the first version used a decoy differing in the *basename*, which `find -name` already filters exactly, so the control passed against the very implementation it was meant to condemn — vacuous, caught only by running it against the old code, which is the discipline this whole file argues for. A last note turned a documented constraint into an enforced one: the header claimed one pin per line, but nothing checked it, so a line carrying two citations would have had both silently checked against the same literal — a false OK if it sat near both targets, a false PINMISS if it named only one. A pinned line with more than one citation is now an error telling the author to split it. Review also widened the scanned set: `.claude/agent-memory/` is un-ignored in `.gitignore` precisely so agent memory persists in git, which makes it committed, long-lived prose of exactly this class — and a rotted pointer there is worse than in a skill doc, because it misdirects the reviewing agent's own institutional memory on a later session with no human in the loop. It was unscanned, and three notes were carrying eleven bare citations; several had already rotted (a pointer into a now-blank line, another into a section enumeration that had moved, and two into `CHANGELOG.md:7`, which every release shifts by construction — including this one). The stable ones are pinned, the re-check lists now name their surfaces instead of line numbers. One more latent hole went with it: the range/list normaliser anchored a single match, so `:249,251,260` resolved to 251 rather than 260 and a past-EOF citation in a 3+ element list would have passed the floor. Two last ones came from review. Retiring `(j4b)` left two live comments still describing it as the active mechanism ("keep the word and the token together on ONE line or the guard stops seeing it") — the same defect class in prose rather than in a line number, and outside `CITE_RE` by construction, so the gate can never catch it. And suffix resolution walked the WORKING TREE rather than the tracked set, so a stray untracked file sharing a cited basename could flip a unique match to ambiguous and silently SKIP a citation locally while CI's clean checkout still checked it — a gate whose verdict depends on local junk. Not hypothetical: an untracked scratch file in this worktree was accidentally swept into a commit while this very PR was being written. Resolution is now `git ls-files` when the root is a checkout. The suite ends at 26 assertions, 20 of them mutation controls, each confirmed to fail against the code it rejects — two of which were themselves vacuous on first write and only exposed by running them against the old implementation, which is the entire argument this file makes.

**The convention surfaces were reconciled, including one that was missed on the first pass.** `CLAUDE.md`'s own "cite exact `file:line`" instruction in §"Adding or Modifying Agents" would otherwise have contradicted the gate it introduces. Review then caught the second-order case: `AGENT_GUIDELINES.md` — the shared preamble *every* agent follows — still said "always cite exact file:line" unconditionally, and its worked example walked an agent through proposing a `## Proposed CLAUDE.md Update` carrying a bare `(lines 23-67)` range, i.e. teaching the retired convention straight into the one file this change is about. Both now carry the committed-vs-ephemeral carve-out: a `file:line` in a live review finding is read once and discarded, so exactness is the most useful thing an agent can give; a line number in text that gets **committed** is falsified by the next insertion above it, so it must be a descriptive anchor or a pin. The gate only ever polices the latter. No `.github/workflows/` edit was needed; CI's existing `loomwright/scripts/test-*.sh` glob picks the suite up automatically, which also avoids making `claude-code-action` self-skip this PR's own review.

**v15.31.0 — `applies_to` stops being a comment and becomes a path filter:** The house-rules substrate shipped `applies_to` in the schema in slice #3b-i and then wired advisory enforcement in #3b-ii without ever activating it. `read-rules.sh` accepted the touched paths as positional args and **discarded them** — every rule reached every agent on every task, which makes a rule that fires everywhere indistinguishable from a rule that fires nowhere. Invisible so far only because the store holds exactly ONE rule; the next queue item harvests ~104 `convention_mismatch` findings into rules, at which point fifty unrouted rules injected at three seams is both token bloat and the advisory-prose-gets-ignored effect the queue exists to fix. The reader now routes: a new shell function **`rule_applies`** matches each touched path against a rule's globs with a native bash `case`, and `add-rule.sh` gains a repeatable **`--applies-to <glob>`** so the scope can actually be authored.

**Everything ambiguous fails OPEN, and one of those cases is load-bearing.** A malformed `applies_to` — non-array, array holding a non-string, empty array — emits the rule repo-wide with a diagnostic to stderr + `memory.log`, never to stdout. So does **a call with zero touched paths**, and that one is not symmetry for its own sake: `session-resume.sh`'s `rules_nudge()` calls the reader with **no arguments** and fires its "no house rules found" SessionStart nudge when stdout is EMPTY. Treating an empty path set as "nothing matches" would make every repo that HAS rules start nudging as if it had none — a silent regression in a firing surface CLAUDE.md calls pinned. Zero args is an absence of scope, not a negative match. (The source requirement's own evidence was wrong here: it cited `session-resume.sh:197`, an unrelated observability-probe comment, and asserted all three seams already pass paths. Two of three do.)

**Order of operations between the two filters was unspecified, and it decides whether retired rules can come back.** Fixed at `validate/dedup → supersession → routing`. Supersession answers "which rule is CURRENT?" — a property of the store, identical on every call — while routing answers "which current rules are RELEVANT to the paths this caller touched?" — a property of the call. Run routing first and a retired rule RESURRECTS on any call whose path set happens to route its replacement away, making the store's own curation decision depend on the caller's diff. Pinned by a test, and the rationale lives in the reader's header docstring rather than only in this entry.

**Matching is a `case` glob in the SHELL, never in `jq`** — portable by construction, no `shopt -s globstar`, no `extglob`, no GNU/BSD flavour divergence. `jq` only NORMALIZES `applies_to` into a route cell. The cost is stated in both author-facing surfaces rather than discovered later: **`*` and `**` are equivalent and BOTH cross `/`**, there is no `!` negation and no leading-`/` anchoring, so `"loomwright/scripts/*"` matches `loomwright/scripts/a/b/c.sh` — explicitly NOT `.gitignore` semantics. `.gitignore` behaviour is not emulated. Two implementation notes worth keeping: the route cell is US-delimited (0x1F) because TAB is an IFS *whitespace* character, so an empty route cell would have folded with its neighbour and shifted every later field left by one — the cell is therefore stripped before rendering; and `--applies-to` accumulates through a newline-delimited string rather than a bash array, because `"${arr[@]}"` on an empty array is an unbound-variable error under `set -u` in the macOS bash 3.2 dev shell.

**A test that only asserts "the rule IS emitted" passes identically against the old no-op reader,** so emission assertions are not evidence here. The non-match case asserts **absence from stdout**, and a **mutation control** proves that assertion is load-bearing: the reader is copied with its routing predicate replaced by `true`, the same fixture re-run, and the absence assertion observed to fail. The control also guards itself — if the `sed` matched nothing the mutant would be byte-identical and the control vacuous, so that is checked too. The three prose seams reduce to exactly TWO executable shapes (`read-rules.sh <paths…>` and `read-rules.sh` with no args); both are now traced dynamically against a fixture store in `test-rules-seams.sh`, with the limit stated rather than oversold — a dynamic trace cannot prove agent/skill *markdown* still hands the reader the right paths, which is why the static grep assertions stay.

**`rules-check.sh` deliberately does NOT follow routing.** It accepts no path scope at all (its arg loop warns-and-ignores unknown args), and the parity it promises with the reader is over per-object validation + `LC_ALL=C` first-seen-id dedup — *which objects are well-formed* — not over applicability. Routing is an emission filter for advisory injection; `/rules check` is a repo-wide audit, and a rule routed out of some worker's advisory block has not stopped being true. **v15.30.0 — the readiness count, the consumption window, and the record now speak one unit:** v15.29.0 shipped the curation cadence with three different units for one quantity, in three different files, with nothing asserting a relationship between them. Readiness counted *log files newer than a wall-clock stamp*; consumption took *the N most-recent files* (`--sessions`, default 5); `record` stored *wall-clock now*. Every conversion between them lost information, and three rounds of plan review missed it because no single file contained two of the three. Measured on this repo 2026-08-09 (62 logs), the probe reported `/dreaming pending=61 ready=yes` for a run whose default window reads 5.

**A watermark cannot fix this — the record had to become a set.** `/dreaming` consumes the *most recent* N logs, so what a run leaves behind is the *older* tail, and a watermark ("pending = newer than T") cannot count an older tail at any value of T: `T = now` collapses pending to ~0 and permanently retires every unread older log (the shipped bug — 56 of them here); `T = newest consumed` is identical; `T = oldest consumed` re-counts the batch just read and *still* never counts the tail. Consumption is a set selection from the top of a sort and pending is its complement, so `record dreaming` now takes the session ids actually fed to reflection and `pending` is the set complement. Pending falls by exactly what a run read, the remainder survives for later runs, and targeting the older remainder becomes expressible for the first time. The set is keyed under `.dreaming.consumed.logs` so twin-loop item 05's second intake source becomes a sibling key rather than a migration. Ids reach jq via `--args`, never interpolated into the filter. A zero-id `record` still stamps `last_run` — a run that read nothing is a real run — but WARNS, because a run that read logs and forgot to name them otherwise looks exactly like a stuck probe. Unreadable or unparseable state yields `unknown`, never a confident backlog manufactured from an input we failed to read.

**The count names the window that will drain it,** and `test-curation-status.sh` group (o) greps `commands/dreaming.md`'s Parameters table and fails if it drifts from the probe's `DREAMING_DEFAULT_WINDOW` — the cross-file assertion whose absence let the gate and the window ship as unrelated numbers.
