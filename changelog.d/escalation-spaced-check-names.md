Spaced check names survive the wait-for-checks line (one shared reader)
`automate-helpers.sh escalation-cause` split the `wait-for-checks.sh --names` snapshot on whitespace, so a matrix-style check named `test (18.x)` was recorded as `check=test` with no run id. For a pending check the merge watcher then searched for a check run named `test`, found none, and never reported `now mergeable`. A red check lost its run id, so it could never be classified `check_red_unrelated`. PR #440 had fixed the same bug only in `drain-subfloor-decision.sh`, the other hand-written parser of that line. Both now read the line through ONE sourced reader, `loomwright/scripts/wait-for-checks-line.sh` (`wfc_line_parse`). It takes the scalars from their first occurrence and the names fields as delimited text, never splitting on whitespace. A missing reader fails closed (`check_red` / `ESCALATED`). The tests cover spaced pending and red names in the escalation suite (current-escalation carries the name through to the run file) and a merge-watch leg that reports a spaced name with no run id, while the truncated name stays silent. A producer-to-reader round trip runs in `test-wait-for-checks.sh`. One shared word-split mutant (`fixtures/wait-for-checks-line/wsplit.sed`) runs in all three suites.
