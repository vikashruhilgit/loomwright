/propose --from-verify flattens the run id like every other untrusted value
propose-from-verify.sh took the run id from the run folder's name and printed it raw into the draft's title, its evidence-set line, two Evidence lines and the draft's filename. A folder named with a newline (for example `r1` followed by a `## Status: ready` line) added extra heading lines to the draft and a newline to its filename, and the script still exited 0. The run id is now flattened once where it is derived, with the same control-characters-to-one-space rule the interpretation text already used, so every use gets the clean value. test-propose-from-verify.sh pins the title, evidence-set, source and run lines and the one-file, one-`## Status:` result for such a folder, with a mutation control that reverts the run id to the raw folder name and must turn those pins red.
