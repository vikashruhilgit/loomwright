ci-local fails a run whose suite leaves a process behind, and stray background processes are named at session start and at run end
`proc-registry.sh summary [--scan]` prints one line, `proc-registry: summary — <E> entries: <r> running, <o> overdue, <a> orphaned, <f> finished`, classifying every entry with the same code `list` runs, fed from ONE `ps -A -ww` snapshot (none for an empty registry). It is read-only: it never signals and never writes. An unavailable registry, missing jq or a failed or empty snapshot prints `proc-registry: summary — unavailable`. `--scan` appends `; <u> unregistered`, counting processes older than `LOOMWRIGHT_PROC_UNREG_MIN_S` (default 3600 s) that look like the plugin's: a command line under `/loomwright/scripts/` or an installed versioned plugin root `/loomwright/<version>/scripts/`, or a temp-dir `python*` whose script is gone. Registered live processes and their descendants (by the snapshot's ppid chain), the caller, its children and its ancestors are excluded. `lane-sampler.sh` now registers itself when its loop starts (kind `lane`, owned by the coordinator pid), so the wave's sampler is no longer counted as unregistered. Under `HERMETIC_TEST_ENV=1` without the new `LOOMWRIGHT_PROC_PS_SNAPSHOT` seam the scan is skipped, so no suite reads the live machine through it. `scripts/ci-local.sh` now has a leak gate. Before the early phase (and before the `--affected` runner call) it exports `LOOMWRIGHT_CI_LOCAL_RUN=<run id>` and opens a per-run marker file on fd 9, and takes one environment-showing `ps` snapshot. After the suite, a new process owned by this user that carries the marker (the variable in its environment, or the marker fd seen by `lsof`) and is still alive after a bounded settle poll (`CI_LOCAL_LEAK_SETTLE`, default 5 s) is printed as `ci-local: leak gate — survivor pid=<p> <command>`, and the run FAILs with `leak gate: <K> process(es) survived the suite (nothing cached)` and no PASS stamp. A failing snapshot fails closed. A new listener without the marker is only a note. The fd half exists because macOS `ps -E` hides the environment of Apple platform binaries such as `/bin/sleep`, so the brief's planned control "delete the export and the nohup leg turns red" does not hold on macOS: each half has its own mutation control instead. An env-blind `ps` with no `lsof` is the one documented fail-open (`leak gate — unverifiable (ps cannot show the environment)`). The suite also now runs with the saved caller stdout and stderr fds closed, so a leaked process can no longer hold a capturing caller's pipe open. SessionStart's `session-resume.sh` prints ONE `**Background processes:** <n> item(s) need attention (<o> overdue, <a> orphaned, <u> unregistered)` line on startup and on resume/clear/compact in a plugin-active repo, from one `proc-registry.sh summary --scan` call (local only, no forge call). Nothing to report, or an unavailable registry, prints no line, so a clean startup stays empty. The line points at `proc-registry.sh list` and `reap` (dry run first). The planned `/janitor` pointer is deferred until `/janitor` (af/39f) lands, and `list` and `reap` cover registered entries only, so an unregistered process still has to be found and stopped by hand. `HOOKS.md`'s SessionStart row and the hook's startup-arm block list name the new line. Both `/automate` done exits (the driver's `terminate` step and `finalize-empty`) append ONE `<ts> process registry: <summary line>` Progress line directly before their `sweep (dry run)` line, and fleet close-out appends ONE `fleet closeout registry: <summary line>` line before its sweep line, which stays the run file's last line. These run-end lines call plain `summary`, without `--scan`. `process registry` and `fleet closeout registry` are reserved Progress prefixes, so a model `progress_note` cannot forge either line. Limits: only macOS `ps` was exercised by hand. The Linux procps forms (`ps -A -ww` columns, the environment-showing snapshot) are exercised only by the self-tests on CI's ubuntu runners. Evidence from real runs on the integrated branch: `docs/evidence/af39g-leak-gate-and-attention-lines.md`.
