Run lock records a live holder under any harness and flags its TTL-only fallback
`run-lock.sh` resolves its liveness holder as `LOOMWRIGHT_HOLDER_PID` (new, vendor-neutral, `pid_source holder_env`), then `CLAUDE_PID`, then an ancestor walk that no longer needs `CLAUDECODE` (wrappers such as `env`/`timeout` are skipped; session hosts such as `tmux`/`sshd`/`Terminal` stop the walk and are never recorded), then `$PPID`; no tier records 0, 1 or a leading-zero pid (a holder `kill -0` would never report dead, so a lock that could never be reclaimed), and a `$PPID` of 0 or 1 records an empty pid that stays TTL-reclaimable. Meta gains a `pid_start` start-time fingerprint after the original five keys, so a reused pid reads dead at reclaim; it is read with TZ pinned to UTC, so sessions in different time zones agree. A new read-only `run-lock.sh liveness` prints that verdict, and the session-start `### Stale run lock` line uses it instead of its own `kill -0` check. A lock that falls back to `pid_source ppid` prints one `run_lock_degraded: pid_source=ppid ttl_only=1800s` line on stderr at acquire and status; every exit code and parsed stdout line is unchanged. The merge watcher and lane close-out pin the holder to the close-out process itself, and lane launches unset the pin. The three acquire callers note the degraded line once and never park on it. See `docs/ARCHITECTURE_CONTRACTS.md` §"Run lock".
