Lanes that stop to ask keep their run log; four smaller lane defects from wave W2 fixed (automate-followups/40)
`close-stranded-run.sh` (SessionEnd) no longer closes a `--parallel` lane's run when the lane exits to defer a question: a lane clone (`.supervisor/lane.json`) holding an inbox question with no answer file writes nothing, because `lane-answer` resumes that same session. Before, the run was marked `failed`, every later lifecycle row went to the session's own log, and FINALIZE point 5 read a child unsettled, which forced `--skip-children-check`. A lane with every question answered, and any non-lane checkout, still close out. Also fixed: the worker-summary check now finds a summary in a dependency worktree (`../<repo>-<sub>-dep`); `lane-readiness` clips its children-settled line on a word boundary instead of inside a PR URL, whose partial `owner/repo` slug made meta-sync's `forge_slug` scrub refuse the lane's metadata push; `lane-status --refresh-readiness` also rewrites a lane that is already closed out; `closeout`'s `item_timing` session-log line omits a `null` `cc_session_id`, and `test-build-floor.sh` recounts sessions with the builder's own rule (a non-empty string id); `lanes_convert_ready` calls `_lanes_rf_done` instead of repeating its regex.
