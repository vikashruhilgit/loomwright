The restated-list house rule now reaches every markdown surface and every script (churn-ledger/01)
The postmortem ledger's `convention_mismatch` entries at flow stage `self_heal` share one cause: a surface restates a list, count, version, table, cross-reference or line number owned by another surface, and the copy is not moved in the same change as its authority. Counts, versions, line-number citations and the skills index already had mechanisms (`check-doc-currency.sh`, the count/version house rule, `test-citation-drift.sh` pins, `check-skills-index-sync.sh`). The restated list/table/enumeration class had only an advisory house rule, and its `applies_to` was `CLAUDE.md` plus `loomwright/scripts/*`, so `read-rules.sh` never emitted it for `loomwright/docs/`, `agents/`, `commands/`, `skills/`, `README.md` or `CHANGELOG.md`, where the cited drift landed, and Phase 4.5's house-rules advisory never showed it on a PR touching them. The rule was retracted and re-added through `add-rule.sh` (same id and statement, still advisory) with `applies_to` `*.md`, `loomwright/scripts/*` and `scripts/*`; `read-rules.sh` now emits it once for nested markdown, `CLAUDE.md` and both script trees, and not for a non-markdown, non-script path such as `stackpack/.claude-plugin/plugin.json`. Measurement limit: since 2026-09 almost every ledger line has `source: automate_drain`, with classes `drain_churn`/`self_heal_churn` and no finding text, so the ledger can no longer observe `convention_mismatch`. The fall from 45 such entries in 2026-06 to 0 in 2026-10 is not evidence that the drift stopped, and this change claims only the routing fix, not an effect.
