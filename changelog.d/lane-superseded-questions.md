Retire a lane question the lane abandoned and re-asked, so it no longer blocks the wave
A lane's pending question was "a question file with no answer file", and nothing retired a question the lane's own session abandoned. On 2026-10-16 lane L8 of run automate-2026-10-15-163325 asked its brief-save question, could not exit deferred, ended a plain turn, and on `--continue` re-asked under a new `tool_use_id` that the owner answered. The first file stayed pending forever: `lane-status --inbox` and the `/lanes` pane showed "1 question waiting", `lane-answer` refused it as "parked on another question", and the lane would have read `awaiting_input` instead of its park, so `lane-convert-ready`, `wave-build` and `lane-remove` would all have refused until the coordinator moved the file by hand. Now the lane's relay hook applies one rule when it records a new question id: every older unanswered question of that lane is superseded, because a deferred question ends the lane's process and a new id means the session moved on. The resume of an answered question re-fires the same id, so it is never superseded. The question moves to `inbox/questions/superseded/` with `superseded_by` and `superseded_at` added (the record is kept), and one lane `## Progress` line names it. `lane-answer` and `--deliver-pending` refuse a superseded id with `superseded by <newer id>`. Every reader now goes through one helper, `_lanes_pending_questions`: lane-remove, pick-guard, lane-status (and so lane-wait and the pane), `--inbox`, and the lane-wait Stop hook. Tests AM1–AM12 replay the L8 sequence (0 pending, the lane reads its park) with a mutation control.
