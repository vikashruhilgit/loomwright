Lane coordinator: /automate --parallel N runs independent Queue items at once
`/automate --parallel N` (N > 1) runs up to N independent Queue items at once, each in an isolated local clone ("lane") at `<primary>-lanes/<run_id>/L<n>/`, tracked by one coordinator in the primary checkout. New `scripts/automate-lanes.sh` (lane-create, lane-launch, relay-hook, lane-answer, lane-remove, lane-convert-ready, lane-info, init-check, pick-guard, branch-check, lane-status, lane-feed, lane-readiness) and `scripts/lane-sampler.sh` (fleet log, memory-guard trip file, once-per-crossing notify).
A READY lane parks the new `ready_for_release` (no merge watcher, "do not merge yet — wave open"); the primary is locked for the wave (`automate-lanes:<run_id>` run lock + `pick-guard` at every sequential PICK, which parks the new `live_lane`, and at every new run's start — so a plain `/automate` is refused even after the coordinator's lock was reclaimed); lane questions are relayed to the owner verbatim through a file inbox; a lane launches only on a command the owner typed in that session (`lane-launch: BLOCKED — …` otherwise); `--auto-merge` with `--parallel N>1` is refused at INIT.
Engine seams: `resume-glob` skips lane run files in the primary, `closeout-others` and `finalize-empty` stay out of other runs inside a lane, `current-wave` writes `## Current`'s `- wave:` line, dismissed-findings reads include lane drafts, `read-token-ledger.sh` sums repeated `--root`, meta-sync manages `.dismissed-decisions`, and `run-self-tests.sh` takes a `ci-slot.sh` slot. Without `--parallel`, or with N = 1, no lane code path is entered except the read-only `pick-guard`, which prints `ok` when no `*.lanes` table exists. Protocol: `skills/automate-loop/SKILL.md` §14.
