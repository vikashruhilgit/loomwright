Spawned agents no longer write waits that match themselves
A fix agent whose `ci-local.sh` run outlived its tool call (a full run takes about 10 min, past the 600 s cap) was moved to the background, and the agent then waited with `until ! pgrep -f "scripts/ci-local.sh"; do sleep 5; done`. The agent's Bash tool runs the whole command line as one `zsh -c "<command>"` process, so `pgrep -f` matched the waiting shell itself and the loop never ended. Two such waiters ran 80 min (pa/23) and 18 min (pa/24) with no suite running. The worker contract (Step 5), the Phase 4.5 fix prompt and both review-heal fix prompts (default loop and until-mergeable drain, which automate's fix-now worker reuses) now carry one rule: redirect long test output to a file and never pipe it into `tail`; block on a backgrounded run with the project's own wait command or a bounded loop on a line the run writes when it ends; never wait with a `pgrep -f`/`pkill -f` whose pattern appears in your own command. The new `loomwright/scripts/test-no-self-matching-wait.sh` finds every fix prompt that says "tests locally" and fails if one lacks the rule. For this repo, `bash scripts/ci-local.sh --wait` waits on the run's own pid instead of a process name. It returns `--last`'s verdict, or exits 3 at a 540 s deadline (`CI_LOCAL_WAIT_MAX`) so the caller can call it again. `CLAUDE.md` and `AGENT_GUIDELINES.md` name it. The preloaded review-heal text raised the `review-pr` prompt budget 39187 → 43235.
