meta-sync's privacy scrub no longer blocks fixture e-mail addresses at reserved domains
The email rule now passes an address whose whole host is reserved so it can never receive mail (RFC 2606 / RFC 6761): example.com, example.org and example.net with their subdomains, and any name under the .test, .example, .invalid or .localhost TLDs. Plans and briefs quote such fixture addresses (`jane.doe@example.test`), which used to fail every branch-mode history push until a person rewrote the brief by hand. The exemption is anchored at both ends, so `x@example.com.evil.io`, `x@test.com` and `x@notexample.com` still hit, and a real address beside a reserved one still hits. The two exemption filters now go through a file rather than a pipe, so a grep error in the first is still reported as a scan error (fail closed). Tests that used `someone@example.org` as the real-address example now use a non-reserved domain.
