Provider probe: setup-providers.sh check plus Grok and Copilot table entries
New read-only `loomwright/scripts/setup-providers.sh check` reports, from commands it actually ran, whether each provider-table CLI is installed, logged in, usable headless with a parseable reply, permission-pinnable and browser-capable, and ends every row with `usable for write seats`, `usable for read-only seats` or `not usable: <first failing column>`, plus the install or login command to run. It always exits 0, writes only its own `mktemp -d` scratch dir, runs a fixed prompt from a throwaway cwd under the real HOME, and bounds every call with a process-group timeout. Permission pin flags are matched as whole tokens in the CLI's help text. For a provider with no auth-status command the smoke is the only auth signal, so its smoke runs even when logged out; a smoke failing for any other reason reports `auth: unknown (smoke failed: <reason>)` with a qualified login hint. The probe data lives in each `provider-<name>.sh` beside its lens contract; the engine names no vendor CLI. New `provider-grok.sh` and `provider-copilot.sh` entries are written from the vendors' docs (cited with dates, documented assumptions until run on a real binary), which also makes both selectable as a `--voter-provider` lens. `test-setup-providers.sh` covers every column state with stub CLIs, and `docs/evidence/provider-routing-02-providers-probe.md` records the real report from the owner's machine; the real `grok` report is still outstanding because `grok` was not installed.
