The publish guard refuses an /automate item published around its run spawn
Under `/automate --inline-phases` the main thread could skip the driver's `/autonomous run` spawn, make the item itself on a new branch, push it and open a PR (#937, seen live from a kernel-started session on 17.38.0). `guard-finalize-publish.sh` scoped publishes to the branch a stale `state.md` named, and a finished or absent `state.md` made it inert. Now, when `automate-next-step.sh` prints the run spawn it records in its sidecar the Supervisor session `state.md` names at that moment (`run_spawn_state_sid`, empty for a `--continue` spawn). While the sidecar waits on `run-result`, the guard denies `git push` and `gh pr create` in that run's checkout with `automate_run_unrun` unless a different session (the spawn's own Supervisor) names the publish's branch. The guard stays on for this even with no live run. A live Supervisor then meets the FINALIZE marker check as before, and a finished one (the inner EVALUATE drain) is allowed. Regression cases in `test-guard-finalize-publish.sh` (the 23r shapes, a closed and an absent `state.md`, the spawn's own Supervisor, `--continue`, an answered spawn, another repository, no jq, and a mutation control) and leg R1b in the driver suite.
