`setup-providers.sh check` and `lens-run.sh` now start a provider CLI the same way, and `pinnable` needs an observed denial
Before this change, `check` ran each provider CLI under the real HOME while `lens-run.sh` ran it under an empty scrubbed HOME, so `check` could report a provider usable while every routed step failed at login. Both now go through one sourced launcher, `loomwright/scripts/adapters/providers/launch-provider-cli.sh`. It gives the CLI an `env -i` allow-list environment and a fresh isolated `mktemp -d` HOME per call, which holds read-only copies of only the login files the provider's table file declares (`PROVIDER_LOGIN_FILES`). Only the declared login env vars that are set cross (`PROVIDER_LOGIN_ENV`). The CLI runs as its own process group with a TERM-then-KILL timeout, and the isolated HOME is removed on every exit path the launcher sees. A provider whose login works in your shell but cannot cross isolation (for example a keychain-only login) now reads `auth: not_logged_in_isolated (ok in your shell)` with a `fix:` line naming its declared login env vars, ends `not usable: auth`, and `lens-run.sh` names the same status at the start of `notes`. In `check` that status comes from a single diagnosis rerun under the real HOME, and no verdict is graded from it. `permissions pinnable`, and with it `usable for write seats`, now needs the permission probe. The probe is one isolated model call per candidate provider, made from an empty throwaway directory with a fixed prompt asking for `probe.txt` under the provider's pin flags (the new optional `probe_perm_argv` table function). The CLI must answer, and nothing may appear in that directory. Pin flags that only show in `--help` read `pin flags advertised (unverified)`, and a CLI that writes the file reads `unpinnable (pin flags not enforced)`. A new guard, `loomwright/scripts/test-provider-cli-single-launcher.sh`, fails when any other script starts a provider CLI directly. Real rows from this machine, with where each CLI keeps its login: `docs/evidence/provider-routing-02-providers-probe.md` §"Re-run after provider-routing/05".
