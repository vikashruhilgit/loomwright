Children-settled gate: every child stop settles, and FINALIZE point 5 runs before anything is published (automate-followups/33)
Part A: `emit-lifecycle.sh ended` writes a terminal `agent_lifecycle` `state: "ended"` row from a matcher-less `SubagentStop` leaf (so `general-purpose` / `Explore` spawns settle) and from `PostToolUse[Task]` on a blocking Task return (so a turn-limit stop settles — on Claude Code 2.1.286 a `maxTurns` stop does not fire `SubagentStop`, pinned in `scripts/fixtures/subagentstop-maxturns-probe.json`; a background launch writes nothing). `check-children-settled.sh` reads `ended` as a lower-tier terminal row: a worker settled only by `ended` reports `ended_without_result: true` (a stated, record-only semantic change), a `SubagentStop`-seam `ended` never settles a worker whose latest stop was validator-rejected, and a hung child or a background child stopped at its turn limit still reads `unsettled`. `build-floor.sh` treats `ended` as terminal (`quiet`, never `working`).
Part B: `guard-finalize-publish.sh` adds a fail-CLOSED `PreToolUse[Bash]` leaf with no `|| true` that denies `git push` / `gh pr create` in a live Supervisor run until `.supervisor/logs/<plugin_session_id>.finalize-gate` names the current HEAD. Only its `write-marker` mode writes that marker, after it runs the `--all` check itself (or on `--skip-children-check`). The session join reuses the `loom_log_owner` rule, now in `scripts/loom-log-owner.sh` and sourced by `emit-lifecycle.sh`. A resumed `--continue` run is still gated. Rollback: `git revert`. The marker does nothing without the guard, and the `ended` row only adds data.
Hardening: the guard now reads `.supervisor/` from the main worktree (shared `loom_main_root`, so a linked-worktree session is gated while the detached review-drain sibling is not), accepts bold-format `state.md`, detects wrapped / nested / quoted / path-qualified / continued publish forms (`env`/`sudo`/`xargs` prefixes, `bash -c`, `$(…)`, subshells, `cmd&`, `/usr/bin/git`, `git -C "my dir"`), records `no_identity_rows` verbatim instead of as `settled`, refuses to write a marker when the session log is missing, and Phase 4.5 re-runs `write-marker` before each heal push.
