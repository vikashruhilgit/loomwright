read-token-ledger.sh --per-item splits Build and Phase 4.5 for fresh-phase runs
The per-item cost report took Build's end and the Phase 4.5 iteration boundaries only from `FINALIZE:` / `Phase 4.5 iter <n>` Progress lines, which only the model ever wrote, by hand, inside an inline `/autonomous` run. A fresh Supervisor phase runs in its own session and never writes them, so every fresh-phase item printed Build and Phase 4.5 as `not recorded`. The reader now takes those boundaries from the hook-written rows `phase-timing.sh` already joins from the Supervisor session log (`pr_created`, one code-reviewer span per iteration), and falls back to the Progress lines only for older runs whose log has none. A new fixture with a deliberately misplaced hand-written `FINALIZE:` line pins the precedence.
