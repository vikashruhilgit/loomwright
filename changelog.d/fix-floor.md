One configurable fix floor for every review step
New `scripts/fix-floor.sh` and a `.supervisor/config.json` `.fix_floor` key (`HIGH` | `MEDIUM` | `LOW`, default `MEDIUM`; a `--fix-floor` flag on `/launch-pad`, `/supervisor` and `/review-pr` overrides it per run) set the lowest finding severity that gets fixed. Before this, the steps disagreed: Launch Pad's plan review and Supervisor Phase 4.5 fixed only BLOCKING/HIGH and let MEDIUM pass, while the `/review-pr --until-mergeable` drain fixed every validated bot finding — so a MEDIUM Phase 4.5 passed was found again by the CI review bot and cost an extra drain round. Now all of them read the same value. Phase 4.5 and the diff-only `/review-pr` loop turn a reviewer PASS that still carries an at-floor finding into a fix round; the drain dismisses a validated finding whose stated severity is below the floor as `below_fix_floor` (a finding with no stated severity is still fixed); Launch Pad refines a plan-review PASS that carries an at-floor issue and re-reviews it, but an at-floor issue still open after the third review is saved as `deferred` and never blocks. The reviewers' own decisions and the result validators are unchanged. The detached drain receives the floor as `LOOMWRIGHT_FIX_FLOOR`, resolved in the checkout that holds the config, because its sibling worktree has no `.supervisor/`. An invalid value fails closed as `fix_floor_invalid`. `--severity-floor` stays termination-only and independent.
