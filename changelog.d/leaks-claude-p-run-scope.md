lane-status --leaks scopes its claude-p section to this run
The wave-end leak check's `claude-p` section compared every headless session on the machine against the wave-start snapshot, so closing wave 1 of run automate-2026-10-15-163325 read `leaks: found — claude-p` from another repo's healthy wave (its `_lane-run` wrappers and their children). The section is now `## claude-p v2` and lists only this run's processes, read from one `ps` call: a `_lane-run` wrapper whose lane directory is under `<primary>-lanes/<run_id>/` or in the lane table, its children by parent pid, and any other headless session whose working directory is one of those lanes. `--plugin-dir` is not used as a tie because every coordinator passes the same plugin root. A snapshot written before v2 reads `claude-p: not compared`, never a false `found`, the same way the `## merge-watch v2` section handles old snapshots. An unreadable process table reads `leaks: unknown`, and the command still exits 0.
