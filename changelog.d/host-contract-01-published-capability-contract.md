Published capability contract (loomwright/capabilities.json)
Adds `loomwright/capabilities.json`, a generated, versioned description of what the installed plugin offers — agents with the exact runtime agent type, commands, skills, result schemas, and hooks with what each one writes into the session's working directory — so a host reads one stable file instead of parsing plugin internals. It is produced by the new `loomwright/scripts/build-capabilities.sh` (deterministic, sorted, no timestamps), its schema and compatibility policy live in the new `loomwright/docs/CAPABILITIES_CONTRACT.md`, and a fail-closed staleness gate (`build-capabilities.sh --check`) runs in CI and in `scripts/ci-local.sh`, which now also derives `bash loomwright/scripts/<x>.sh --check` lines from ci.yml as gates. Hook `writes[]` come from a per-script audit recorded in the generator; an unaudited script reports `["unknown"]`, never an empty list, and the hook-command parser fails closed (any construct it does not model, such as `tee`, `cp` or an unparsed script path, reports `["unknown"]`). `scripts/bump-version.sh` now regenerates the contract's `plugin_version` in the same bump and restores it on failure, so a release never pushes a stale contract. Additive only: no existing behaviour changes.
