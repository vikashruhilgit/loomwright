Wave-1 review fixes: --last keeps its full-run log, the resume probe sees BOM run files, no false "kept" leftovers
Fixes from the review the S3 wave-1 PR #397 never got (recovered locally). `ci-local.sh` prunes full-run logs before `--affected` ones, so 20 `--affected` runs no longer push out the full-run log `--last` reads (total still 20). `AGENT_GUIDELINES.md` states what is actually kept and lists the `UNVERIFIED` verdict. `session-resume.sh` uses a byte-identical copy of `is_run_file`'s title ERE (leading BOM, up to 3 spaces of indent) instead of a narrower private pattern, with a drift guard. `closeout-classify` treats only the partial-removal form `removed — worktree …; kept …` as a kept leftover, so an item or branch NAME containing "kept" no longer raises a false leftover question. New tests: ci-local (PA), session-resume (zg), closeout-classify (CL2k), and the cross-run close-out leftover path (CO4–CO6, including that a PR URL in a leftover detail reaches the record line as `<url>`).
