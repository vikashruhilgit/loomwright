Pin the no-PR RUN Progress line and read its status_reason in the lane timeline
`/automate`'s per-item loop pinned a `## Progress` line only for a RUN that opened a PR; when `/autonomous` stopped with no PR the acting agent worded the line freely, so the `/lanes` timeline had to guess the stage from prose (#569 loosened that guess after lane L5 of run automate-2026-10-15-163325 read Merge while it had stopped at Plan). Step 2 RUN now pins `<ts> ran /autonomous — no PR: <status_reason> (<one-line why>)`, carrying `AUTONOMOUS_RUN`'s own `status_reason` token, and `_lanes_timeline` reads it: the eleven reasons that stop `/autonomous` before the Supervisor starts (Launch Pad blocked or aborted, a discarded brief, NO-GO, Plan Review FAIL, a dropped rubric, the INIT refusals) reach Plan only, every other reason reaches Build, and a free-text line from an older run file still falls back to #569's match. Tests AJ4e–AJ4f check each Plan-stage reason, that every one is a real `status_reason` in the autonomous-loop enum, that the step-2 prose carries the template, and a mutation control.
