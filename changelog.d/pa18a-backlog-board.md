/backlog — one read-only board of every requirement item's real state, derived from evidence (parallel-automate/18a)
A requirement's first `## Status:` line is not updated on merge, so counting `pending` lines over-counted open work and re-offered shipped work. The new `/backlog` command (`commands/backlog.md`) runs the new `automate-helpers.d/backlog.sh` family. `item-state <item>` is the one status reader. It gives each item exactly one state from a closed set (done, abandoned, parked, proposed, brief_shipped, merged_unstamped, pr_open, in_flight, conflict, open, unknown), derived from the item's own stamps (any `## Status:` line, so an appended done stamp under a first-line `pending` reads done), run files, live lanes and two cached `gh pr list` reads, and it names the evidence line behind each state. `backlog` is the board: rows grouped by folder, totals that sum to the item count, a right-size column from ONE `right-size --json` call, `--json`, `--state`, `--unknown` and `--verify-list`. A failing `gh` reads `github: unverified`, never a silent `open`. `backlog-stamp … --confirm` is the owner-approved writer, the dispatcher's sixth carve-out. `/backlog --verify` proposes per item and asks through two new human-only catalog gates: `BL-VERIFY` (stamp done, stamp done with escalation, abandon or skip an item with no merge evidence) and `BL-CONFLICT` (abandon, keep open or skip a conflict item, owner decision D-conflict-1). It stamps only the approved items, and in branch mode publishes them with `meta-sync.sh push --branch … --paths-from`. When it cannot ask, it lists its proposals and writes nothing (`verify_requires_owner`). `reconcile-status --apply` no longer stamps ABANDONED from a Queue row over an item whose first status line is explicit `pending`/`ready`. A `conflict` item prints `info\t<rel>\tconflict\t<run file>` instead. Restated command counts outside the manifests were removed rather than bumped. Live run (`docs/evidence/pa18a-backlog-board.md`): 447 items, every state counted once.
