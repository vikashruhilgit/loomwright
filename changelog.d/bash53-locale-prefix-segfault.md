Shell scripts no longer run commands under a temporary locale prefix (Homebrew bash 5.3 segfault)
Every `LC_ALL=C cmd` / `LC_ALL="$X" cmd` at command position in the plugin's shell scripts (190 lines across 51 files: 163 `sort`, plus `find`, `tr`, `grep`, `awk`, `comm`, `uniq`, `sed`, `jq` and a child `bash`) is now `env LC_ALL=C cmd`. On macOS, Homebrew bash 5.3 (the `bash` on PATH, so the one tests and hooks run) restores the locale after such a command by calling setlocale → libintl → CoreFoundation, which is not fork-safe; inside a forked subshell this segfaulted a few percent of fresh processes (exit 139, empty output, which a fail-safe reader reported as a clean answer). Measured with LANG unset, 150 fresh processes per shape: a prefixed command that is not the last in `$( )`, or one inside a function called in `$( )`, crashed 8/150; the `env` form, `export LC_ALL=C`, `local LC_ALL=C` and the exec-optimised last-command and pipeline-element positions crashed 0/150. `env` passes the child the same environment, so every command's output is byte-identical. The new fail-closed CI gate `scripts/check-locale-prefix.sh` (self-test `scripts/test-check-locale-prefix.sh`, with a mutation control on setup-memory.sh's `gitignore_gate`) bans the shape repo-wide, because Linux CI cannot reproduce the crash.
