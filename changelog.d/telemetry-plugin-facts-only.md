Telemetry carries plugin facts only, never project content
Telemetry issues go to a repo the user chooses, often public, and user-scope consent can route any source repo there, including private ones. Until now the issue body carried the first line of every new BLOCKING/HIGH finding description, a 200-character `primary_error` excerpt, failed-subtask and failing-test names and the result-block `task_id`, while `docs/TELEMETRY.md` claimed it never carried finding descriptions. `send-telemetry-core.sh` now posts only plugin facts (agent type, schema, status enum, score, per-severity counts, tool-name tokens, plugin version) for every source repo; Issues Detected lines are fixed templates such as `[HIGH] new finding`; `primary_error` and `task_id` feed only the local dedup hash. The `include_result_block` consent key is inert (the core logs `include_result_block_ignored`). The privacy section of `docs/TELEMETRY.md` now states the rule and matches the code; `test-send-telemetry-core.sh` Group 12 pins it with path / function / line / repo-URL fixtures and a mutation control.
