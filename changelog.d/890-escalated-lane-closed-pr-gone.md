An escalated lane whose PR was closed unmerged can be abandoned
`lane-status` now reads the live PR state for every lane park that carries a PR (`escalated`, `failed`, `drain_died` as well as `awaiting_merge` / `ready_for_release`), so a PR the owner closed unmerged turns the lane `gone` and `lane-remove --abandon` records and pushes it through its evidence-gated path. Before, only the READY parks were checked: an escalated lane with a closed PR kept reading `escalated` and `--abandon` refused it `metadata not pushed`, leaving the wave unable to close (#890). Plain `lane-remove` on such a lane now refuses `gone (PR closed unmerged) — a human runs lane-remove --abandon` (it read the gone state only from the lane table and run file, so it said `metadata not pushed` instead). A non-READY PR merged by hand keeps its park and says a human should check it; an unreadable PR never reads `gone`.
