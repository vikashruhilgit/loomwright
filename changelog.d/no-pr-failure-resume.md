A lane stalled by a no-PR failure is now sent to --resume-run, because --continue could never restart it
After `phase_died`, `launch_pad_result_malformed`, `concurrent_session_detected`, a checkpoint or `supervisor_failed_other`, the driver's pending instruction is `done/stopped`, and a no-result call only re-prints it. So the one `--continue` a stalled lane gets did nothing and the work never restarted. `lane-launch --continue` now refuses a lane in that state, and the reason shown by `lane-status` and `lane-wait` names `--resume-run`, which re-picks the item; a checkpoint still resumes its Supervisor run. The reason says the owner decides when the same failure recurs or the phase left a PR open. A stall with a live driver spawn still continues as before.
