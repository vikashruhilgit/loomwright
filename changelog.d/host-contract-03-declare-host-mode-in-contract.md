Capability contract declares host mode (host_switch + per-hook host_mode)
`loomwright/capabilities.json` now tells a host how host mode works without it parsing internal docs. The top-level
`host_switch`, published as `null` until now, is an object `{env, state_dir_env, effect}` naming `LOOMWRIGHT_HOST_MODE`
and `LOOMWRIGHT_HOST_STATE_DIR` (the self-test greps `scripts/host-mode.sh` to prove both are read there). Every
`hooks[]` entry gains `host_mode` (`redirects`, `skips` or `unaffected`), generated by `build-capabilities.sh` from the
`docs/HOOKS.md` §"Host mode" classification table: rows keyed by script name or glob, an inline-leaf row and a prompt
row, combined `redirects` > `skips` > `unaffected`. Anything it cannot classify is `unknown`, and the self-test holds
the real contract to no `unknown`, so a hook script added without a `docs/HOOKS.md` row fails CI. A missing table or an
unknown class word fails generation with one line. Both changes are additive: `contract_schema_version` stays `1`, and
every pre-existing field of every `hooks[]` entry is byte-unchanged. Source requirement:
`.supervisor/requirements/host-contract/03-declare-host-mode-in-contract.md`.
