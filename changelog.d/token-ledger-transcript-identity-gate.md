Token ledger reads only the stopping agent's own transcript
`emit-token-ledger.sh` now sums a transcript's usage only when its basename is `agent-<agent_id>.jsonl` for the payload's `agent_id` — the same positive identification that already set `agent_scope: "subagent"`. Before, any readable `agent_transcript_path` was summed: a payload with no `agent_id` had no resume watermark, so every repeat stop re-summed the whole transcript, and a path naming another agent's transcript booked that agent's real tokens to this one. Both now take the proxy line (0 tokens). This matters because `--max-tokens` ceilings and per-lane totals become live with parallel-automate/24. Test case 28 fails on the pre-gate emitter and passes here; case 25b's fixture, which reused another agent's transcript, now uses its own.
