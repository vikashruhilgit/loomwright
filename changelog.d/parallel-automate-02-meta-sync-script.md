`meta-sync.sh` syncs run history with a metadata branch as a per-file 3-way merge, scrubbed fail-closed before any push
New `loomwright/scripts/meta-sync.sh` (`init` / `pull` / `push` / `status`) moves run history between a checkout and a dedicated metadata branch (default `loomwright-meta`) without switching branches, forcing a push or touching the code branch's index, HEAD or working tree: the branch side is built in a separate index and pushed by refspec. Every sync decides each path of ONE explicit managed list (requirements, done/failed briefs, automate run files, the postmortem ledger, minus nested `.supervisor/` trees) from local, remote tip and a recorded base, so a stale clone no longer reverts a sibling's newer file, deletions propagate and stay deleted, and ignored logs can never be published. The base (`<gitdir>/meta-base`) is the per-path state both sides are known to agree on, not the branch tree, and a clone's first sync derives it from the branch history. Both-changed paths are a conflict that changes nothing and needs a human; the append-only ledger is line-unioned instead. Before any push every added or changed file is scrubbed (ledger repo allowlist, e-mail addresses, absolute home paths, five anchored token shapes in portable ERE, forge slugs outside the allowlist, optional tracked deny patterns): a hit exits 2, leaves the branch untouched and names every offending path in one run. A missing branch is a non-zero `no_remote_branch`, and only `init` creates it. A rejected push re-fetches and retries a bounded number of times, never forced. The hermetic `test-meta-sync.sh` covers the full scenario matrix plus two sed-built mutation controls, and `ARCHITECTURE_CONTRACTS.md` gains a `## Metadata branch` section.
