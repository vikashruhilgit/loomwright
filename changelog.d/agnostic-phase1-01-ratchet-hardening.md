Vendor-coupling ratchet counts the coupling that locks the plugin in
`scripts/check-vendor-coupling.sh` now reads named token classes from `loomwright/docs/vendor-coupling-manifest.json` (schema 2: install root, subagent orchestration, ask-user, hook protocol, runtime identity, SDK binding, model names) and prints a reference total per class plus a flat total; the gate still hard-codes no token. Overlapping tokens are attributed leftmost-longest in a POSIX-awk pass, so one occurrence counts once, for one class, on BSD and GNU alike. Agent and command files are a new `adapter_frontmatter` class: their YAML frontmatter stays exempt and their bodies are counted; hooks stay whole-file adapter. A new `raise_check` compares allowances with the base manifest (`$VENDOR_COUPLING_BASE`, else `origin/main`, read from the object store) and fails any new or raised allowance whose `allowance_reasons` entry is missing or inherited unchanged; CI fetches main into a dedicated ref and sets `VENDOR_COUPLING_REQUIRE_BASE=1` so the check cannot silently skip there. The manifest is re-baselined by `--print-allowances` with a reason on every raised or new entry; no reference was added or removed. An unreadable tracked file is now an error rather than a silent zero.
