reconcile-status no longer reads a PR that commits a requirement as the PR that shipped it
A dry run proposed `done (PR #359)` for `meta-sync-followups/04`, a requirement PR #359 had only added as `## Status: pending`; `--apply` would have stamped it done and `resolve-folder` would never have enqueued it again. The evidence rule now reads the PR's diff (`files`/`changedFiles`, re-read through the paginated REST endpoint past `gh pr view`'s 100-file page): a body citation from a PR whose diff adds or modifies the cited requirement is not evidence, a PR whose changed files are all under `.supervisor/` is never evidence, and an unreadable or incomplete diff is no evidence (fail closed). The trail-branch exclusion stays as a cheap first check. New test leg H8 in `test-automate-helpers.sh` covers the PR #359 shape, its control and the fail-closed reads, with a mutation control for each new check.
