wave-build — the engine builds the wave branch and opens the wave PR
At the end of a `--parallel` wave every lane PR parks and someone has to integrate the wave on one branch, and until now nothing did: `wave-plan` only printed the commands, so wave W3 (2026-10-11) stopped at wave end until the owner ran them by hand. The new `automate-helpers.sh wave-build <parent_runfile> [--wave-branch <name>]` (in the new `scripts/automate-wave.sh`, the one writer of a wave branch) does those steps itself and stops at an open wave PR. It reads the wave through the same resolver `wave-plan` prints from, now shared, so the two never disagree. In a temporary worktree off a fresh `origin/<base>` it merges each lane PR's exact head `--no-ff` in planner order, runs `scripts/ci-local.sh`, makes `scripts/bump-version.sh` plus one `chore(release)` commit the last commit, pushes only the wave branch and opens the wave PR, then records one parent `## Progress` line. It refuses with nothing created when a lane PR is not open, a lane is not parked, or the branch already exists. It stops with nothing pushed and the worktree kept on a conflict, a red local CI or a failed release step. A re-run with the wave PR already open reports `done`. It never merges a PR, never pushes a lane branch and never force-pushes, and merging the wave PR stays the owner's. The coordinator runs it as a background command at wave end (automate-loop SKILL §14 step 9).
