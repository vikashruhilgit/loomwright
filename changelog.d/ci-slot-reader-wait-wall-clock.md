ci-slot's 5 s load-reader wait is bounded by the clock, not a loop count
`ci-slot.sh` waited for a slow machine-load reader with 100 × `sleep 0.05`, a loop COUNT. Each `sleep` is a process start, which costs ~8 ms extra on macOS, so the "5 s" wait took 5.85 s on an idle Mac and longer under load: a reader answering at 6 s was taken as answered instead of still running, and `test-ci-slot.sh` (G10) failed locally on every branch including `main` (it passed on Linux CI, where process start is faster). The wait now reads the wall clock (bash ≥ 5's `EPOCHREALTIME`; bash 3.2 falls back to `SECONDS`, waiting 4–5 s, never past 5). New test (G13): with a `sleep` on PATH that costs 0.1 s extra per call the slow-reader check still holds `busy`, and a mutation control restoring the old loop fails it. Behaviour is otherwise unchanged.
