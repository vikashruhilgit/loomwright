A test-automate-lanes part run on its own no longer SIGTERMs every live /automate lane
Each `loomwright/scripts/test-automate-lanes.d/` part is sourced by `test-automate-lanes.sh`, which sets the hermetic `$T`. Run standalone, `$T` was empty, so the AN-z cleanup in `06-phase-sessions.sh` turned `pgrep -f "_lane-run $T"` into `_lane-run ` and SIGTERMed every live lane wrapper on the machine (two lanes of a live wave on 2026-10-22). Every part now exits 2 on its first line unless the entry script sourced it, and every name-pattern process lookup in the suite goes through one helper, `tal_pgrep`, which refuses an empty or relative `$T` and any path outside it. `test-automate-lanes.sh` and `test-guard-lane-wait-armed.sh` also stop when `mktemp -d` fails instead of using the working directory as `$T`. The new `test-automate-lanes-standalone.sh` runs each part standalone beside a decoy `_lane-run` process and checks that the part exits 2, reaches no `pgrep` / `pkill`, and leaves the decoy alive. It also fails a part without the guard and any raw `pgrep -f` / `pkill -f` line, with mutation controls.
