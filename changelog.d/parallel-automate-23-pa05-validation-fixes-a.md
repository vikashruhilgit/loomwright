Lane coordinator fixes from pa/05's Validation 4/5 run (parallel-automate/23)
Seven defects in `automate-lanes.sh` that the first real `/automate --parallel 2` run hit are fixed, each with a hermetic test that fails on the pre-fix code. F1: `lane-status <parent_runfile> --leaks --snapshot` works before the first `lane-create` (it derives the parent run id and the primary from the run file) and an unwritten snapshot exits 1 naming why. F2: a HELD `lane-answer` keeps the validated answer coordinator-side, the lane reads `answer_pending`, and only `lane-answer <lane> --deliver-pending --owner-command '<cmd>'` from the coordinator's poll delivers it, after the full launch gate and a re-check against the question's labels and the still-deferred tool call. F4: `lane-launch --resume-run` resumes a died lane's last session, so its own run lock no longer stalls the resume for up to 30 minutes. F5: `lane-readiness` writes its report when the Validation names no repro. F9: the leak check reads `leaks: none` after a clean wave; salvage and stream logs stay under `<primary>-lanes/<run_id>/`. F10: `lane-remove --abandon` writes no absolute path into the parent run file and reports the lane's real state. F11: the wave end pushes a lane's metadata through `trail-pr`'s evidence gate (never a whole-lane push), and `lane-remove --abandon` on a lane whose PR closed unmerged stamps the reconcile-status ABANDONED shape, so the lane is removable with no hand step and no done claim for unmerged work reaches the metadata branch.
