Every question gate fails closed with a named status when it cannot ask
A question gate that nobody can answer used to hang, or leave the model to improvise. Nobody can answer when the run is non-interactive, or when the gate's prose runs inside a subagent, where the host removes the ask tool. Each gate now has a defined branch for that case.
Product Owner's pre-persist soft gate persists nothing and emits `po_gate: needs_owner (<n> flags)`. `/product-owner` gains `--non-interactive`. `/automate --non-interactive-fallback` passes that flag to its prompt intake and stops on `needs_owner`, the same way it stops on 0 generated files.
Launch Pad gets `clarification_needed_non_interactive`, `no_go_non_interactive` and `plan_review_fail_non_interactive`. On a PASS it saves the unmutated reviewed brief, noted `saved_on_pass_non_interactive`, and it defers memory candidates.
Supervisor gets `init_input_missing_non_interactive` and `adjudication_required_non_interactive` (which checkpoints and picks no option). `/autonomous` gets the new AUTONOMOUS_RUN `status_reason` `review_heal_escalated_non_interactive`. Bare `/automate` gets `no_source_non_interactive`, and continues a single incomplete run as `resume_continued_non_interactive`. qa-executor's URL fallback returns `needs_human` (`base_url_unresolved`).
Detection uses the explicit flag plus spawn-contract knowledge ("I am a subagent"), never a stdin-TTY probe alone. Interactive options are unchanged.
The full per-gate inventory lives in `docs/ARCHITECTURE_CONTRACTS.md` §"Question-gate inventory", with a pointer in CLAUDE.md §"Failure-Mode Invariants". `scripts/test-non-interactive-gates-seam.sh` pins each gate's status string and runs a mutation control on the PO branch. It is seam-only because the PO flow has no fixture harness.
