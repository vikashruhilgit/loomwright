test-curation-status.sh separates --json stdout from stderr and names a parse failure as itself
CI run 37110081398 failed group (s) once with `dreaming= insights=`, both values empty, which meant jq could not parse the `status --json` output. The log could not show why: `run()` merged stderr into stdout, so one stray stderr line made the whole document unparsable, and the failure message printed only the two empty values. A one-line stray-stderr mutation of the probe reproduces that exact message. Now every `--json` run (`run`, `run_gh`, and the garbage-stat run in (c)) sends stderr to its own file. Each one is followed by `json_clean`, which makes two named checks: stderr is empty, and stdout is exactly one JSON object. Each check prints the probe's rc and the raw stream when it fails. A closing harness check fails any `--json` run that has no `json_clean`, and names its line. Inline `$(jget "$(run …)")`, `run … | jq` and `dpending` sites now capture first, then check. That matters most at the two `!=` assertions in (n) and (q), which passed vacuously on an unparsable document. No value assertion was weakened. The (s) message and the (d) degraded-body comparison also print the raw output.
