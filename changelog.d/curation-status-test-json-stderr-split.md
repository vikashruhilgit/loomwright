test-curation-status.sh separates --json stdout from stderr and names a parse failure as itself
CI run 37110081398 failed group (s) once with `dreaming= insights=`, both values empty, which meant jq could not parse the `status --json` output. The log could not show why: `run()` merged stderr into stdout, so one stray stderr line made the whole document unparsable, and the failure message printed only the two empty values. A one-line stray-stderr mutation of the probe reproduces that exact message. Now every `--json` run goes through `run` or `run_gh` and sends stderr to its own file. That includes the garbage-stat run in (c) and the jq-absent and `render_failed` fixtures in (d), which used to call the probe directly. Each one is followed by `json_clean`, which makes two named checks: stderr is empty, and stdout is exactly one JSON object. Each check prints the probe's rc and the raw stream when it fails. Two closing harness checks enforce this. One fails any wrapper call that has no `json_clean`, and names its line. The other scans the file and fails any direct `"$PROBE" … --json` call that bypasses the wrappers. Inline `$(jget "$(run …)")`, `run … | jq` and `dpending` sites now capture first, then check. That matters most at the two `!=` assertions in (n) and (q), which passed vacuously on an unparsable document. No value assertion was weakened. The (s) message and the (d) degraded-body comparison also print the raw output.
