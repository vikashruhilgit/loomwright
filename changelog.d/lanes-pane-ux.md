loomwright-lanes 0.3.0 — wave PR and lane PR links, slim step rail, in-flight button states, no lost re-read after an answer
Each lane card links its PR. The step rail is a thin bar per step (an SVG strip on remote surfaces) with its name centred beneath, a mark on the current step only, and, when the pane is too narrow for seven names, one centred "Build ● · step 3 of 7" line. Send, Keep awake, Refresh now and Show steps read "Sending…", "Starting caffeinate…", "Refreshing…" and "Loading steps…" while their work runs, and a second press is ignored. Root cause of answers that looked unsent: the pane's refresh skipped any read asked for while another was in flight, so the re-read after lane-answer was dropped whenever it landed on a 15 s poll, the answered question stayed on screen, and a second Send was refused as "already answered". A read asked for mid-read now runs once more after it. A refusal because the main session answered first now says so and clears the picks. A poll writes the open lanes' step feeds in one state write instead of one per lane, and repeated action lines fold into one with a count.
lane-status --json now carries `waves` (every wave PR the run opened, oldest first, from wave-build's `wave built: <branch> — PR <url>` progress record, no gh call), and the plain view prints a `wave <k> PR:` line; the pane shows the wave PR at the top of the page, latest first, each a link.
