Machine-wide load gate: heavy starts wait under load, nothing freezes the machine
New `loomwright/scripts/machine-load.sh` reads load per CPU and the OS's own memory-pressure judgment (macOS `kern.memorystatus_vm_pressure_level`, Linux `MemAvailable`/`MemTotal`) and prints `load1`, `cpus`, `load_per_cpu`, `mem_pressure` and `state=ok|busy|overloaded|unknown` (busy at 2x CPUs, overloaded at 3x, `LOOMWRIGHT_LOAD_BUSY`/`LOOMWRIGHT_LOAD_OVERLOADED` override; an unreadable value is `unknown`, exit 0). `ci-slot.sh acquire` now asks it before every grant, under the repo mutex and after the fairness check: an overloaded machine holds the caller in its queue place (re-checked every 15 s), a busy one admits only one holder machine-wide, and `unknown` or a broken reader grants as `ok`. Holders are listed in one machine state dir shared by every repo key and every `XDG_STATE_HOME`, so a clone with a local-path origin joins the count. An acquire nested inside a live holder (self-tests under `ci-local`) folds into it. `status` shows `held for load: <state> load1=<n>`. The gate never signals a process, and `status`, `dir`, `release` and `ci-local --last` never wait on it. `AGENT_GUIDELINES.md` now says to run suites through `ci-local`, never a bare `run-self-tests.sh` in a loop.
