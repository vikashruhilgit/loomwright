Plugin script steps report their failures and warnings as opt-in telemetry
Telemetry only ever heard from agents (`SubagentStop` result blocks), so when `/setup memory migrate` failed in a real repo on 2026-10-13 (seed's A/B check, A = 63 / B = 66) and printed a false readiness warning, the plugin learned of it only because a human pasted the session into a new one. Plugin scripts can now report a step's outcome through the same pipeline. `scripts/emit-script-event.sh` builds a `script_event` payload and pipes it to the existing wrapper, so consent, target repo, privacy scan and threading are the agent path's: nothing is sent without user-scope consent. It always exits 0 and prints nothing, so a failing gate still fails in front of the user with byte-identical output and exit code. The core reads only allow-listed fields of allow-listed shapes and copies nothing else: a known script name, token step and code, the `pass` / `fail` / `warn` outcome, up to 16 integer counts, per-group counts of a fixed managed-file KIND enum, and a `<script>.<step>` caller token. An extra key, a path, a message or a repo slug is dropped and counted, never posted. Each script step and code gets one thread per source repo, independent of branch and session, and the step's next pass closes every open code-thread of that step (`telemetry:healed-in-loop`). `migrate-branch-mode.sh` reports every step except the read-only `plan` / `state` from an EXIT trap. Diagnostic sites name their code (`ab_names_mismatch` with a/u/b counts and the KINDS each side holds alone, `preflight_checks_failed`, `still_tracked`, `pr_leaves_tracked` …), and any other failure reports its message class (`refused`, `step_failed`, `error`), never its text. `setup-memory.sh apply` reports its readiness verdict with leaked/blocked path counts and the migration step that called it. `LOOMWRIGHT_SCRIPT_EVENTS=0` turns emission off. New `scripts/test-script-event-telemetry.sh` covers field selection, the thread lifecycle against a recording `gh` stub, no-consent, the emitter's exit-0 contract, the migrate and setup-memory wiring, and mutation controls for the field selection and the group close.
