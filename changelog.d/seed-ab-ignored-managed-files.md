Branch-mode migration seed accepts the gitignored managed run history it pushed
`migrate-branch-mode.sh seed` (and `verify-pr`) failed its A/B check in every history-case repo where an `/automate` run had recorded a dismissed-findings decision. loomwright-studio hit it on 2026-10-13 with A = 63 and B = 66. The seed push sends the LOCAL managed run-history set, and the default `/setup memory` block deliberately keeps `.supervisor/automate/<run>.dismissed-decisions` ignored (as it does the postmortem ledger while the repo allowlist gate fails). Those files reached the branch without ever being tracked, so the strict A = B could never hold. The first-round relation is now B = A + U, where U is the managed run history on disk that git does not track. Names must match and so must every blob: A's from `HEAD`, U's hashed from disk. U is listed, recorded as `seed_u`, stated in the untrack PR body and in verify-pr's PASS line, and never untracked. A branch entry that is neither tracked nor a local file (another checkout's push, a stray) still fails, so the half-migrated A ⊆ B guard keeps its teeth (its test now plants a branch-only file). `meta-sync-rehearsal.sh` gains a `seed-ab` check that runs the shipped `seed` on the scratch clone, as `rollback-run` runs the shipped rollback. Rehearse had passed because its `verify-*` checks never compared the branch with the tracked set (it did copy the ignored files), and a mutant with the pre-fix relation turns only `seed-ab` red. The rehearsal also keeps each copied untracked file ignored in a half-migrated scratch clone that it resets to the default block, so the shipped seed does not see a dirty tree. The default block is unchanged: un-ignoring the ledger would leave it untracked (the trail PR never commits it) and fail migrate's clean-tree preflight instead.
