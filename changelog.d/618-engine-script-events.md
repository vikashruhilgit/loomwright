The /automate engine reports its failures as opt-in telemetry script events (#618)
Script events used to accept only the two migration scripts, so engine failures reached this repo only when a human read the coordinator output. `wave-build`, `closeout-classify`, `trail-pr`, `lane-remove`, `fleet-closeout` and `supervisor-next-step` now each emit at their fail/warn seam with a fixed code chosen at the site, such as `merge_conflict`, `leftover_sync`, `sidecar_missing_key`, `metadata_not_pushed`, `pull_failed` or `init-failed`. Each also emits a `pass` that closes the step's threads, but only when the same call reported nothing worse. Expected states send nothing: a lane's normal waits, `pr not merged` exclusions and run-lock retries. The payload rules are unchanged: tokens and integer counts only, never message text, paths, lane ids, PR numbers or branch names. The lane and wave seams are rooted at the primary, never a lane dir. `hermetic-test-env.sh` defaults `LOOMWRIGHT_SCRIPT_EVENTS=0`, and the tests that assert on events set it to `1`. `docs/TELEMETRY.md` has a new "What the engine reports" table.
