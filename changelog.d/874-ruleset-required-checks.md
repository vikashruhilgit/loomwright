Required checks and merge-gate protection read repository rulesets, not only classic branch protection (#874)
A base branch protected only by a ruleset answers the classic protection endpoint with 404, so every owned drain escalated `required_checks_unavailable` on round 1 with green CI, the scoped wait read its required set as verified-empty, and the `--auto-merge` gate read the base as unprotected. A new sourced library, `required-checks-rulesets.sh`, reads the branch's effective rules (`repos/<o>/<r>/rules/branches/<base>`, every active ruleset merged, paginated). `drain-gh-read.sh required-checks` (the drain's `required` step and Phase 4.5's CI read), `wait-for-checks.sh` and `gate-eval` condition 4/5 now take the union of the classic and ruleset required lists. An active ruleset that requires a check or an approving review counts as enforceable protection at the gate, which now reads the PR's live base instead of a literal `main`. Fail-closed behaviour is kept: an unreadable ruleset read is unavailable metadata (`required_checks_unavailable`, `required=unknown`, `PARK: protection_unreadable`), and a ruleset with no required-check rule is still "no required list", never "every check required". The classic paid-plan 403 path is unchanged.
