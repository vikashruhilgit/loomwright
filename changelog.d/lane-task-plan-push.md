A lane whose run wrote a task plan is removable after its wave end
`lane-convert-ready` and `lane-remove --abandon` now put the Orchestrator's task plans (every top-level `.supervisor/requirements/<slug>-plan.md` that is not a Queue item and carries no `## Status: done` heading) on the lane's exact non-claim push list. The plan sits on a meta-managed path that neither wave-end push carried, so `meta-sync status` kept reading `local_ahead` and `lane-remove` refused every such lane until a hand `meta-sync push` (seen 2026-10-10). A re-run of `lane-convert-ready` now names the state the lane reads afterwards (`<lane> reads done / awaiting_go (a re-run converts nothing)`) instead of claiming it converted the lane to `awaiting_merge`. New `test-automate-lanes.sh` group AC covers the lifecycle with no hand push, plus a mutation control that reproduces the refusal.
