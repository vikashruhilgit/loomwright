A lane's run file records its backlog path repo-relative, so its wave-end metadata push no longer fails the home-path scrub
`lane-launch` started each lane with `/loomwright:automate --backlog <absolute lane dir>/.supervisor/lane-backlog.md`, and the lane copied that argument onto its run file's `## Source` line. Whether the line ended up relative depended on what the model wrote, so on some lanes `lane-convert-ready` stopped with `meta_sync: scrub … home_path`. The launch now passes `.supervisor/lane-backlog.md`, which resolves because the lane session runs in the lane dir. Every run-file write (`runfile-write`, `progress-append`, `current-set` and the other writers) also rewrites any `- backlog` / `- folder` bullet under `## Source` whose absolute path is under the run file's checkout root to the root-relative path, matching the root as given or with symlinks resolved, so a run file created before this change is repaired on its next write. A path outside the checkout is left as written, and the scrub still refuses it.
