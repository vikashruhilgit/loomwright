Drain survives a failed PR read and keeps its counts across a restart
One failed `gh` read no longer ends a `/review-pr --until-mergeable` drain: `review-heal-next-step.sh` retries every PR read twice before the failure stands, and a read that keeps failing still ends `ESCALATED`, now with gh's error in the PR comment. A `--start drain` over a finished run no longer loses that run's work: the new block's `rounds`, `iterations`, `fix_cycles`, `issues_fixed` and `findings_validated` are totals across the runs, with a new optional `prior_runs` field, while `--max-rounds` still bounds each run. PR #830 showed both: a failed head read right after a push posted a false `ESCALATED (pr_unreadable)`, the restart then reported `issues_fixed: 0` for a drain that had pushed a fix.
