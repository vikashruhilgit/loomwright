Completion-evidence integrity: FINALIZE no longer passes a run whose worker evidence never landed
`scripts/check-children-settled.sh --all` takes a repeatable `--expect-id <id>`: every expected id is checked by the same terminal-row join as the `agent_identity` ids (union, deduped), so a worker whose identity row never landed (hook not fired, log dir unresolvable, non-Claude host) reads `unsettled` instead of the `no_identity_rows` a run that spawned nothing gets; a missing or empty log with an expected id is `unsettled`, and without the flag the output is byte-identical to before. Supervisor FINALIZE Point 5 and `scripts/guard-finalize-publish.sh write-marker` both pass one `--expect-id` per `### {worker-id} ({subtask-id})` heading under `state.md`'s `## Worker Results` (a leading `worker` / `agent` label word before the id is skipped) and per `agent_id: <id>` / `worker_id: <id>` key on a bullet, YAML-continuation or pipe-separated bold line (`- **subtask: 1** | agent_id: a1b2 | …`), so the finalize-gate marker now refuses `children_unsettled` for a recorded worker with no terminal row; because `## Worker Results` is LLM-written and its shape varies, a section with content but no readable id (a table, prose) makes `write-marker` refuse `worker_results_unparsed` (stale marker removed, none written) instead of silently reading it as "no workers" — an absent, blank or `(empty)` section is unchanged, and `--skip-children-check` still writes `skipped`; `write-marker` takes its flags in any order and refuses an unknown argument (`bad_args`) instead of ignoring it — after removing any stale marker, so a refused call never leaves an earlier one in place. `no_identity_rows` now passes only when the run spawned nothing. The two skill worker-spawn examples (`skills/async-orchestration/SKILL.md` §"Spawning a Worker", `skills/workflow-management/SKILL.md` §"Worker Dispatch") use `loomwright:worker` instead of `general-purpose`, the only type the worker hooks fire on. New tests in both suites, with mutation controls for the flag, the write-marker wiring and the `worker_results_unparsed` refusal.
