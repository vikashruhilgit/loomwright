migrate-branch-mode.sh protect --waive: an owner-recorded way past protect when GitHub cannot apply a ruleset
A private repo on GitHub's Free plan cannot get a ruleset or classic branch protection, and the branch-mode migration hard-blocked there: mode-pr and seed required protect=PASS with no waiver path. `migrate-branch-mode.sh protect --waive --reason <text>` now records the owner's decision to run the metadata branch unprotected. It is evidence-gated: it reads `gh api repos/<o>/<r>/rulesets` and waives only on GitHub's HTTP 403 (refused when GitHub serves a ruleset list, on any other failure and on a rate-limit 403), needs preflight PASS and a non-empty reason, and records `protect=WAIVED` with `protect_waive_reason` / `_evidence` / `_at`. WAIVED satisfies the mode-pr and seed gates and completes protect for `state`; the mode-pr and untrack-pr bodies carry an UNPROTECTED warning quoting GitHub's answer and the reason, and `state` and after-merge repeat it. A failing `protect --verify` leaves a waiver standing; a `protect --verify` PASS supersedes it and deletes the waive keys. The waiver reports script-event telemetry as `warn protect_waived`, never a pass. `/setup memory migrate` asks the owner before waiving and never chooses it; with no answer nothing is waived. New test leg 30 in `test-migrate-branch-mode.sh` (26 checks, one mutation control).
