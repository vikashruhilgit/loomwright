A finished run's file reaches the metadata branch whole
In branch mode both done exits (the run controller's `## Status: done` termination and `finalize-empty`) pushed the run file to the metadata branch and only then appended three more lines: the trail push's own result, the process-registry summary and the dry sweep summary. Nothing ever pushed a finished run again, so every run's copy on the metadata branch stayed those lines behind for good (23 run files here). Each done exit now ends with `trail-pr <runfile> --settle`, which pushes the run file alone once more after its last line is written; its result is printed, never appended, so nothing trails it. It is skipped with branch mode off or when the run's `meta-push-failed` marker is present (the earlier failure is already loud and the settle must not hide the paths that push did not send), and a settle failure is loud like any meta push. test-automate-trail's branch-mode finalize case now requires the branch copy to equal the local run file byte for byte; against the previous code it fails by exactly those three lines. Mode off (trail PRs) still leaves the same lines after the trail PR and is not changed here.
