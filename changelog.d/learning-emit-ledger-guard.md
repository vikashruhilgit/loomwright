learning-emit refuses a missing ledger path instead of writing a flag-named file
`automate-helpers.sh learning-emit` takes the ledger path as its first positional argument. A call that left it out and started with a flag (`learning-emit --repo …`, `--run-id …`, `--help`) appended the POSTMORTEM_RESULT line to a file literally named `--repo` / `--run-id` / `--help` in the cwd, and the real ledger got nothing. That happened in lane clones (where `fleet-closeout`'s `lane-remove` then refused the dirty tree) and in the primary checkout. The helper now refuses an empty or `-`-prefixed first argument: it writes nothing, prints one stderr line with the expected call shape, and still exits 0 (fail-SAFE). New test F20 in `test-automate-helpers.sh` covers `--repo`, `--run-id`, `--help` and an empty first argument, keeps the ledger-first call at exactly one line, and carries a mutation control.
