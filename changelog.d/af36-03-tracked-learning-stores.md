meta-sync leaves a git-tracked learning store to git
A learning-store path that a checkout's git index tracks now has one owner, git. This covers a repo that committed its eval file, twin contracts or proposals on its code branch; the migration never untracks one. `meta-sync.sh` pull and push leave such a path alone: they never write, delete, merge or publish it, and never report it as a conflict. Each one is named on stderr as `meta_sync: learning_tracked <path> — tracked by git, left to git`. Its `meta-base` entry keeps the previous one, so no later sync deletes the branch copy or overwrites the local file. Before this, a branch copy that diverged was merged into the tracked file on every pull. That dirtied the code branch, so `migrate-branch-mode.sh after-merge` failed on a non-empty `git status --porcelain` and rollback's clean-tree precondition broke. The index read fails closed. Run history is unchanged: a tracked run-history path keeps the 3-way rule. The exit code is unchanged too. `status --learning` appends `; tracked <n>` when such paths exist.
