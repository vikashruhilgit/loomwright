Read-only pipeline seats can now be routed to another AI CLI, per seat, with a user-scope consent grant per provider
A repo's `.supervisor/config.json` `routing` block (and `/supervisor --route <seat>=<provider>[:<model>]` for one run) can send a read-only analysis or review step to a non-Claude provider CLI instead of a Claude subagent. Claude stays the default everywhere: a repo with no `routing` block behaves exactly as before, and `routing.default` must be `claude`. The closed seat list lives in one place, `loomwright/scripts/resolve-routing.sh seats`; `resolve-routing.sh seat <id>` prints the resolved provider, model, source and reason as `KEY=VALUE` lines and always exits 0. Each seat's prompt points at the one procedure in `loomwright/docs/PROVIDER_ROUTING.md` (§"Routed seat protocol") and keeps its Claude path as the fallback; `strict` makes a missing provider the seat's own degraded path. Non-review seats return a result text plus a registered marker, which the caller checks with the Claude path's own validator. Consent is user-scope only: `repos.<slug>.providers` in `~/.claude/loomwright/egress.json`, read through `resolve-egress-config.sh` as `PROVIDER_GRANTS`. A repo file can request a provider but never grant it, and `lens-run.sh` now degrades to the new `provider_not_granted` status before starting any CLI when the grant is absent. `/setup providers status|apply|remove` (writer `loomwright/scripts/setup-routing.sh`; the check-only probe `setup-providers.sh` is unchanged) shows the table, writes the `routing` key and the grant only after a consent question that names the provider and what is sent to it, and removes both again; it refuses any provider the probe did not mark usable for read-only or write seats. The `ARCHITECTURE_CONTRACTS.md` provider-lens paragraph now points at the `provider-*.sh` files instead of restating a provider list, and the setup and supervisor-config prompt budgets and the vendor-coupling allowances for the new install-root references are raised with reasons.
