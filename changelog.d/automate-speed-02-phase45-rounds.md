Phase 4.5 spends its rounds on new defects
New `scripts/run-pin-mutations.sh` checks a brief's `## Pin mutations` rows by script, once per code state: two machine-applicable row forms (`delete` / `flip`, fixed-string literals), a working-tree scratch copy with `HOME` relocated and a watchdog, verdicts `held` / `not_held` / `unverified` (fail closed), a content-hash `--cache` and `--only-paths` row scoping.
The Phase 3 deterministic gate runs it beside `verify-provides.sh` (one bounded worker re-spawn on `not_held`, then recorded and carried forward, never adjudication) and every Phase 4.5 iteration runs it before the reviewer, who reads the verdicts as DATA and applies a mutation itself only for an `unverified` row.
New `scripts/phase45-ci-read.sh` reads the PR's required checks once per Phase 4.5 iteration and turns each red one into a BLOCKING finding for that iteration's fix worker, with the failing step's log tail wrapped as external text (an `untrusted_infra` check is a note, pending or unreadable is nothing).
Worker and fix-worker prompts run `ci-local.sh --affected`, never the full pool, and `test-ci-local.sh` pins that every static CI gate is in its early set.
