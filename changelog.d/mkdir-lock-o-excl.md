Move every remaining `mkdir` lock to an O_EXCL create, and add a gate so a new one cannot land
uutils `mkdir`, the default on `ubuntu-latest`, exits 0 on an existing directory even without `-p`, so a bare `mkdir` lock can have two holders. The token ledger, `followup-bundle` and `backlog-stamp` moved first; this covers the rest.
`run-lock.sh`, `dispatch-pr-review.sh`, `meta-sync` (lock and reclaim marker), `write-agent-memory.sh`, the `automate-next-step.sh` ledger lock, the lane table lock and the `ci-slot.sh` slot claim keep their directory, because their readers and older builds' directories expect it. The O_EXCL create of the stamp file inside it (`meta`, `pid`, `owner`, `holder`, `info`) now decides who holds the lock.
`build-state.sh`, `stamp-requirement-status.sh`, the `write-run.sh` registry lock and the breakers and reclaim guards had no stamp, so each is now an O_EXCL file at the lock path.
A stale directory from an older build still works. One carrying a stamp reads as held and goes through the same stale logic, and a stampless lock directory at a file-lock path reads as held and ages out. A directory with no stamp at a stamped lock has no holder and is taken at once, where it used to wait out its age or, in `run-lock.sh` and `dispatch-pr-review.sh`, never clear.
`build-loop-evidence.sh` and `build-reviewer-replay-case.sh` used `mkdir`'s status as a refusal, not a lock. They now check the directory itself, so uutils cannot wave through a planted scratch directory or overwrite an existing replay case.
New CI gate `scripts/check-mkdir-lock.sh` fails any non-recursive `mkdir` in a shipped script that has no `# mkdir-ok: <reason>`. New `test-mkdir-lock-false-win.sh` runs each lock's own function under a `mkdir` that always lets racers win, with a control that puts the `mkdir` test back and sees the second holder return.
