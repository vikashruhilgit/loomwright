Repo-relative config writers refuse a target whose physical location is outside the repo
A repo that committed a symlinked `.supervisor/` (or editor-settings) directory could make the plugin rewrite, and leave a backup beside, a file elsewhere on the machine, because the writers only checked a symlinked leaf or nothing at all. The new sourceable `loomwright/scripts/contained-path-lib.sh` (`cpl_phys`, `cpl_inside`, `cpl_check_write`, with its own self-test) resolves both the target and the repo root physically and refuses with `path_outside_repo` when the target lands outside the repo, or `containment_unavailable` when the library cannot be loaded. `setup-base-branch.sh`, `setup-routing.sh` (the repo `routing` write; the user-scope `egress.json` keeps its leaf-only check), the `/setup memory` allowlist seed, `automate-helpers.sh config-suppress`/`config-restore` (exit 2, which `/automate` maps to `config_malformed` before RUN) and the fail-safe `set-otel-resource-attrs.sh` emitter (still always exit 0) now check before their first write, so a refused write leaves the outside folder byte-identical with no backup or temp file. Inside-pointing symlinks and repos reached through a symlinked ancestor (macOS `/tmp`) still write. The allowlist, config-suppress/restore and otel writers now also refuse a symlinked config leaf (reason `symlink`) instead of replacing it with a regular file. User-scope files (`setup-statusline.sh`'s `settings.json`, `egress.json`, consent and stamp files) are exempt on purpose.
