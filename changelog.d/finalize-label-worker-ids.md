fix(finalize-gate): a Worker Results label heading no longer refuses a settled run
`guard-finalize-publish.sh write-marker` took the first word of every `## Worker Results` heading as an expected agent id, so a run whose headings carried labels (`### worker-1`, `### subtask-3-worker`) instead of the Task-returned ids refused `children_unsettled` on every retry, even with every worker settled (#717). The new `resolve_worker_result_ids` drops such a token as a label only when the session log's agent_identity rows already record the spawns and the token matches no log row and has no agent-id shape (8+ hex characters). An id-shaped token or a run with no identity rows still fails closed, and the dropped labels are listed under `ignored_worker_result_labels` in the marker or refusal. The execute-manager prompt now states that `worker_id` is the Task-returned agent id, never a label.
