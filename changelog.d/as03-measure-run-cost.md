Per-item /automate cost report from real transcript usage
`read-token-ledger.sh --per-item <run file>` prints what each `/automate` item cost and in which phase. Each item gets a row, with a row per phase under it (Launch Pad, Build, Phase 4.5 and its iterations, each owned drain, Decide). The rows show context and output tokens, turns, peak context, subagent tokens by agent type, and wall time. Every token figure is real usage: the per-message `message.usage` read from Claude Code's own transcripts. The proxy ledger is never mixed in, and there are no dollar figures. The item scope, drains and wall time come from `phase-timing.sh`, so an item's wall time is the same number phase-timing reports. Sessions resolve from the run file's `session_id` lines through each session's `.owner` file and session-log `cc_session_id` values to the transcripts. With repeated `--root`, a lane clone's sessions count toward the lane's item. Each message is counted once by `message.id`, so the repeated streaming lines and forked-session copies that inflated hand counts are gone. A missing phase boundary prints `not recorded`, never 0. An item whose sessions have no transcript gets a named `no_transcripts` reason and a row with no number; one whose transcripts hold no usage inside the item's window gets `no_usage_in_window` and likewise no number, and an empty phase window reads `no usage in window`. `/insights` renders the same table as `### Per-item cost (real usage)` under Token economics, for the most recent runs by run id, each with its `--parallel` lane files; a parent item a lane picked reads `picked in lane <run_id>-L<n>`. `docs/evidence/automate-speed-baseline.md` records the baseline that later automate-speed items are measured against, including PR #533's item (Launch Pad 12m 55s, Build 40m 8s, Phase 4.5 1h 25m, Drain 2h 11m 8s). A value-taking `read-token-ledger.sh` flag given last with no value (`--session`, `--run-id`, `--root`, `--per-item`, `--projects-dir`) now prints usage and exits 1; before, a trailing `--session`, `--run-id` or `--root` hung the reader in its argument loop.
