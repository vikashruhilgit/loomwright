Single-lane mode for /automate --parallel 1
`/automate --parallel 1` now runs each Queue item, in Queue order, in ONE fresh lane (a new clone, a new session) that parks `awaiting_merge` with a merge watcher exactly like a sequential item, with no wave and no wave PR; the owner's `--resume` after the merge closes the lane out through `lane-convert-ready` and `fleet-closeout` and starts the next item in a new lane. `init-check` refuses `--auto-merge` with any `--parallel` and refuses `--parallel 1` unless branch mode is on (`single_lane_requires_branch_mode`). `lane-create --parallel 1` writes `"single_lane": true` into `lane.json`, takes fresh lane numbers 1..99 and makes `--max-tokens` a whole-run ceiling (removed lanes counted from a new parent `fleet closeout: <lane> tokens TOTAL=<n>` Progress line that `fleet-closeout` and `lane-remove` write before deleting the lane). New read-only subcommands `lane-park` (the READY park a run writes) and `lane-drain-check` (single-drain guard at a lane's park); `current-set` refuses `ready_for_release` in a single lane, and `wave-build` refuses a single-lane parent. A run without `--parallel` is unchanged.
