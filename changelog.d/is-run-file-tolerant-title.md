/automate RESUME no longer hides a run file whose title has a BOM, odd spacing or a different case
`is_run_file` in `automate-helpers.sh` matched the run-file title as exactly `# Automate Run:`, so a run file saved by an editor that adds a UTF-8 BOM, or hand-edited to `#Automate Run:` or `# automate run:`, was silently dropped by `resume-glob` (letting a second run start beside a paused one) and refused by `runfile-write`, `progress-append` and `queue-checkoff`. The predicate now accepts an optional leading BOM, whitespace around the `#` and inside the phrase, and any letter case; an H2 `## Automate Run:` line and the `review-heal-result` / `supervisor-result` sidecars are still not run files. The engine still writes the canonical title. New D0b legs in `test-automate-helpers.sh` cover each tolerant form, the H2 and sidecar negatives and the write validators, and a second gated mutation control restores the old exact-match predicate to prove the new legs discriminate; the existing always-true mutant's `sed` now targets the new line. The rule is stated in `skills/automate-loop/SKILL.md` §1.5 and §4 and in the `RESULT_SCHEMAS.md` AUTOMATE_RUN title row, with a patch bump of the automate-loop skill.
