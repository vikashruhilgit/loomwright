/automate runs each phase of an item in its own fresh session, and phase questions reach the owner through the lane relay (automate-speed/09)
By default the `/automate` next-step driver runs an item's three phases as their own headless `claude -p` sessions instead of inside the coordinator's context: Launch Pad (`plan`), Supervisor (`run`) and the owned `/review-pr --until-mergeable` drain (`drain`). Each spawn carries `"session":"fresh"`, its `phase`, a runnable `launch` line and the sidecar the phase writes its result block to.
The coordinator runs `automate-helpers.sh phase-launch`, then `phase-wait` (exit 3 means call again, which keeps each call under the Bash tool's 600 s cap). When a phase asks a question, the relay hook records it under `.supervisor/automate/<run_id>.phase/<phase>/inbox/` and defers the session. The coordinator re-asks it verbatim and `phase-answer` resumes the same session with `--resume`. The coordinator never answers a phase question itself.
`phase-launch` needs the owner's typed command (`--owner-command`, which the coordinator passes to next-step) and refuses `BLOCKED`, exit 3, without it. A phase session re-enters the coordinator's run lock through `LOOMWRIGHT_RUN_LOCK_SESSION_ID` (acquire only; its release never frees the lock), and a `--parallel` lane never inherits that variable or `LOOMWRIGHT_PHASE_DIR`.
The driver applies `/autonomous` PLAN's result handling to the Launch Pad report itself: validation, the status mapping, the ls-diff fallback and the rubric check. It writes one `session_id <sid> (<item>) phase=<phase>` Progress line per phase, which the token-ledger readers sum unchanged and `phase-timing.sh` times by its `phase=supervisor` line. Without a usable relay, PICK parks the new `pause_reason: phase_relay_unavailable` before anything is picked.
`--inline-phases` restores the previous inline behaviour byte for byte and is the rollback. It is also needed for `--notify`, whose gate webhooks belong to `/autonomous`, which fresh phases do not run.
`docs/ARCHITECTURE_CONTRACTS.md` §"Subagent nesting" and §"Question-gate inventory" now describe the new context HR (headless phase session with relay) on every Launch Pad and Supervisor gate, each with its can't-ask status unchanged. `commands/automate.md` Step 0 reads `/autonomous` and `/review-pr` only under `--inline-phases`. Evidence: `docs/evidence/as09-fresh-session-per-phase.md`. The owner's real end-to-end run is still to do.
