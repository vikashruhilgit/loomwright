Branch mode in the /automate engine (opt-in, default OFF)
A repo can now keep its run history on the metadata branch that meta-sync.sh syncs instead of committing it to the default branch through a trail PR. `setup-memory.sh apply --branch-mode <branch>` writes a managed .gitignore block without the run-history re-includes plus one tracked `# loomwright-meta-branch: <branch>` line (a plain apply preserves it, `--branch-mode off` restores the default block), and `setup-memory.sh mode` is the one reader (`off` / `on <branch>` / `unknown <reason>`). `automate-helpers.sh meta-entry` pulls before the engine first reads run history and fails loudly (abort with nothing created, or a new `meta_unreachable` park on a resume); `trail-pr` pushes the evidence-gated trail with `meta-sync.sh push --paths-from` instead of opening a PR, deletes dropped dismissed drafts on the branch, and on any push failure appends a `meta-push FAILED:` Progress line, notifies, and writes a gitignored `<run_id>.meta-push-failed` marker read by the new `meta-push-failed` subcommand. SessionStart adds one offline hint when the clone has never pulled (meta-base absent). Corpus-gated tests now fall back to frozen fixtures under loomwright/scripts/fixtures/ so they still run without live run history. Mode off is unchanged; no repo is switched by this release (contract: skills/automate-loop/SKILL.md §13).
