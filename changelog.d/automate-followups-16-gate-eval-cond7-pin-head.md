Condition 7 of the `--auto-merge` gate ran `rules-gate-verdict.sh --root <checkout>` on whatever was checked out, so a stale checkout (an older commit, or `main`) or a dirty one (an un-pushed local fix to a bound file) could answer `ok` for a PR head whose bound files fail, and the gate would merge. `gate-eval` now checks the checkout first, before the helper runs. If `git rev-parse HEAD` at `--root` differs from the live `headRefOid` condition 2 confirmed, or cannot be read (not a checkout, no commit), it parks `rules_gate_head_mismatch`. If `git status --porcelain -uall`, read from the repo top level so a subdirectory `--root` still sees dirt anywhere, lists a tracked edit, a staged change or an untracked non-ignored file outside `.supervisor/` and `.claude/agent-memory/`, or fails, it parks `rules_gate_dirty_tree`.
