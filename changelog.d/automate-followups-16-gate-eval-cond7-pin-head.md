Condition 7 of the `--auto-merge` gate ran `rules-gate-verdict.sh --root <checkout>` on whatever was checked out, so a stale checkout (an older commit, or `main`) or a dirty one (an un-pushed local fix to a bound file) could answer `ok` for a PR head whose bound files fail, and the gate would merge. `gate-eval` now checks the checkout first, before the helper runs. If `git rev-parse HEAD` at `--root` differs from the live `headRefOid` condition 2 confirmed, or cannot be read (not a checkout, no commit), it parks `rules_gate_head_mismatch`. If `git status --porcelain -uall`, read from the repo top level so a subdirectory `--root` still sees dirt anywhere, lists a tracked edit, a staged change or an untracked non-ignored file outside `.supervisor/` and `.claude/agent-memory/`, or fails, it parks `rules_gate_dirty_tree`. Local-only git state cannot hide dirt from that check: a tracked file flagged assume-unchanged or skip-worktree parks, ignored-ness is judged from per-directory `.gitignore` files plus the user's global excludes file (`core.excludesFile` from the user's own global config, `[include]` / `[includeIf]` followed, else `$XDG_CONFIG_HOME/git/ignore` or `~/.config/git/ignore`, honoured only as an absolute path whose physical location, with symlinks and directory aliases resolved and the checkout matched by device and inode, is outside the checkout), so `.git/info/exclude`, a repo-local `core.excludesFile` and an env-injected one cannot hide an untracked file, while a clean checkout holding a globally-ignored `.DS_Store`, `.idea/` or `settings.local.json` still merges; an untracked `.gitignore` git reads parks, the `GIT_CONFIG_*` env injection variables are unset, fsmonitor and the untracked cache are disabled, and a `--root` whose top level cannot be read parks. Submodules count too: the status read runs with `--ignore-submodules=none`, so a committed `.gitmodules` `ignore = all` cannot hide a dirty submodule or one checked out at a commit other than the recorded one, and every checked-out submodule gets the same reads, recursively, so its own `info/exclude` or assume-unchanged flags cannot hide dirt either.
