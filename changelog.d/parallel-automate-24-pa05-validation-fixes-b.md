Lane park notification, real token counts and the leaking lane-feed test (parallel-automate/24)
Three defects from pa/05's Validation 4/5 run are fixed, each with a hermetic test that fails on the pre-fix code. F6: a lane's `ready_for_release` park now notifies through ONE helper, `automate-helpers.sh lane-park-notify <runfile>`, which sends the desktop notification and the new `automate_ready_for_release` webhook gate event ("do not merge yet — wave open"), both fail-SAFE, and appends one `## Progress` line naming what each channel actually did (`desktop: sent|disabled|suppressed|failed`, `webhook: attempted|ignored (<reason>)|not configured|failed`) — never "sent" for a channel that was not. F8: the token ledger counted nothing — the SubagentStop payload carries no usage, so every `token_ledger` line was a transcript-byte proxy and every `TOTAL` read 0, sequential runs included. `emit-token-ledger.sh` now reads the subagent's own transcript usage, once per message id (the final `stop_reason` line, else the per-field max), as top-level integers marked `"usage_source":"transcript"`; a resumed agent counts only its new messages. **Behaviour change: `--max-tokens` ceilings are live for the first time and will now park — and `TOTAL` includes cache-read tokens, usually its largest part, so size ceilings accordingly.** Still not counted: the main thread's own tokens, CI-side `claude-review` spend, a `--parallel` coordinator's own run, and output tokens of a message whose final transcript line is absent. F12: `lane-feed --follow` kills its own `tail | grep | jq` pipeline on TERM/INT/HUP; the test's cleanup pattern never matched (an unescaped `+` in a `pkill -f` ERE), so every suite run leaked one pipeline, and the suite now fails if any process naming its temp dir survives it.
