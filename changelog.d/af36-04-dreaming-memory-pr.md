/dreaming offers one memory PR for the memory it wrote (af36-remainder/04)
Accepted project-memory facts, LESSONS and agent-memory promotions used to sit uncommitted in place until someone opened a memory PR by hand, because `/dreaming`'s only PR path carried `.agent/rules/*.json`. `commands/dreaming.md` gains a `### Memory PR (delivery queue)` subsection: after every Accept, `/dreaming` may offer ONE pull request on its own `dreaming/memory-<session_id>` branch (separate from the unchanged `dreaming/rules-<session_id>`, whose delivery steps stay byte-identical, so a reviewer can merge either alone). It sits behind one per-run Pre-push confirmation (header `Push`, `Do not push` first, never recommended, ambiguous is no), not a per-item one, because memory Accepts write into shared files such as `LESSONS.md` and the writer-owned `MEMORY.md` index, which path staging cannot split. It is not offered when `.supervisor/memory/` or `.claude/agent-memory/` held uncommitted changes before the first Phase 4 write (a snapshot taken with `--untracked-files=all`, so a user's `status.showUntrackedFiles=no` cannot hide an earlier run's untracked file, and excluding the never-committed harness-memory pointer's file, so its line cannot block every later run), when a recorded file is gitignored or unstageable, or when the harness-memory pointer's target is a recorded file; it records each successful writer call's files at Accept time, stages only the changed files of that record by explicit pathspec, commits them pathspec-limited (so a pre-staged unrelated entry stays out), verifies the commit's file list equals that set before pushing, reuses the rules PR's HEAD-in-base pre-flight, runs after the rules delivery when both apply, restores the original branch on success and failure, and never merges. The section also states that the accepted memory files read the original branch's content after delivery until the PR merges and is pulled, and that `CLAUDE.md` edits, `.agent/orientation/` promotions and the harness-memory pointer stay out of it, and the header note now names the rules PR's known gap: its plain `git commit` would carry an unrelated entry already staged before the run. Every restatement of the old rules-only PR rule in `commands/dreaming.md` and `commands/agent-help.md` now describes both paths, the stale "legacy `.claude/agent-memory/` proposals remain paste-to-apply" clause is corrected, and the `/dreaming` row of the Question-gate inventory in `docs/ARCHITECTURE_CONTRACTS.md` now says it also pushes nothing without a Pre-push confirmation.
