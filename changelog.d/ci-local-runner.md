One pre-push command, scripts/ci-local.sh
Sessions were hand-rolling a serial `for t in …/test-*.sh` loop before every push (one core, a shared fixed /tmp log, root gates forgotten), re-testing unchanged trees several times a session while other sessions contended for the same CPUs. `bash scripts/ci-local.sh` runs every `bash scripts/…` gate named in ci.yml (derived from the workflow, not hand-listed) plus every root and loomwright self-test in ONE run-self-tests.sh pool; caches a PASS by working-tree content (tracked + untracked) + origin/main + OS, shared across sessions and worktrees, so an unchanged tree returns instantly and a failure is never cached; serializes full runs with a lock in the shared git dir (stale-pid takeover, re-check after waiting); runs check-vendor-coupling.sh against a throwaway index holding the whole working tree, so a new untracked file is no longer invisible to it (the PR #294 miss) without touching the real index; and refuses to cache when the tree changed mid-run. Self-test scripts/test-ci-local.sh (fixture repos only) is wired into ci.yml.
