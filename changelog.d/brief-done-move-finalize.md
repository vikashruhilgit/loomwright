The completion tail's brief move is a script, and a split move is repaired
The Supervisor completion tail moved its job brief from `in-progress/` to `done/` with whatever shell command the model chose. On PR #873 that was `git mv -k … || mv …` followed by `cat >> done/<brief>`. `.supervisor/` is gitignored, so `git mv -k` exited 0 having moved nothing, the `mv` fallback never ran, and the append created an Outcome-only file in `done/` beside the stranded brief. The session's own `ls done/<brief>` check passed on that stub. Every later repair then refused it: closeout's `brief-repair` logged "destination exists" and moved on, and `reconcile-jobs.sh --repair` refused while the SessionStart notice kept recommending it. Now the tail runs one call, `reconcile-jobs.sh --finalize <brief> <done|failed>`, with the Outcome on stdin. It writes brief body plus Outcome, removes the brief, checks both afterwards, and is the script's one mode that exits non-zero (1 refused with nothing written, 2 post-write check failed). `reconcile-jobs.sh` also classifies the split as a new `stranded_split` state. It is repairable under `--repair-merged` too, so SessionStart fixes it on its own. The repair rejoins the brief body and the stub's Outcome verbatim, the one existing destination it does not refuse, and that also clears closeout's `--evidence` path. `test-reconcile-jobs.sh` cases 34–35 cover both halves, with a whole-brief-destination control. A replay of the real PR #873 files gives a byte-identical join.
