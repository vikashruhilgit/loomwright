/automate adopts the PR a dead Supervisor phase left behind
Before this change, a Supervisor phase that opened its PR and then died before writing a SUPERVISOR_RESULT left the item with `pr: null` and a no-PR `phase_died` line. On `--resume`, RECONCILE then re-picked the item and re-planned it with a fresh Launch Pad, which could open a second PR. `--start drain` and `--merge-parked` were both refused. After the merge, `closeout` checked the row off but did not reconcile `## Current`. Now `automate-next-step.sh` looks up the dead phase's PR on the branch named in its fresh `.supervisor/state.md` (an OPEN PR first, else a MERGED one) and records it in `## Current` with `current-set`. An open PR goes to the pass's one owned drain. A merged one goes to SYNC's closeout and the check-off. RECONCILE adopts the PR in the same way from a run file an older driver wrote, so the item is never re-planned. Regression legs F3d cover an open PR, a merged PR, no PR, and both resume forms.
