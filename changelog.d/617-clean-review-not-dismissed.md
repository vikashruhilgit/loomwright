A clean bot review is recorded as clean, never as a dismissed finding the owner is asked about (#617)
The review-heal validate step gains a fourth verdict, `clean`, for a candidate whose whole text raises no issue at all (a bot review that only says "no new findings"); a text that says so and then raises anything stays `confirmed` or `dismissed`. A clean item lands in neither `findings_validated` nor `findings_dismissed`: it is counted in a new optional `REVIEW_HEAL_RESULT` v2 field, `findings_clean` (additive, no schema bump, allowed by `sidecar-check`), and listed in its own `<!-- loomwright:clean round=<n> -->` PR comment, kept apart from the dismissed marker because `pr-postmortem-gather.sh` counts every bullet of that one. The fallback review still refuses `clean`, and classification is unchanged, so a clean review still counts as a posted lens and never earns the fallback. As defence in depth, `automate-dismissed.sh dismissed-drafts` skips any item with no recognised severity whose whole text is a no-finding verdict (`… of <sha>: no new findings`, `no new findings on <sha>`, the bots' own `Reviewed <sha>: no new findings`, `… reported no findings`, `no finding raised`), logs it as `not-a-finding <h8>` before the summary line, and retires an undecided draft of it left by an earlier run.
