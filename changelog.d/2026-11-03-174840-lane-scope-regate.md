Launch Pad asks once about files outside an item's Touches
Launch Pad's save step now asks ONE question, under the new human-only gate `LP-SCOPE` (`Extend Touches` · `Revise plan` · `Stop`), listing every brief path outside the source requirement's `## Touches`, before the `LP-SAVE` / `LP-SAVE-NOTE` question. The list comes from a deterministic helper, `automate-lanes.sh scope-outside <item> <brief>` (new module `automate-lanes.d/scope.sh`), which reads Touches through the same `plan-waves --touches` call as the scope fence and wave-build's overlap check (companions included) and compares with the same matcher. It prints `inside`, `unknown` (Touches not declared: no question), `outside <n>` or `unreadable <n>` (the Touches read failed: every brief path is listed, never a silent pass). `Extend Touches` records the accepted paths in the brief's new `## Scope widening` section, and the save question that follows no longer mentions them. Files outside Touches are no longer a feasibility NO-GO. When Launch Pad cannot ask, it saves nothing and reports `scope_widening_non_interactive: <n> path(s) outside Touches`, even with the explicit non-interactive flag. Every Launch Pad question must name a catalog code; a free-form design question goes under `LP-CLARIFY`, never an improvised header (issue #808).
