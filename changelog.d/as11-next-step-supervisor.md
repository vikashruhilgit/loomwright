supervisor-next-step.sh drives Supervisor Phases 0-2 one instruction at a time
A new step driver, `loomwright/scripts/supervisor-next-step.sh`, owns the deterministic part of Supervisor Phase 0 INIT, Phase 1 ACQUIRE, Phase 1.5 PRE-FLIGHT SYNC and Phase 2 PLAN and hands the inline Supervisor one instruction per call in the `/automate` driver's instruction schema (`spawn` / `ask` / `park` / `done`): the `.supervisor/` bootstrap, the job move `pending/` to `in-progress/`, the run's config (flag, else the brief's `## Configuration`), the test-integrity guard arm, the idempotent branch guard (reuse only at the base tip, else the `acquire_branch_collision` park), the `/autonomous` `state.json` ACQUIRE fields, the pre-flight routing (CLEAR / UNVERIFIED / the SUP-OVERLAP ask with its catalog labels and `preflight_overlap_detected` can't-ask status / the fail-closed park with the job to `failed/`), PLAN from the brief's subtask table (or the orchestrator spawn) and path selection into the Phase 3 entry spawn. It never writes `.supervisor/state.md`: every Phase Flag, `initialize` and `record_decision` is printed as a Context-Keeper spawn carrying the exact operation text. Its instruction shape is documented in `docs/result-schemas/supervisor-result.md` §"supervisor next-step instruction"; `scripts/test-supervisor-next-step.sh` drives fourteen golden cases under `scripts/fixtures/supervisor-golden/` (four built from a real run, the rest synthetic with the reason recorded), checks that `state.md` is untouched, the SUP-OVERLAP ask shape, the merge-surface file list and that no step spawns `code-reviewer`, with mutation controls for each leg.
