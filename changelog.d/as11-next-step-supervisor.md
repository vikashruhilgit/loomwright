supervisor-next-step.sh drives Supervisor Phases 0-4 one instruction at a time
A new step driver, `loomwright/scripts/supervisor-next-step.sh`, owns the deterministic part of Supervisor Phase 0 INIT, Phase 1 ACQUIRE, Phase 1.5 PRE-FLIGHT SYNC, Phase 2 PLAN, the Supervisor-side routing of Phase 3 EXECUTE and Phase 4 FINALIZE, and hands the inline Supervisor one instruction per call in the `/automate` driver's instruction schema (`spawn` / `ask` / `park` / `done`): the `.supervisor/` bootstrap, the job move `pending/` to `in-progress/`, the run's config (flag, else the brief's `## Configuration`), the test-integrity guard arm, the idempotent branch guard (reuse only at the base tip, else the `acquire_branch_collision` park), the `/autonomous` `state.json` ACQUIRE fields, the pre-flight routing (CLEAR / UNVERIFIED / the SUP-OVERLAP ask with its catalog labels and `preflight_overlap_detected` can't-ask status / the fail-closed park with the job to `failed/`), PLAN from the brief's subtask table (or the orchestrator spawn) and path selection into the Phase 3 spawn. Phase 3: the `EXECUTE_RESULT` / `EXECUTE_CHECKPOINT` is read by the validators' shared parser and routed (complete, partial with the failures carried to the hand-over, all failed, a crash, a budget checkpoint), and an adjudication asks SUP-ADJ-GAP or SUP-ADJ-LANE by `adjudication_kind` — never picking an option; under `--non-interactive` it records `adjudication_required_non_interactive: <kind>` instead. Phase 4: pre-merge gate points 1–4 (a failed point fails the job with its reason), point 5 through `check-children-settled.sh` (the SUP-CHILDREN ask, or `children_unsettled` fail-closed), the merge spawn, `guard-finalize-publish.sh write-marker` — the push / PR spawn is printed only after it exits 0 — and the PR-base self-verify with its one retry, the SUP-GH-RETRY ask and the `base_mismatch_detected` flag, ending at the hand-over to Phase 4.5. It never writes `.supervisor/state.md`: every Phase Flag, `initialize`, `record_decision` and `record_error` is printed as a Context-Keeper spawn carrying the exact operation text. Its instruction shape is documented in `docs/result-schemas/supervisor-result.md` §"supervisor next-step instruction"; `scripts/test-supervisor-next-step.sh` drives golden cases under `scripts/fixtures/supervisor-golden/` (each with a `source` naming its real run or why it is synthetic), checks that `state.md` is untouched, that the publish spawn only follows the marker, the ask shapes, the single gh retry, the merge-surface file list and that no step spawns `code-reviewer`, with mutation controls for each leg, and replays a hermetic Phase 0 to hand-over drive with real merges, push and guard.
