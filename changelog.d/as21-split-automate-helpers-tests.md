test-automate-helpers.sh is a thin runner over sourced parts in test-automate-helpers.d/ (move-only)
`loomwright/scripts/test-automate-helpers.sh` was the largest test in the repo, a single 6,216-line file that every helper change edited, so parallel lanes collided on it (automate-speed/21). It is now a runner that keeps the header, the shared setup and the summary, and sources 17 parts by name from `test-automate-helpers.d/`, one contiguous base line range per helper module or dispatcher subcommand (`01-config` to `16-queue-gates`, none over 800 lines). Every leg moved verbatim and in base order. When the runner is expanded (runner-only blocks deleted, each part-source line replaced by its part, and the one hoisted split-index setup put back at its base position), it equals the base file byte for byte. The suite prints the same `RESULT:` line and the same multiset of `ok:` / `FAIL:` lines as base. Section E's all-pass MERGE leg stays inline in the runner, so the merge-command invariant grep's file list does not change. A missing or unreadable part aborts with exit 1 and names it. `bash test-automate-helpers.sh <part>...` runs only the named parts plus their prerequisites (`05-gate-eval`, `06-gate-eval-tail` and `07-rules-gate` need `05-gate-eval-harness`), in base order. With no argument it runs everything as before, which is how CI and `run-self-tests.sh` call it. The test's three vendor-coupling references moved with their legs into two parts, and the allowance total is unchanged. No helper script changed. Measurements are in `docs/evidence/as21-split-automate-helpers-tests.md`.
