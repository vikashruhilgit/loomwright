The drain honours a named required-checks set when protection gives no list
On a base branch that cannot supply a required-check list (a private repo on GitHub Free, an unprotected base, a token that cannot read protection), the `/review-pr --until-mergeable` drain gated READY on every non-neutral check or escalated, so a check that is red for a reason no code fix can reach blocked READY forever (#805). A repo can now name its gating checks once, as `"required_checks": ["<name>", …]` in `.supervisor/config.json` (read from the `--root` checkout, so an `/automate` lane reads its own clone's copy), or per run as `--required-checks name:<a>[,<b>…]`. Precedence, decided in one place (`review-heal-next-step.sh`'s `required` step): a readable protection list, even an empty one, always wins (`required_mode protected`); then the flag (`all-non-neutral`, or `name:` ⇒ `named`); then the config key (`named`); then GitHub's paid-plan refusal (every non-neutral check); otherwise `ESCALATED` `required_checks_unavailable`, unchanged. A 404 counts as "no list" only when its body says `Branch not protected` or `Not Found`. The wait and the confirming pass get the set through the new `wait-for-checks.sh --named-required <json array>`, which uses it only where its own protection read gives no list; without the flag its output is byte-unchanged. A named check missing from the rollup is pending, never green, and at the wait's bound the drain ends `ESCALATED` `required_check_absent` naming it. A malformed key (`[]`, a non-array, a non-string or blank entry) ends `ESCALATED` `required_checks_unavailable` naming `required_checks`, and `name:` with an empty name is a usage error (exit 2). `/automate` passes no `--required-checks`, so the key applies there; the `--auto-merge` gate never reads it. `setup-base-branch.sh status` now prints an `advisory:` line, with a `fix:` line, when the base has no readable required-check list and no `required_checks` is set, and a separate line when the key is malformed; it still exits 0. A new golden case, `named-required-ready`, pins a READY with a red deployment check outside the set. The live check on a real repo: `docs/evidence/drain-named-required-checks.md`.
