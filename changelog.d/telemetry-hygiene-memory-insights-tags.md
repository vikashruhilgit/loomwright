Agent-memory proposals reach the store the runtime reads; stranded close-outs are no longer failures; knowledge-source tags aggregate as one row per source
`write-agent-memory.sh` used an agent's `agent:` value verbatim as the store directory, so a proposal naming `code-reviewer` created an unread `.claude/agent-memory/code-reviewer/` and exited 0. It now resolves `<agent>`, `loomwright:<agent>` and the runtime type to the existing store, or to `loomwright-loomwright-<agent>` for a plugin agent that declares `memory: project`. A proposal naming no known store is refused (`REFUSE_UNKNOWN_AGENT_STORE`, exit 1) unless `--new-store` is passed. An unfenced proposal is refused as `REFUSE_PROPOSAL_UNFENCED` rather than the misleading "names no 'agent:'". AGENT_GUIDELINES and the six `memory: project` agent prompts now state the fenced format and each agent's store slug.
`close-stranded-run.sh` now stamps `plugin_version` (omitted when the manifest is unreadable, still always exit 0). Its `session_ended_without_completion` records are a Stranded bucket in `/insights`, kept out of Failed, the completion-rate denominator and the per-version table; `build-loop-evidence.sh` excludes them from the funnel and counts them under Data quality, and `/handoff` labels them.
`knowledge_sources_used` has one canonical vocabulary in the `session_end` contract (`docs/result-schemas/session-end-jsonl.md`), and the emitting prompts point at it. `build-insights.sh` normalizes tags at read time (base tag lower-cased with `-` → `_`, `:<qualifier>` verbatim), so `project-memory` and `project_memory` in existing logs count as one tag.
