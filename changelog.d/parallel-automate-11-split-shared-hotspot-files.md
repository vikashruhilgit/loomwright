Split the three shared hotspot files that serialised parallel waves (parallel-automate/11)
`plan-waves` was forcing open items into separate waves because they all touched `SKILLS_INDEX.md`, `automate-helpers.sh` or `RESULT_SCHEMAS.md`.
`SKILLS_INDEX.md`'s Version and Last Updated cells, and its row set, are now generated from each skill's frontmatter by `scripts/check-skills-index-sync.sh --write`. The curated cells are preserved, and a second `--write` changes nothing.
Gate mode regenerates the index into a temp file and fails on a hand-edited cell, a missing row or a ghost row, and `--self-test` checks both directions.
Because of that, the `loomwright/skills/*/SKILL.md` => `SKILLS_INDEX.md` companion rule is gone from `.agent/companions.json`, so two items that edit different skills can share a wave.
`loomwright/scripts/automate-helpers.sh` is now a dispatcher. It keeps the header, the shared predicates, `gate_eval` (so the `gh pr merge --squash` invariant still resolves to the same five surfaces) and `main`. It sources family files from `automate-helpers.d/` at the positions their code held in the old single file, and a missing family file fails closed.
The CLI is byte-identical, `--help` included. The new `test-automate-helpers-dispatch.sh` checks that every subcommand reaches its function, and the suites that copy the helper into a temp tree now copy `automate-helpers.d/` too.
`loomwright/docs/RESULT_SCHEMAS.md` is split into one file per top-level schema under `loomwright/docs/result-schemas/`. The file keeps its path, its preamble and every top-level heading in order, each pointing to its split file. A new `## Cited sub-section anchors` table maps each sub-heading that prose cites to the split file that now holds it.
`test-result-schemas-split.sh` checks the split byte for byte and checks that every anchor resolves. The citation-drift pins and the vendor-coupling allowances now point at the split files, and the allowance total is unchanged.
