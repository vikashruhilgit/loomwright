untrack-pr no longer prints a false readiness WARNING
`migrate-branch-mode.sh untrack-pr` wrote the branch-mode block, and so ran `setup-memory.sh apply`'s post-write readiness verify, BEFORE it ran `git rm -r --cached` of the seeded A set. `git check-ignore` never reports a tracked path as ignored, so in a history repo whose findings ledger (`.supervisor/postmortem/results.jsonl`) was tracked, the must-stay-ignored probe read the ledger as committable. Apply then printed `apply: WARNING — readiness is 'partial (an unintended path is committable …)'` for a commit whose tree reads `Memory readiness: configured` (seen on loomwright-studio#45, 2026-10-13). The probe is right in general (a tracked ledger in branch mode really would be committed), so the fix is the order: untrack-pr now untracks the A set first and writes the block second. The verify therefore judges the tree the step commits, and a WARNING it prints is real. When apply refuses after the untrack, the step now restores the index (`git reset`, as mode-pr already did), returns to the default branch clean, deletes the new branch, records FAIL and pushes nothing. Migrate leg 27 covers a tracked ledger: no WARNING, the PR head reads configured, the ledger is untracked and stays on disk. Its mutation control restores the old order and reproduces the WARNING, and a stubbed apply refusal covers the cleanup path.
