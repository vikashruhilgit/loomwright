The Supervisor keeps .supervisor/ ignored without touching the tracked tree
When git did not already ignore `.supervisor/`, the Supervisor's setup step appended the line to the checkout's `.gitignore` and never committed it, leaving an untracked or modified `.gitignore`. The merge gate's condition 7 parks `rules_gate_dirty_tree` on exactly that file, so `--merge-parked` and `--auto-merge` parked after every run in a repo whose `.gitignore` did not already cover `.supervisor/` (issue #829). Inside a repo the line now goes to the repo's local `info/exclude`, which `git status` and `git add` honour; the gate needs nothing changed because it never counts `.supervisor/`. Outside a repo it still falls back to `.gitignore`, and under `/setup memory`'s managed block nothing is written, as before. A checkout an earlier run already dirtied still needs its `.gitignore` line removed by hand.
