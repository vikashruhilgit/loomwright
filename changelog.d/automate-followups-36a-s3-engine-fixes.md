Engine leftovers from the S3 wave-1 review, and reconcile-status writes no home paths
A run lock held by a LIVE process no longer reads as a close-out leftover: `closeout` names the holder's liveness (`run lock held by <owner> (live pid <p>)` or `(holder pid <p> not running)`), `closeout-classify` prints a `run_lock_held` row for a live holder (not `complete`, not a leftover), and `closeout-others` records it and parks nothing, so the next start retries that close-out; a dead holder stays `leftover lock`. The SessionStart probe's `gh pr view` calls share one overall deadline (`LOOMWRIGHT_SR_GH_DEADLINE`, default 8 s) instead of up to 25 s. `current-rebuild` writes `pause_reason: null` with its `status: running`. `finalize-empty` keeps writing `## Status: done` before `trail-pr`, because the trail PR carries that stamp; the call site now says so, and a test pins that the trail sees `done` and that a failed trail is recovered by a hand `trail-pr --reason done`, not by a later `--finalize`. The execute-result schema and its validator fixtures use `../myapp-…` worktree paths instead of `/Users/<name>/…`. meta-sync's unreadable-meta-base refusal has a test leg and a mutant, and test 38's title says a symlinked non-managed file is ignored. `reconcile-status` prints and writes repo-relative paths only: the `- **Brief:**` line it stamps and the abandoned rows' run-file field were absolute, which the metadata push's home-path scrub refused.
